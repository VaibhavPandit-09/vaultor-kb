## Baseline and working rules

- Audited clean `master` / `origin/master` at `5003a91`; fetched remote, zero divergence. Branch `codex/desktop-experience-d1` created at the user's explicit request. Existing unrelated worktrees retained.
- Desktop version remains 0.25.2. This initiative explicitly excludes automatic versions, installers, tags and releases; no integration into master without completed scope/required checks.
- Preserve resource-based structured Tiptap JSON, multi-collection membership, shared API/settings/tokens, pane save barriers, private recovery and source/grant boundaries. Commands coordinate existing operations; they do not replace authorization or lifecycle transactions.
- Status progression: `NOT STARTED → IN PROGRESS → IMPLEMENTED → VALIDATED → COMPLETE`; also `BLOCKED` and `DEFERRED`. IMPLEMENTED means code exists; VALIDATED requires specified automated/runtime evidence; COMPLETE additionally requires acceptance criteria and applicable platform/user review. Compilation alone never qualifies.
- Medium risk for navigation/commands/focus; native text menus require Electron runtime validation. Lifecycle/backend logic is preserved. Future clipboard/filesystem/lifecycle mutations require high-risk boundary/failure checks.

Under 640px neighbors compress away; current title truncates with full tooltip. ### Architecture, acceptance criteria and intentional boundaries

- Controller payloads are scoped opaque tickets for resources, collections, tags or sessions; source/target adapters use the same intent and command routing. Resource IDs are resolved/rechecked only on drop, including native linked metadata with captured generation. Metadata resolution must return the original IDs; stale source work cannot mutate another workspace or report success there. No resource clone is created by an internal drag.
- Editor registry binds each actual ProseMirror root across mount/unmount. A drop captures posAtCoords and the existing transaction-mapped insertion target before any async work. Normal resourceLink JSON, shared history, onUpdate/autosave and recovery handle the insertion. One undo removes the entire link batch without undoing adjacent typing. A mounted regression and native smoke caught/fixed old saved snapshots replaying into an unfocused view during palette dismissal; unchanged incoming content is now distinguished from an authoritative new snapshot.
- Cross-pane moves reorder assignments while retaining session/slot/root identity, document, history, caret and reading positions. They never invoke load/save for visible sessions. CSS visual order changes while DOM roots stay mounted; logical pane commands/labels follow visual model order, while ordinary DOM Tab traversal retains mount order. Spatial animation and physical keyboard/drag feel remain user acceptance items; there is no correctness dependency on animation. Existing configured pane maximum is rechecked after async admission. Narrow layouts retain the existing compact pane switcher rather than a new pane system.
- Browse-origin drags retain their original list as a temporary narrow shelf when holding over an Open Notes row reveals its editor. Palette stays mounted and becomes pointer-transparent during dragging; success closes it, cancellation restores the search. This avoids destroying native drag sources. Floating/compact sidebars keep their shared reveal/scroll behavior.
- External collection import preserves destination before native acquisition and review. Normal FileImportModal/Activity owns duplicate handling, source/grant checks, folder paths, restart/recovery and confirmed execution. Single-file editor insertion instead reuses the existing **foreground InlineImportModal** and idempotent upload ID, captured source generation/epoch and mapped editor anchor. It never dispatches a new hidden importer. Closing/failure/stale source means no link; a successful upload whose insertion target later disappears remains an ordinary Library resource, with no dangling document link.
- **D:** folder/multiple-file → editor is explicitly refused. Background Activity tasks outlive editors, while mapped anchors are editor-bound; safe multi-file completion callbacks and resumable insertion would require a separate durable insertion contract. Use ordinary reviewed Import into Library/collection, then drag resource(s) as links. This includes no new Activity path for inline insertion. **D:** native drag-out still requires prepared-export tickets (D2.4b). **—:** linked/read-only editor resource/file-link insertion, arbitrary text/URLs as resource identities, unsupported/trashed/special-file sources, collection-to-editor, resource-to-Open-Notes reorder, inactive-session replacement at full capacity, independent windows/new pane systems. Keyboard alternatives remain available for supported operations.
- Acceptance: review actual pointer insertion, multi-resource single-step Undo/Redo/autosave, source identity/ownership, external collection destination/Cancel/retry, dirty-pane movement/edge placement/session restoration, Add vs Move feedback, Escape, hover/scroll/floating/compact behavior, keyboard order and reduced-motion/theme feel in the Windows development build. D2 stays **IN PROGRESS / AWAITING ACCEPTANCE** until the user explicitly accepts this extension. D3 is NOT STARTED.

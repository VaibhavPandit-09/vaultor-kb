### Architecture, acceptance criteria and intentional boundaries

- Controller payloads are scoped opaque tickets for resources, collections, tags or sessions; source/target adapters use the same intent and command routing. Resource IDs are resolved/rechecked only on drop, including native linked metadata with captured generation. Metadata resolution must return the original IDs; stale source work cannot mutate another workspace or report success there. No resource clone is created by an internal drag.
- Editor registry binds each actual ProseMirror root across mount/unmount. A drop captures posAtCoords and the existing transaction-mapped insertion target before any async work. Normal resourceLink JSON, shared history, onUpdate/autosave and recovery handle the insertion. One undo removes the entire link batch without undoing adjacent typing. A mounted regression and native smoke caught/fixed old saved snapshots replaying into an unfocused view during palette dismissal; unchanged incoming content is now distinguished from an authoritative new snapshot.
- Cross-pane moves reorder assignments while retaining session/slot/root identity, document, history, caret and reading positions. They never invoke load/save for visible sessions. CSS visual order changes while DOM roots stay mounted; logical pane commands/labels follow visual model order, while ordinary DOM Tab traversal retains mount order. Spatial animation and physical keyboard/drag feel remain user acceptance items; there is no correctness dependency on animation. Explicit grip arrangement rechecks the configured maximum after async admission; ordinary note reveal instead follows normal fill/reuse/Save rules, including inactive/unopened notes at capacity. Narrow layouts retain the existing compact pane switcher rather than a new pane system.
- Browse-origin drags retain the original list mounted and unpainted at its original full size after hover reveals an editor; no narrow shelf or Library/editor overlay is shown. Palette stays mounted and becomes pointer-transparent during dragging; success closes it, cancellation restores the search. This avoids destroying native drag sources. Floating/compact sidebars keep their shared reveal/scroll behavior.
- External collection import preserves destination before native acquisition and review. Normal FileImportModal/Activity owns duplicate handling, source/grant checks, folder paths, restart/recovery and confirmed execution. Single-file editor insertion instead reuses the existing **foreground InlineImportModal** and idempotent upload ID, captured source generation/epoch and mapped editor anchor. It never dispatches a new hidden importer. Closing/failure/stale source means no link; a successful upload whose insertion target later disappears remains an ordinary Library resource, with no dangling document link.
- **D:** folder/multiple-file → editor is explicitly refused. Background Activity tasks outlive editors, while mapped anchors are editor-bound; safe multi-file completion callbacks and resumable insertion would require a separate durable insertion contract. Use ordinary reviewed Import into Library/collection, then drag resource(s) as links. This includes no new Activity path for inline insertion. **D:** native drag-out still requires prepared-export tickets (D2.4b). **—:** linked/read-only editor resource/file-link insertion, arbitrary text/URLs as resource identities, unsupported/trashed/special-file sources, collection-to-editor, resource-to-Open-Notes reorder, inactive-session replacement at full capacity, independent windows/new pane systems. Keyboard alternatives remain available for supported operations.
- Acceptance: review actual pointer insertion, multi-resource single-step Undo/Redo/autosave, source identity/ownership, external collection destination/Cancel/retry, dirty-pane movement/edge placement/session restoration, Add vs Move feedback, Escape, hover/scroll/floating/compact behavior, keyboard order and reduced-motion/theme feel in the Windows development build.

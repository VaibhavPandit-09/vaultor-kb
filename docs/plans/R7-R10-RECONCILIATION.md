## Preserved presentation and authority contracts

R6 supplies the reader-first Home / Library / Review shell, connected/downloaded source context, quick switching separate from management, contextual Aa, resource-origin opening/closing, theme/motion tokens, restrained native semantic haptics, protected creation and automatic Review delivery. These are accepted implementation, even where physical acceptance remains open.

The old A5 drawer-led root, editor toolbars, editing/lifecycle controls, prototype screenshots, permanent Sources destination and generic rebuild-all-settings sketches are historical. None may replace the current shell. Review is not an uploads destination. A queue does not justify a fourth primary tab. Source names/addresses do not identify a destination; native host/workspace/generation does.

Keep RN product UI and motion with thin Kotlin platform modules; no Compose rewrite. Preserve retained WebView/DOM/scroll/journeys, measured valid-origin movement with bounded fallback, exclusive accessibility/touch ownership, Back/IME/focus order, reduced-motion immediate endpoints, coordinated theme/system bars and font scaling. Prefer one scroll owner, compact rows and contextual disclosure. No persistent queue toolbar, duplicated headers, unrelated motion or automatic completion celebration. Background imports are H0; any intentional durable-queue feedback must use existing semantic policy and be justified at the interaction gate, not invent a new rich pattern.

Android creates new resources only through the approved import contract. It never edits original documents/organization, changes desktop Review status, manages Trash, replaces workspaces or runs a local authoritative server. Structured Tiptap JSON, original bytes, shared API/security/design contracts and desktop host ownership remain intact.

## Refreshed milestone boundaries

### R7 — Offline collecting and authoritative host import

Reuse source/lock identities, protected native storage practices, Review dispatch concepts, cached collection metadata, existing UUID import semantics, host document validation/transactional membership, ZIP validator and existing utility/motion primitives. Missing: acquisition, separate input journal/files, binary transport, host conversion/receipts, destination/queue UI and authorized ZIP path. Detailed sequence below.

Backend needs an advertised versioned import capability/limits, generation-checked creation and durable exact-intent acknowledgment/conversion. Kotlin needs input lifetime ownership, streamed private files, transactional queue and captured-source upload. RN needs confirmation, Pending imports and state updates without reader reload. ZIP needs an explicit authorization decision first.

Acceptance: offline text/MD/PDF/images/other advertised originals survive URI loss and process death, then produce one correct host resource per confirmed item despite lost acknowledgments. Unsupported/failed items remain local with reasons; batches expose partial success. Equal IDs/names, changed collections, replacement/revocation/source switches cannot redirect delivery. Original bytes remain unchanged. No general mobile editing, scraping/shared-URL fetching, OCR, automatic note insertion, new primary destination, guaranteed background execution or broad resumable-upload platform.

Dependencies: R4/W3/R6 already present; compatible host release required for new contracts. Decisions: ZIP delegation, preservation policy, numeric queue limits and upload metered default (below). R7 UI gate reviews only the import addition and its transitions.

### R8 — Full and partial exports

Add mobile full-export preparation/status/download/hash/save/share; a versioned partial inventory/package and desktop importer support; bounded offline structured/Markdown rendering with available assets and explicit missing references/review coverage/last refresh. Host/native/RN changes must keep full ZIP connected-only even for a complete download. Reuse contextual resource/Library actions and Settings & tools for workspace-level export; no Exports tab or editor-save prerequisite.

Acceptance: connected full and online/offline partial round trips into disposable desktop storage preserve included IDs/links/reviews/original hashes under declared remapping rules. Cycles, missing bytes/targets, locked sources, cancellation/provider denial and interrupted handoff remain understandable. Exclude trust, credentials, sessions/preferences and unsynced queues; export never acknowledges delivery. Separate recovery stays separate. Non-goals: offline complete workspace reconstruction, offline PDF/Word without tested renderer, arbitrary format conversion. Depends on R7 queue isolation, archive compatibility and a confirmed partial-format contract; package schema/limits are engineering decisions to settle in R8, not new product scope.

### R9 — Remaining settings, discovery, connections and verified updates

Extend existing Settings & tools and source management; keep Aa contextual. Discovery results are candidates, never trusted enrollment or auto-switching.

## Actionable R7 architecture and sequence

### 1. Freeze a narrow host import contract first

Keep ordinary desktop imports compatible. Reuse `FileImportService` for creation where sufficient, but do not merely expose its current multipart route to Android:

- Bind stable operation UUID to exact host/workspace/generation, destination collection or explicit root, original filename/MIME/length/hash, intended original-file/text/Markdown mode, and conversion contract version. Preserve raw input identity even when output is normalized structured JSON. No credential is part of that record.
- Check generation at authoritative mutation admission/transaction under the workspace gate, including retries; preflight identity GET cannot prevent replacement between check and creation. Recheck current grant and validate collection in that workspace; no silent root fallback when a collection disappears. Existing private fingerprint does not contain generation or expose a sufficient acknowledgment.
- Persist enough immutable import intent/result to reconcile an uncertain operation even if a resulting resource is later edited, trashed or purged. Never recreate a deleted result on automatic retry, overwrite an occupied ID or infer success from a title/list entry. Receipt must identify operation, request fingerprint/input hash, source generation and exact created resource/result. UUID/body mismatch is Needs attention, not a new UUID retry. Define receipt retention/bounds without silently making old uncertain requests replayable.
- Add bounded host text/Markdown conversion to structured Tiptap JSON with strict encoding/size/node limits, safe links/images and visible warnings; do not run a hidden mobile editor or assume existing frontend conversion is a Java service. No remote asset fetch or HTML/script execution. Characterize current frontend fixtures to preserve useful semantics; host validates output. PDFs/images/other advertised binary formats remain original File resources.
- Advertise actual format/mode and byte limits (host multipart, file storage, converter and mobile staging all constrain them). Begin with bounded whole-file streaming and exact retry. Add chunked/resumable uploads only if measured accepted inputs require them; existing snapshot byte-range resume is download-only. No route names/schema version are claimed implemented here.

### 2. Native input acquisition and private staging

Add explicit SEND/SEND_MULTIPLE MIME filters and handle both cold initial Activity intent and warm `onNewIntent`, before relying on a mounted RN listener. File/Photo pickers and received shares feed one native acquisition path. Treat intent metadata as untrusted; no destination/host/operation identity is accepted from an external sender.

Use granted content URIs, validate read access and bounded metadata, stream to a uniquely named private partial file while hashing/counting; fsync/rename and commit metadata before reporting Collected. Deduplicate URI appearances within one intent (ClipData/EXTRA_STREAM); retain a durable acquisition identity through activity recreation so the same delivery does not create duplicate queue rows. Two separate deliberate shares of identical bytes remain two user actions, not global content deduplication. Text shares retain their exact received string encoded as UTF-8, not pretend source-file bytes; no automatic URL crawling. In mixed batches expose individually failed acquisitions without discarding successful ones.

Copy promptly while grants are valid. SAF persistable permission is a fallback only when actually offered; it cannot replace owned bytes. Never claim a partially copied file is durable after provider failure/death; recover safe partial acquisition or ask the user to select again. No broad storage permission, MANAGE_EXTERNAL_STORAGE, arbitrary filesystem path, camera feature or storage-tree scan is needed. Keep exported entry points narrow. See Android's [SAF guidance](https://developer.android.com/training/data-storage/shared/documents-files) and [permission minimization](https://developer.android.com/privacy-and-security/minimize-permission-requests) (checked2026-10-22): URI grants can be temporary, persistable grants can still lose access, and Photo Picker avoids runtime storage permission. Android37 LAN permission remains separate from local collection.

Create a separate native SQLite queue plus app-private files, not the Review AtomicFile blob or companion download store. Preserve encrypted legacy input files/catalog as recovery only. Use native protected metadata and streaming encrypted staged originals, with crash-safe finalize/recovery; do not load64MiB into JS or inherit the old whole-buffer staging path. Reuse Keystore protection conventions without storing credentials with payloads. Maintain file/DB ordering and detect orphan/corrupt/missing bytes without deleting known queue ownership.

Enforce per-item/batch/total-byte/count bounds, disk reserve and partial/temporary overhead before and during copy; reserve capacity concurrently. Downloads/Review/legacy records cannot be evicted to make room. Proposed initial envelope: **64MiB per ordinary original, eight items per acquisition, 256MiB total staged originals, 128 queue items, at least16MiB free reserve**, further constrained by advertised host/conversion limits. These are proposed R7 defaults, not existing policies or acceptance measurements. ZIP may need a separate lower/local bound; do not inherit host512MiB without mobile measurement.

### 3. Confirm destination and expose Pending imports within Home

Cold Share opens a local confirmation surface after durable acquisition, usable with no host/source selected. Show **Pending imports** as a compact conditional Home row (count/needs-attention, no permanent toolbar); it opens one device-local, source-grouped queue utility. It includes Unassigned items so they remain reachable after dismiss/restart or when no connection exists. Library's contextual Import action opens the same flow with current source/collection offered for confirmation. Review remains exclusively evidence/desktop status. Source switching never changes the queue's destinations.

States: acquiring → collected/unassigned → destination/mode review → confirmed queued → sending → acknowledged; side states retryable, delivery unconfirmed, needs attention, cancelled-before-send. Confirmation names host/workspace/generation and collection/root, format and bounds. Cached collection IDs are choices, not proof of current authority. Before first dispatch the user may change destination/mode; the confirmed request is frozen before the durable sending claim. After any possible dispatch, destination changes wait for exact reconciliation; a later intentional import is a separate user-confirmed operation.

Reuse ContextSheet/MotionSheet and existing Settings/Back/focus primitives: the selected pending row remains the same object while details/status disclose; opening preserves underlying Home/Library/reader position, Back returns to its invoker and hides IME first. Background state changes update that row silently without opening a surface, replaying motion or replacing reader content. Reduced motion uses immediate endpoints; row status has readable/accessibility text and aggregate progress exposes item counts plus known bytes without suggesting atomic batch success. Large queues use one bounded/paged list, not an internally scrolling card inside another scroll view. No real resource navigation is offered before host acknowledgment; staged originals are labelled local.

### 4. Captured-source delivery and recovery

One native import dispatcher owns durable transitions. Persist sending/attempt identity before transport. Native resolves the *captured* host profile, pinned TLS, workspace header, generation, capability, grant and current network policy; it never activates the reading source. Stream file bytes from private storage with bounded buffers; cancel/deny on revoked or changed approval and reject redirects. Use exact retry after unknown outcomes and persist a fully validated acknowledgment before any payload cleanup. App process death restores sending as uncertain. Receipt-storage failure leaves the claim and original bytes intact.

Reuse Review concepts: single-owner admission, native credentials, immutable operation identity, durable-before-send, bounded backoff, coalesced foreground/reconnect opportunity and source-lock observation. A small shared transport/admission helper is appropriate only after preserving both domains' tests. **Do not share Review payloads, journal, receipt validator, status enums or resource target authority.** Review sends small immutable evidence attached to an existing resource and polls desktop status; import sends original bytes/conversion intent and creates a new resource. Review success cannot acknowledge an import; download eviction cannot remove either queue. Upload metered policy must not silently change Review synchronization behavior.

Automatic delivery starts only after explicit import confirmation and admission. Foreground/reconnect and manual Retry are authoritative; no delivery guarantee while suspended/force-stopped. Network/busy/temporary host failures use bounded retry; unsupported capability, generation mismatch, missing collection, conflict, permission or revocation remain explained and preserve staging. Reapproval must prove the same identity; changing address is not retargeting. A committed import does not automatically enter the offline checkpoint: show host-created/refresh-needed until a normal verified refresh includes it.

Cancel unattempted work safely; sending/unknown work can stop further attempts but cannot promise host rollback. Retain uncertain identity/bytes until reconciled. Remove-local-copy needs an explicit consequence if recovery would be lost; never automatically evict an unacknowledged row. Acknowledged original-file staging can be cleaned after exact persisted receipt and any required local-availability policy; preserve a lightweight completion receipt so restart/UI refresh cannot redispatch.

### 5. ZIP authorization boundary

Recognize a possible workspace ZIP separately from ordinary original-file import. Validate only on host through existing archive limits/checksums/path/document checks; no local extraction or new privileged mobile replacement route. New workspace creation is host-level, not a collection choice in the current workspace. Never send a workspace ZIP to `/imports/.../commit` against an existing workspace or relax OWNER checks for all paired devices.

**Recommended decision:** Android can collect/retain the ZIP and request an owner-approved import-as-new handoff; host owner reviews/confirms the immutable hash/name/operation before W3 creates/publishes the independent workspace. This needs a narrow request/approval/receipt bridge, not existing functionality. Alternative: an explicitly granted, revocable per-device import-as-new capability, with its own bounds/approval and grant on the resulting workspace. Until this decision is approved, ZIP remains locally staged/needs owner action; ordinary R7 imports need not wait for an invented administration model. No automatic access grant, replacement, merge into the focused workspace or desktop credential forwarding.

### 6. Focused acceptance, integration and release

Implement in order: host capability/conversion/generation/receipt contract → native crash-safe staging → destination confirmation/Pending UI review gate → captured-source dispatcher/reconciliation → approved ZIP path → focused integrated/upgrade/release checks. Keep each slice coherent and stop at authorized sprint boundaries; this sequence does not authorize six independent releases or extra milestones.

Focused host checks cover identical/different UUID intent, atomic generation rejection, collection changes, safe conversion/encodings/warnings/limits, receipt durability and post-create resource lifecycle. Native checks cover cold/warm Share including pre-JS delivery/recreation, SAF/photo-provider URI loss, copy interruption/disk full, corruption/process death, receipt failure, no wrong-source dispatch and legacy/Review separation. Use disposable API36/37 emulators with explicit serials and ordinary pinned HTTPS approval; no phone pairing. Test lost actual host acknowledgment, death after sending, reconnect, duplicate filenames, batch partial success, revocation/replacement, changed source/address and exact hash outcome. Check retained reader/Aa/Back/reduced-motion/focus while queue changes; review new interaction in motion. Real provider/OEM/haptic acceptance remains user-owned.

Run compilation and changed-domain checks only; don't replay full R6 suites or Docker by default. If host contracts change, ship compatible fresh host/desktop and Android artifacts with update order/capability refusal on older hosts, original identities/signers and immutable tags. Alpha.23→next installed upgrades must retain protected Reviews, legacy recovery, downloads, preferences and new pending imports. Update topic guides/CODEBASE with actual results. No release/version bump for this planning checkpoint.

## Product decisions for roadmap approval

1. **ZIP authorization:** recommended owner-approved import-as-new handoff; alternative narrow delegated permission. Existing paired-device access is insufficient. This is the main authority decision.
2. **Text/Markdown original retention:** recommended preserve raw bytes locally through acknowledgment, then retain the source bytes on the host as import provenance without automatically adding a second visible File resource. Exact host provenance storage/recovery/portability and bounds must be specified in R7; current conversion stores only structured JSON. If source bytes need to remain visible/exportable as a separate resource, explicitly choose that instead. Do not silently discard raw bytes or invent an extra Library item.
3. **Queue policy:** approve or adjust the initial ordinary-import envelope above and **Wi-Fi/unmetered automatic upload by default**, with an explicit per-operation cellular override. Keep download policy and small Review catch-up behavior unchanged; exact limits must be validated against host capability and crash-safe encryption overhead.

Home placement, no fourth tab, explicit destination and frozen retry identity are the recommended interaction contract for approval. No additional speculative product features are proposed. R8 partial schema and R9 update/discovery implementation choices are settled at their owning milestone gates. **Stop here for roadmap approval; do not begin R7.**

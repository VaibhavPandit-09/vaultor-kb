## Interaction and ownership

- Shell: the original288px sidebar starts at the window edge. Native controls stay at the top right; the note journey belongs to the main workspace. Library retains40px chrome clearance through compression. Collapse moves the same sidebar allocation/surface; its launcher remains reachable.
- Library: one original LibraryOrientation transforms title/search/actions/paging into one compact lane. The same bounded resource rows retain selection/navigation authority. Header context discloses below only when requested. Reverse scroll expands the same header.
- Note: NoteOrientation owns title/organization compression. Pin belongs with header actions; collection/tag controls belong in organization. Formatting is disclosed from the header using LibraryPopover; selected text uses the existing selection-aware controls without reserving a permanent toolbar row. One shared document/writer can have two visible views; Settings creates none.
- Settings: opening preserves workspace DOM, panes, history and scroll. The original SettingsSurface supplies geometry/glass/motion; dialogFocus/Escape owns containment and launcher restoration. Closing immediately ends interaction ownership; shared motion may retain only an inert visual exit copy. No correctness depends on animation completion.
- Appearance: Rust validates profile opacity0.6–1.0; default0.85 matches the original. Original NumberRange supplies60–100%,5% steps and numeric validation. `--ui-opacity` changes backgrounds of panes and shared menus/dialogs; glyphs/text remain opaque. This is CSS backdrop glass inside an opaque WebView2 window, matching the inspected original implementation, not native desktop transparency.
- Motion: existing timing/easing/reduced-motion services remain authoritative. Sidebar category direction is now actually applied; pane/grid/focus transitions retain their document/view identities. Window controls are portaled outside workspace navigation transforms and modal stacking contexts. Shared popover initial focus yields to already-focused controls or newly opened child portals; palette-to-Settings handoff restores the launcher before opening the new dialog. System reduced motion takes priority.

# Vaultor 0.23.0 — Windows only

Published Windows x64 on2026-10-27 at [v0.23.0](https://github.com/VaibhavPandit-09/vaultor-kb/releases/tag/v0.23.0), explicitly authorized after disclosure of the failed1MiB performance qualification. This release preserves 0.22.0 recursive collection deletion and improves linked Markdown worker validation, source-range reuse and large-draft protection.

## Known large-document limitations

**General 1 MiB rich-text usability is not qualified.** In the Gate 1 lab, near-1 MiB worker-validation p95 improved from671ms to44ms and typing-to-frame p95 from34.6ms to30.0ms. The packaged prose-heavy near-1 MiB fixture nevertheless took8seconds to open and measured629ms typing p95. A denser fixture exceeded the preserved30,000-node parser ceiling and safely opened read-only. Candidate admission is1MiB/8,192 root blocks/30,000 parser and render nodes, with existing text-block, table and clipboard bounds. Large documents can remain slow or read-only; this is not completion of the1MiB performance milestone.

Source-authoritative editing, explicit Ctrl+S, protected syntax, exact untouched Markdown, conflict refusal and durable recovery remain enforced. Packaged beginning/middle/end Saves, native Undo/Redo, external-conflict refusal and dirty-draft restoration after full application restart passed. Frontend198-case regression, additional parser-cap checks,49 existing linked desktop checks plus the large-file integration, native safety68/68 and consent7/7 passed. Production UI/server builds, lint and original-key artifact verification passed. No installation over the user's app, new physical multi-volume/power-loss acceptance or native peak-memory qualification is claimed.

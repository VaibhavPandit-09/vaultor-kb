# Vaultor 0.18.2 — desktop navigation and diagnostics

Windows x64 patch; Mac arm64 qualification is pending. GitHub Latest must remain the fully qualified v0.18.1 until the matching Mac pair is verified. Android alpha.28 and the isolated Linked Markdown Gate1 work are unchanged; Gate2 is not started.

## Behavior and root causes

The global browser error listener previously forwarded every error event into the same red Dashboard banner, which unconditionally exposed Retry saves and an event identifier. Native ResizeObserver delivery notifications have no exception object or source line; they are browser layout scheduling diagnostics, not evidence of a save failure. Only the two exact known delivery messages with that native event shape now become rate-limited informational layout diagnostics. Thrown exceptions, rejections and other ResizeObserver-related errors remain visible. Events distinguish layout, UI, application, save, recovery and integrity categories with info/warning/error/critical severity. Critical styling is reserved for critical failures; Retry saves requires an actual failed SaveCoordinator operation. Identifiers remain in Details.

Pane/header/Journey geometry callbacks previously performed React/CSS/scroll writes within observer delivery. These avoidable feedback paths now coalesce writes into a cancellable animation frame; header CSS measurements are deduplicated. The intermittent natural third-pane trigger was not reproduced during36 resize/focus cycles. A separate bounded native observer feedback probe reproduced four real browser notifications, confirmed the exact document-URL/no-exception/no-line shape, and verified diagnostic retention without a false save banner. This establishes classification and removes identified feedback risks, without claiming proof of the intermittent original trigger.

Ordinary direct navigation now defaults to Fill available panes, then replace. Maximum visible panes remains a ceiling1–3. Automatic filling also respects the existing actual workspace side-by-side capacity (>850px two, >1200px three); narrow clicks do not create hidden panes. At capacity the focused assignment is replaced and the displaced session remains in Open Notes. Already-visible notes focus their pane; inactive existing sessions retain identity. Links continue the source journey. Explicit splits remain available, falling back to the focused slot at maximum without confirmation. Live placement is rechecked after loading/save barriers. Narrowing preserves sessions and existing assignments.

Workspace setting **Opening new notes** persists noteOpening=fill|reuse, default fill; Always reuse focused pane is available. Old openBehavior split/replace deliberately migrates to fill and is no longer emitted. Session schema, journeys, protected drafts, archive formats and protocol3 are unchanged.

Collection0.18.1 implementation is retained: measured breadcrumb withdrawal followed by title migration, accessible full Path, metadata-paged All default and persistent Hierarchy presentation, direct immediate-child discovery with shared management. No import engine or editing engine redesign.

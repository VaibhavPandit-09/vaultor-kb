## Changes and support

Native Apple Silicon APFS linked folders now use the existing rich editor, source-preserving Markdown patches, explicit Save/Command-S, conflicts, drafts/Recovery, relative links/scoped assets, search and reference-only collections/Open Notes. Common authorization, publication, journals and recovery remain shared. Windows filesystem/metadata implementations moved to a selected platform source set; shared capture now also checks captured content before publishing.

The [linked-source contract](../../workspace/LINKED-SOURCES.md#macos-filesystem-support) owns APFS authorization, metadata, concurrency and refusal boundaries. Ordinary writable owner-owned local APFS files are admitted. Internal APFS and a distinct mounted APFS disk image were tested. No external APFS hardware, physical unplug, power-loss/disk-full matrix, exFAT/SMB/network/cloud synchronization or Mac Intel result is claimed. Extended ACLs, special flags/modes, non-owner/read-only/multiple-hardlink files and nontrivial xattrs/resource forks refuse direct Save; incidental OS provenance is admitted without exact transfer guarantees. The256KiB editor admission remains. POSIX does not provide Windows deny-write/delete share modes or a filesystem-wide revision CAS.

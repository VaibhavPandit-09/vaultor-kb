# Vaultor 0.5.0 — safe resource lifecycle

Windows x64 only. Mac arm64 has no verified package for this version; native build/access is unavailable. The exact same-tag procedure is in [Mac handoff](https://github.com/VaibhavPandit-09/vaultor-kb/blob/v0.5.0/docs/desktop/MAC-HANDOFF.md). No Linux/Android native package is promised.

## Changes

Shared resource Actions now provide Open/Preview, Rename, collection/tag organization, Pin, applicable Export/Download and Move to Trash across browsing, shortcuts and resource headers. Ctrl+K hands deletion to the same confirmation flow. Trash retains original IDs, file bytes, documents, surviving memberships/tags and pins. Restore returns that same resource; nothing is purged automatically. Removing a placement, unpinning or removing collection membership remains separate from trashing its original.

Trash provides bounded title browsing, bulk Restore and explicit permanent deletion with saved-usage warnings. Partial failures stay selected and retryable. Revision checks and durable operation identities prevent uncertain retries from repeating a destructive mutation. Binary cleanup commits irreversible intent first; cleanup failures remain unavailable and retry against the same identity, including after server restart. Incoming labels/placements remain identifiable; referring notes are not rewritten.

Local relevant drafts must save before Trash, or the user explicitly keeps a verified recovery copy and trashes the saved version. Foreign Trash pauses all mounted views and retains content for recovery; unavailable history remains identifiable. No old DELETE fallback, no automatic resurrection.

## Compatibility and updating

**Update hosts before remote clients. Both need 0.5.0 / API protocol 3, minimum client 3.** An updated Windows local app includes its bundled host; an old remote Mac host still needs its separate native update. A Windows client update does not update that host, and compatibility refusal is deliberate. The former hard DELETE and replace-links routes return 405 on this host.

Installed Windows 0.4.1+: window menu → Updates → Check for updates → **Update and restart**. Both signed files are fetched/verified internally; save, backup, install and relaunch are coordinated. Older installations: download the EXE, finish saving and Quit from tray/menu, then run the installer once; the signed-pair manual import remains available for backup-aware transition. Personal OS installers are unsigned for SmartScreen purposes; the original Ed25519 update signing identity is unchanged.

Additive lifecycle columns and local retry ledger; old rows default active. Complete workspace ZIP format **3** retains Trash and original files; imports read formats 1–3. Purge-pending workspace export is refused. Ledger identities stay outside portable archives. Do not run old application code on the changed database: rollback uses the pre-update verified backup in separate recovery storage, not a blind executable downgrade. No new runtime dependency.

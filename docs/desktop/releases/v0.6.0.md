# Vaultor 0.6.0 — file discovery and saved references

**Windows x64 only.** Mac arm64 has no verified package for this version; native access/build verification remains unavailable. [Exact same-tag Mac handoff](https://github.com/VaibhavPandit-09/vaultor-kb/blob/v0.6.0/docs/desktop/MAC-HANDOFF.md). No Linux/Android native package is promised.

## Changes

Images, PDFs, Audio, Video, Text and Other files are searchable Type-filter categories within Files. Library, Recent, collection contents and Pinned stay mixed and server-paged, with true filtered totals. Shared labels/icons cover browsing, sidebar, Ctrl+K, pickers, inline links and previews. New upload/import MIME inspection uses bounded signatures; old stored MIME is not rewritten automatically.

Image browsing uses authenticated lazy static thumbnails, at most 320 px and 384 KiB, with a 48-entry/8 MiB connection/workspace-isolated cache. Original bytes remain unchanged. GIF thumbnails do not animate.

On-demand **References** replaces the automatic backlinks sidebar. Used in counts distinct active saved notes and occurrences separately; Links out identifies targets, repeated placements, cycles and missing/trashed destinations. Resource Actions, headers, image tools and lifecycle confirmations expose it. Results default to 30 rows (maximum 100), with 20 displayed occurrences per row and full occurrence totals. Opening a source can select a validated saved occurrence; changed paths, revisions or drafts safely fall back to opening the note. Local unsaved references are labeled separately.

## Compatibility and updating

API protocol/minimum client **3** and complete archive format **3** remain unchanged from 0.5.0. No schema migration or runtime dependency is added. Update the selected host to 0.6.0 for category/reference/thumbnail APIs, then clients. An older protocol-3 host reports an explicit update requirement for category requests; scope is never silently broadened. Updating a Windows client does not update a remote Mac host.

Installed Windows 0.4.1+: window menu → **Updates → Check for updates → Update and restart**. Downloads/signature checks, relevant saves, backup, installation and relaunch are coordinated internally. Older clients: download the EXE, save and Quit through tray/menu, then run the installer once; manual signed-pair import remains available for backup-aware transition. Personal OS installers are unsigned for SmartScreen purposes; the original Ed25519 update identity remains unchanged. Never downgrade an upgraded lifecycle database blindly; use the verified pre-update backup procedure.

## Actual validation and limits

- Frontend/Java production builds and scoped lint passed. **47 distinct focused frontend, 11 backend and two desktop tests passed**: category isolation/counts, legacy-host refusal, ordering/preferences, stale/retained rows, reference counts, keyboard/focus, occurrence selection, MIME limits, static thumbnails, original image/export behavior and archive merge/replace.
- Disposable packaged Windows session checked mixed resources, Images filtering, thumbnails, Used in/Links out, exact occurrence selection and source focus. Seven initial frames covered simulated theme tokens and 680 px layout; final reference/source/narrow behavior and keyboard ownership were rechecked. Theme simulation does not verify OS changes or physical OLED hardware.
- Disposable 0.5.0 → 0.6.0 installer upgrade, repair, uninstall/reinstall and separate sentinel retention passed; prior shortcuts were restored. No personal workspace/production installation was used.
- Five fresh renderer assets match packaged UI and embedded browser JAR; packaged main/preload/policy match source. Windows installer **245506062 bytes**, SHA-256 **87c33a4d2a0645dd2e48b97d1f0444575b11d530840e78c23f2ad93b1417d99e**. Original-key sidecar preflight passed.
- No broad API smoke or routine Docker rebuild. Mac/LAN/touch/physical OLED checks remain unavailable. Reference queries scan saved JSON and retrieve bounded occurrences per result; large Atlas cost is not certified here. File-body search is not implemented; title-first and explicit saved-note content search remain. Historical MIME can limit category discovery. Video/audio thumbnails are not generated.

This finishes Sprint 3. **Two sprints remain:** supported saved file-content search, then measured scale/multi-device/Android readiness. Android implementation and scheduled backups remain deferred.

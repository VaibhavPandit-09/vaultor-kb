## Changes and measured results

- Avoids repeated whole-manifest deserialization during companion payload transfers using one reclaimable immutable parsed value per workspace for manifests with serialized bytes at most4MiB. Every request still reads/hashes current bytes and validates receipt ownership, grant, generation, expiry/cancellation and If-Match; streams retain per-chunk authority checks.
- Corrects reproduced inherited editor DOM attributes through compatible frontend Tiptap3.31.4/ProseMirror view1.42.7 dependencies; updates Axios1.20.0 and router-dom7.18.4. Frontend and desktop runtime npm production audits reported0 at qualification. Remaining development/packaging-tool advisories are recorded rather than claimed resolved.
- Controlled Atlas5000 payload observation:50 warm samples, median24.63→15.41ms and empirical p9540.67→24.24ms. This is a payload-path measurement, not a whole-app/LAN speedup claim.
- API36 Atlas readable download was408.65seconds for21.26MB; candidate full refresh was366.74seconds. First download and refresh are different operations. Final retained Windows Atlas profile reached Library in19.05seconds; these observations do not establish a cold-cache startup speedup or a numeric performance guarantee.

The [R10 report](https://github.com/VaibhavPandit-09/vaultor-kb/blob/master/docs/development/qualification/R10.md) records complete Small70/Atlas5000 timings, frame observations, query/media latency, memory/storage, queue recovery and failed harness attempts. High Windows startup/memory and multi-minute Atlas transfer remain measured costs. Approved R6 Android Home/Library/Review, source switching, contextual Aa, themes, motion and semantic haptics are preserved.

## Compatibility, update and recovery

API protocol3, checkpoint schema1, full archive5 and partial package6 remain unchanged. Androidalpha.28/code32 remains compatible and its product source is unchanged. No workspace-schema migration or data clear is required.

Installed Windows0.4.1+: open Updates → Update and restart. The updater selects complete signed Windows pairs even though this partial-platform release is non-latest. Manual installation: fully quit Vaultor including tray hosting, run the EXE and reopen. Keep the matching signed sidecar beside the EXE for offline import/verification. Do not uninstall or clear app data to update. Hosting briefly stops; paired clients reconnect. Preserve pre-update backups and use Advanced recovery if needed. See the [installation guide](https://github.com/VaibhavPandit-09/vaultor-kb/blob/master/docs/desktop/INSTALLATION-AND-UPDATES.md).

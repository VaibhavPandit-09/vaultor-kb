# Vaultor 0.18.0 — Nested collections and folder imports

Windows x64 release, 2026-10-24. This is a Windows-only stable, non-Latest partial-platform release. Mac Apple Silicon execution/signing access is unavailable; no Mac artifact is claimed. Source: immutable `v0.18.0` on master, release commit `de8137804b7fdf11aefeee38abb617ffeeed4fa9`.

Nested collections preserve multi-membership resource identity, provide ancestor breadcrumbs and contextual subcollections, and support safe subtree moves. Existing SQLite collections migrate to roots without ID/favorite/membership resets. Parent deletion requires moving or deleting children first and never deletes their resources.

Import folder recursively imports regular files and empty directories on desktop. Review leads with counts and batch choices, with collapsed folder preview, paged overrides and grouped issues. Stable IDs and a durable source-scoped journal support interrupted retries after reselecting the source. Relative Markdown links and supported local images resolve to managed resources after creation. Heading fragments remain explicit text rather than automatic scrolling. Original files remain untouched; no filesystem synchronization is introduced.

## Compatibility and limitations

Protocol/minimum-client3 remains. Hierarchy-bearing full/partial archives use7/8; flat exports retain5/6. Do not downgrade workspace databases into older hosts. Existing Open Notes, sessions, journeys and revision-checked editing retain their architecture. Androidalpha.28 live reading and host exports remain available; its offline exporter drops hierarchy, so checkpoint1 downloads containing nested collections are explicitly refused. Existing downloads/flat selections remain usable. No Android APK is included.

Browser folder inputs cannot retain empty folders; use the desktop picker for full hierarchy. Native imports reject symbolic links/junctions. Imports are bounded to2,000 entries and32 levels. Restart resume requires matching source paths/sizes/modified times and retained browser journal storage. Failed creation delays relationship finalization, preserving readable text references. User edits made before finalization are preserved and reported. See [import contract](https://github.com/VaibhavPandit-09/vaultor-kb/blob/master/docs/workspace/IMPORTS.md).

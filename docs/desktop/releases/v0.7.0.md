# Vaultor 0.7.0 — explicit saved file-content search

**Windows x64 only.** Mac arm64 remains unavailable pending native build/key/verification. [Exact same-tag Mac handoff](https://github.com/VaibhavPandit-09/vaultor-kb/blob/v0.7.0/docs/desktop/MAC-HANDOFF.md). No Linux/Android native package is promised.

## Changes

Library and Ctrl+K keep Titles only as the default. **Include saved content** now opts into saved note text, text-bearing PDFs and UTF-8 text/Markdown/CSV/JSON/XML/code files. Collection, tags, type/category and pin filters stay in force. Ranked results use title weight 10 / body 1, deterministic ties and bounded plain-text snippets/highlights.

Scoped coverage distinguishes pending, unsupported, encrypted/invalid/limited, and PDFs without text; no OCR is claimed. Pending results offer Refresh results. Diagnostics adds paginated file status and retry. Originals remain unchanged; extracted text is derived, rebuilt after archive import/replacement and invalidated by resource version/workspace generation. Mounted documents and drafts are untouched.

Limits: PDF 20 MiB / 100 pages, text 4 MiB, 500,000 UTF-16 units/file. Parsing runs one file at a time in an owned JVM with 128 MiB heap/96 MiB metaspace and 15-second timeout. It holds no SQLite connection while decoding and inherits no host credentials. This is not an OS sandbox or total RSS guarantee. Pinned Apache-2.0 PDFBox 3.0.8 also passes existing PDF export checks. No remote URLs/scripts/attachments/macros/office/OCR extraction.

## Compatibility and updates

API/minimum client **3** and archive **3** remain unchanged. The new table is disposable derived data, not a domain/archive migration. Update the **selected host to 0.7.0**, then clients, for file-body and coverage semantics. Older protocol-3 hosts may connect; they report missing file coverage rather than certifying title-only matches as body search. Updating a Windows client does not upgrade a remote Mac host.

Installed Windows 0.4.1+: window menu → **Updates → Check for updates → Update and restart**. Download/verification/save/backup/install/relaunch is coordinated internally. Older installations: save, Quit through tray/menu and run the current EXE; manual signed-pair import remains available for a backed-up transition. The original Ed25519 trust remains; personal OS installers are unsigned for SmartScreen purposes.

## Actual checks and limitations

- Frontend/Java production compilation and scoped lint passed. **17 distinct focused frontend, 15 backend and 2 desktop checks passed.** These cover title/content/scope and stale responses, literal/Unicode ranking, coverage safely rendered as text, pending/invalid/encrypted/page/byte/output limits, actual subprocess timeout termination, missing-byte failure/retry, revision/generation invalidation, Trash/Restore, archive merge/replace and PDF export regression.
- Disposable protected packaged host + native Windows app passed body-vs-title, collection/category isolation, paged status, failed/unsupported limits, restart cache reuse and Library/Ctrl+K excerpts/coverage. Two frames were inspected. No personal workspace or production installation was used.
- Disposable 0.6.0→0.7.0 upgrade/repair/uninstall/reinstall and sentinel retention passed; final artifact verification follows below. Five renderer assets match fresh dist and embedded browser JAR; original-key package preflight passes.
- [Bounded Atlas observation](https://github.com/VaibhavPandit-09/vaultor-kb/blob/v0.7.0/docs/development/FILE-SEARCH-MEASUREMENTS.md): 5,000 resources/1,000 files; six warm searches during indexing median 164.0 ms, max 248.2 ms. After 60 seconds, 63 files indexed/133 unsupported/3 no-text/801 pending. Full coverage, cold cache and peak/combined child memory were not measured. Large replacement caused a 30-second SQLite pool timeout on status; import completed. This remains Sprint 5 work.
- No broad API smoke or Docker build. Mac/LAN/touch/physical OLED unverified. File coverage is asynchronous; metadata mutations may requeue files. Direct external changes to stored bytes require explicit rebuild. No PDF page-jump/OCR/office extraction. One backend owns each database.

# Vaultor 0.18.1 — Collection navigation and header polish

Windows x64 and Mac arm64 patch, 2026-10-24. Complete-platform stable Latest release. Source: immutable `v0.18.1` on master, release commit `f8bd4743c2ee4225cc1597ddc16ddcfee06bca8e`. No Android rebuild is required.

## Changes

- Corrects nested breadcrumb/title collisions during header compression. The breadcrumb withdraws before the title enters its lane; measured breadcrumb height/title wrapping determine geometry. One persistent Path control exposes all full ancestor labels. Narrow actions compact to labeled icons and reduced motion uses the existing immediate endpoints.
- Collections defaults to All: bounded, independent entries for every collection, with parent paths distinguishing duplicate names. Hierarchy retains lazy child expansion and capped indentation. Search spans all paths in both modes. The same rows provide pins, contextual subcollections and rename/move/delete; arrow keys navigate loaded rows and expand/collapse the tree.
- All/Hierarchy preference uses shared device-local settings in the selected workspace. Parent browsing prominently groups immediate children alongside direct resources and improves its empty-resource guidance.

## Compatibility and installation

Resource identities/memberships, import engine, structured documents, protocol3, archives5/6 and hierarchy7/8 are retained. The additive collectionView presentation setting defaults to All on existing profiles and requires a 0.18.1 host for persistence. Android alpha.28/code32 is unchanged, including the documented nested-checkpoint boundary. No filesystem watching, linking or synchronization is introduced.

Installed Windows 0.4.1+: Updates → Update and restart. Manual Windows users quit Vaultor fully and run the EXE without uninstalling or clearing data. Mac users download and mount `Vaultor-0.18.1-mac-arm64.dmg`, dragging `Vaultor.app` to Applications to replace the previous installation while preserving data. The original Ed25519 update identity is preserved; Windows EXEs are not Authenticode signed and macOS builds use personal ad-hoc codesigning with standard user Gatekeeper consent. Native Apple Silicon qualification is complete, and the release is promoted to Latest.

## Root cause and visual evidence

The old collection CSS put the breadcrumb and compact title at the same top coordinate and moved the title by a hard-coded68px, enough only for Library /. Nested ancestors continued into the title lane. The correction removes that width assumption: measured breadcrumb height reserves its own lane until withdrawal completes, then the same title migrates upward. Full ancestors stay accessible through Path; the expanded row retains the nearest ancestors that fit measured text widths.

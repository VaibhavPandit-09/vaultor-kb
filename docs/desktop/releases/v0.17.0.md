# Vaultor 0.17.0 — Open Notes and multi-pane navigation

Windows x64 release, 2026-10-23. This is a **Windows-only stable, non-Latest partial-platform release**. macOS Apple Silicon build/signing/native execution access is unavailable in this environment; no 0.17.0 DMG exists or is represented as qualified. Android remains alpha.28/code32 and is unchanged.

Source: immutable `v0.17.0` on master (the tag resolves to the exact release source commit). Both desktop targets must use this same tag/version; adding Mac later requires original-key signing and native qualification, without changing the tag or Windows bytes.

## Changes

- Open Notes now manages sessions independently of one, two or three viewing panes. Ordinary opening reuses the focused pane immediately after the departing save barrier, retains displaced sessions, and never asks for pane replacement.
- Selecting an already open note preserves its journey, caret and reading position. Explicit splits use the session menu or Ctrl/Cmd-click on a link; visible destinations receive focus rather than a duplicate direct session.
- The existing sidebar lists sessions in stable opening order, identifies active/visible panes, filters larger lists by title, and offers individual Close plus contextual Close others/all. Inactive editors are unmounted; clean inactive bodies are evicted.
- Close pane retains its session. Close note removes the session and fills its viewing slot from the last opened inactive survivor, otherwise focuses the rightmost surviving pane. Journeys belong to sessions and linked Back/Forward retains per-visit positions.
- Local and connected-client Trash/purge remove active and inactive sessions. Historical references remain unavailable. Restore makes a note available without reopening it. Recovery copies and conditional autosave remain independent of navigation cleanup.
- Version-2 layout snapshots preserve every session and stable viewing-slot assignments, migrate version-1 pane layouts without a reset, retain excess legacy panes as inactive sessions and distinguish missing resources from temporary network failure. Visible bodies and inactive summaries load separately.
- Maximum visible panes replaces the misleading Max open notes label (same shared `maxOpenNotes` key). Automatic split/Open behavior is retired and legacy values normalize to direct replacement. Alt+arrows keeps pane focus; configurable Ctrl/Cmd+Alt+PageUp/PageDown switches open sessions. Existing history, close-note, Escape and editor bindings remain.
- Bounded saved-state reconciliation and eight-request client backpressure prevent session restoration from overrunning the unchanged native bridge admission limit. Queued requests cancel on source departure; mutations are never replayed.

## Compatibility, installation and recovery

Resource/structured Tiptap JSON, database, API protocol/minimum client 3/3, checkpoint1, full archive5 and partial package6 are unchanged. No Android rebuild, database reset, workspace data clear or signing-key replacement is required. The local session snapshot upgrade is additive; independent draft journals are retained. Undo is transient and is not retained after the last editor for a note unmounts. Scroll/caret offsets are numeric, not semantic anchors across remote edits; snapshots can lag by 500ms and browser storage remains best effort.

Installed Windows 0.4.1+: **Updates → Update and restart**. Platform-pair discovery can find this newer signed Windows pair independently of GitHub's global Latest flag. Manual users fully quit Vaultor (including tray hosting), run the EXE and reopen without uninstalling or clearing data. Keep the matching original-key sidecar with the EXE for offline import. The updater's normal save/backup/recovery barrier remains authoritative. A remote host updates separately. See [installation](https://github.com/VaibhavPandit-09/vaultor-kb/blob/master/docs/desktop/INSTALLATION-AND-UPDATES.md).

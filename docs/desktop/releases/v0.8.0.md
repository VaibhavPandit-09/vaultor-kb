# Vaultor 0.8.0 — isolated host workspaces (W1)

**Windows x64 first; Mac arm64 build/native verification pending.** No new Android APK or Linux installer. Publication/artifact ledger is recorded after verification; a candidate build is not a release.

- The host can address up to eight isolated workspaces, each with independent metadata/files, transactions, search/index workers, transfer operations, maintenance and change streams inside the existing JVM.
- Existing data stays in place as the fixed default workspace. Initial catalog adoption creates and verifies a SQLite metadata checkpoint; damaged catalog/identity states fail without resetting storage. This checkpoint is not a complete file backup.
- Additive owner APIs create/rename workspaces and assign device grants. New workspaces do not automatically admit paired devices. Workspace data and streams are authorized independently; revocation closes affected streams, and queued transfers check their captured admitting device before starting work.
- Existing clients still address the fixed default workspace. **Workspace selectors are W2, import-as-new/local-copy UI is W3, and Android reader/offline changes are later sprints.** No new picker or Android editing removal is claimed here.

API/minimum client **3/3**, archive **3**, updater **1** remain unchanged. No existing resource schema migration or dependency change. Host catalog/context storage is new; preserve the complete owned data directory for recovery. Portable archives do not contain the host catalog/grants/credentials. This release does not turn on LAN sharing.

# Vaultor 0.19.1 — linked Markdown admission and read-only preview

Published Windows x64 patch, reviewed2026-10-25. Mac0.19.1 is unqualified; complete-platform GitHub Latest remains0.18.1. Android is unchanged.

## Fixes

An ordinary linked Markdown file with an NTFS tracking object ID was incorrectly refused as SPECIAL_FILE. PracticalMetadata.inspect delegated to a historical strict condition that treated a successful FSCTL_GET_OBJECT_ID query as OBJECT_ID_UNQUALIFIED:0. Reproduction returned BOOL1,64bytes and independent STATUS_SUCCESS0x0; there was no failing Windows operation. A plain copy dropped the ID and passed; adding an ID to a disposable copy reproduced the same exception. The ordinary-file policy now admits a correctly sized successful ID query. Unexpected query failures, ADS/EA, multiple-hardlink and other existing safeguards remain. The original is never modified to pass admission. Incidental tracking IDs, like physical file identity, need not survive publication.

Read-only linked Markdown now defaults to formatted GFM when valid UTF8 and within256KiB/render-complexity limits, independently of direct-Save admission. View source / View formatted switches the same document surface. Large, invalid-encoding and over-budget input retains safe source access. Raw HTML remains inert; images cannot trigger remote fetches and local/unsafe links do not gain browser filesystem navigation. No write capability is granted by preview.

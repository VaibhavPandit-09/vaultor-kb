# Vaultor 0.24.0 — Windows UX reliability

Published Windows x64 on2026-10-29 at [v0.24.0](https://github.com/VaibhavPandit-09/vaultor-kb/releases/tag/v0.24.0). Immutable release source: `4bde1ab944aacbf29bffb0aee193bad1a4c51332`; subsequent publication-ledger changes are documentation only.

## Changes

- One corner Activity popover owns ordinary batch import, workspace ZIP/local-copy preparation and commits, full/partial exports and Empty Trash. Reviews close after durable dispatch; unrelated browsing and minimization remain available. Interrupted work retains IDs/receipts and requires safe explicit resume or source reselection.
- Exact typed maintenance waits retry for a bounded interval without alarming global notices. Genuine failures and stuck locks remain visible. Diagnostics retain request/route/status/source and gate ownership evidence.
- Byte/path-matching prior imports offer recommended Skip unchanged or explicit independent copy. Ambiguous/changed sources never silently merge or overwrite edits. Legacy unfinished imports retain IDs and revalidate host fingerprints.
- Compact browse/collection/Trash headers use one title/action row with accessible icons and on-demand filters/details. Selection reveals page actions; Trash rows use ellipsis menus. Direct resources and child collections are counted separately.
- Empty Trash separately confirms an all-pages server snapshot, excludes later arrivals, protects changed/restored revisions and retries durable per-resource cleanup. Linked external originals remain untouched.
- A CSP-compatible pre-paint theme bootstrap and matching native window background apply device Light/Dark/OLED/OS before the first styled UI. Intentional theme reveals remain unchanged.

## Compatibility and limits

API/minimum-client protocol3 and existing full/partial archive schemas remain unchanged. New background export/merge and Trash snapshots require host capability `backgroundOperations:1`; update remote hosts to0.24.0 first. Ordinary source files are copies and never removed. New renderer journals exclude source text/documents/bytes, absolute paths and credentials. Host/task/lifecycle receipts stay private and nonportable. Resume never automatically enters a different profile or generation.

In-place updates of changed imported files remain unsupported; use explicit separate copies. Source recognition depends on retained device journals and exact content/relative paths, not proof of physical-folder ownership. Clearing browser storage removes recognition. Captured editor/slash insertion keeps its existing contextual target review. Activity does not promise arbitrary filesystem jobs survive complete app exit. Host integrity gates remain; a stuck lock becomes actionable after30seconds. Empty Trash supports20,000 targets per reviewed snapshot,50-item batches and128 retained snapshots; confirmed receipts are not automatically evicted. Existing large linked-Markdown responsiveness limitations from0.23.1 remain unqualified by this UX pass.

Known issues identified after publication: Activity overlaps the Windows menu/drag-grip region because its offset omits part of the control group. Repeat-import review can describe retained history even after collections/items were removed, and its path-only state has an unclear single-radio approval gate. [The2026-10-29 audit](../../design/MENU-UX-AUDIT-2026-10-29.md) documents the original source evidence. These issues are corrected by the separately qualified and published Windows[0.24.1](v0.24.1.md);0.24.0 itself retains its original bytes and behavior.

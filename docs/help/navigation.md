# Panes, Open Notes and history

## Sessions and visible panes

An Open Notes session keeps a note journey; a pane is a visible viewing slot. More open notes do not mean more visible panes. The sidebar's Sessions category shows Open Notes; Auto exposes it while editing, while an explicit category choice takes precedence.

Ordinary opening fills available panes then reuses the focused pane, unless Settings chooses Always reuse focused pane. Maximum visible panes is 1–3; available width also limits ordinary side-by-side opening. At capacity, the departing note is saved before its slot is reused. Its session stays in Open Notes. Opening an already current destination focuses it without resetting its journey.

## Open in another pane

Use a note's Actions menu or an inactive Open Notes entry's **Open in another pane** action. Ctrl/Cmd-click a resource link also requests a split. At the configured limit, the focused slot is reused. Files use previews rather than new note panes.

Drag Open Notes sessions to reorder them. Pane targets can arrange or swap visible sessions; follow the displayed destination hint. [Dragging](interactions.md#drag-and-drop) describes resource drops separately.

Closing a pane removes its visible assignment. Closing an Open Notes session removes that session. Close other notes / Close all notes use the existing save safeguards. Closing is not Trash.

## Back, Forward and History

Each session has its own journey. Use Back/Forward or History to revisit destinations; these are separate from Open Notes order. Reading positions are retained on a best-effort basis. The [shortcut reference](shortcuts.md) shows platform-specific commands.

## Restore and workspace switching

Restart restores sessions, visible assignments, journeys and Library context from local storage. Menus and previews do not reopen. Snapshots can lag by about half a second; Undo is memory-only. Browser sessions are tied to their origin and tab ownership.

Workspaces hold separate knowledge libraries; Connections select the owning computer/server. Desktop Workspaces and Connections/sharing controls manage these separately. Switching flushes settings, notes and recovery/layout first; active native/import work can block departure. Failed saves require the offered explicit draft/recovery decision. Never clear storage as a substitute for resolving a draft problem. [Recovery](recovery.md), [Transfers](transfers.md).

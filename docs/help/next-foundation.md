# Vaultor Next experimental foundation

Vaultor Next development builds use their own Windows profile. The planned production installer replaces the old Electron application and starts a fresh workspace. It removes the verified old managed workspace and settings once. External linked files and independent backups outside that storage are retained. Next can still open explicitly supported portable imports through Workspace transfers.

The installed Next application's **Settings → Application and Storage** offers **Check for updates**. Once a signed installer is verified, **Update and restart** protects pending edits and preserves the new workspace. Finish active transfers before installing.

## Workspaces

Only one Vaultor Next version can use the same local profile at a time. Before opening a new Next candidate, save any linked-file edits and close earlier Next versions such as M14 normally. If startup fails, a Windows dialog displays the error. Close the running version and try again; do not delete workspace or profile lock files.

The first launch creates a separate local Vaultor Next workspace. Open workspace accepts an empty folder or a supported experimental workspace. M1 and published Electron databases are not migrated; choose a new empty folder if an older workspace is refused. Unrelated nonempty folders and workspaces already open in another process are refused. Import and transfers also offers Create local workspace: choose a parent and a new folder name. Finish or cancel Activity tasks before switching. Linked folders are separate from this workspace.

## Desktop window and menus

Drag the caption space marked with a grip above the workspace to move the window. Double-click that space to maximize or restore. Buttons, journey controls and native minimize/maximize/close remain separate. In a narrow window, secondary caption actions move into the application menu. Menu labels and shortcuts occupy separate columns; use arrows, Home/End and Escape to navigate and return focus to the trigger.

## Library and note presentation

Library uses the original Vaultor resource-row and transforming-header presentation. Rows show type, collection/tag metadata, date and pin/actions. Scroll to compress the same search and paging controls into one line. The details button exposes page selection in compact mode; Escape clears selection after a contextual menu has closed. Quick Access contains collapsible Pinned and Recent sections; View all opens the complete browser. Sidebar options shows or hides these groups and restores their defaults. Each group filters supported resource types independently; Pinned also includes collections. Collection shortcuts open collections, never fake notes. Pinned resources and collections share the counted, paged Pinned browser. Explicit companion choices stay selected until Auto is enabled; changing the companion does not replace the full-workspace browser.

Collections, Tags and Linked Sources use the same transforming browse header. In Tags, New tag is in that header; a row opens its resources and its More button manages the tag. Collections offers All and Hierarchy; direct active-resource counts exclude Trash. All lists matching collections across their paths. Hierarchy shows roots and expanded descendants; its count reflects the visible matching rows. Scroll the collection list to compress the header and scroll back to expand it. Switching All/Hierarchy, searching or changing pages returns to the top; expanding a branch keeps your place. Short lists stay expanded when there is nothing to scroll. Use a collection row’s Pin button in either mode to add or remove its shortcut. Collection details expose the parent breadcrumb through the details control.

Browse pages, sidebar lists, Settings and dialogs scroll vertically within their own surface. Diagonal trackpad gestures should not shift the whole page sideways or scroll the workspace behind a dialog. Wide code blocks and tables retain horizontal scrolling inside the block. Long saved-resource titles in the command palette stay within the result row; hover to read the full title.

Managed and linked-note titles use the original scroll-driven note heading. Linked notes keep an always-available External source disclosure, explicit Save and source review controls. Organization can be expanded explicitly; save status, resource actions and Close remain available in the title band. This reconciliation does not change autosave, recovery or linked Markdown's explicit Save.

## Open Notes and journeys

Use available panes is the default opening policy for a workspace without a saved choice. Direct opens, including Open Notes and linked documents, use a free configured slot before replacing the selected pane. At capacity, the selected pane is reused and its displaced session remains in Open Notes. Reopening a visible note focuses its existing session and keeps its journey and reading position. Following a link or explicitly targeting a pane keeps that destination. The opening choice is saved with the workspace and survives restart. Existing saved Reuse selected pane choices are preserved; older values do not identify whether the choice was deliberate.

Open Notes retains sessions displaced from up to three visible panes. Reopening a current session preserves its journey. Use its actions to move it earlier/later, close it, close other notes or close all notes. Close pane removes its viewing area while retaining the session. Only assigned pane editors are mounted; narrow windows show the active pane and retain assigned peers without mounting additional editors for unused capacity. Drag an Arrange handle to reorder Open Notes, or onto a pane to swap viewing positions. The session menu offers Move earlier/later alternatives. Ctrl+Alt+PageUp/PageDown cycles view identities, including multiple views of the same note. Choose one, two or three panes in Workspace settings. Reducing capacity protects edits and keeps displaced sessions in Open Notes.

Resize either boundary by dragging, or Tab to its separator and use Left/Right (Home/End for its bounds). Escape cancels an active drag. Opening beside inserts after the active pane. Layout weights, active pane and independent journeys restore after restart. When the workspace is too narrow for all assigned panes, focus another view through Open Notes or the pane shortcuts; the application does not gain a horizontal scrollbar.

Following a managed resource link or linked Markdown relative link extends the active session's journey. Journey Back/Forward and the full journey menu revisit its steps; each visible pane has its own journey. Direct Library and shortcut opens retain independent sessions. Reading scroll and caret restore when revisiting or restarting; Undo is not persisted. Workspace Back/Forward remains available outside a journey. Navigation protects linked drafts without publishing external files; explicit Save is still required.

Pasting explicit Markdown or text with clear Markdown structure opens a conversion review. Insert, Paste as text, or Cancel. Rich HTML, spreadsheet cells and images use their existing paste handlers. Linked Markdown keeps its explicit Save and existing admission limits.

## Search and filtering

Search notes searches the Library or the selected collection's direct members. Search options switches between titles and titles plus saved content, and between newest-created, recently modified and title A–Z order. It also provides Refresh results.

Words match prefixes, ignoring case and accents. All words must match; punctuation separates words. There are no Boolean, wildcard or fuzzy operators. Queries allow up to 256 characters and 12 words. Only committed text is indexed; pending edits and protected drafts become searchable after saving. Existing M2/M3 notes are indexed automatically on opening the workspace.

Results update after a short typing pause and use pages of at most 100 summaries. Down from the search field focuses results; Enter on a result opens it in the existing pane. Ctrl+A in the field selects text. With list focus, Escape clears selection first, then search and filters. Escape in the editor returns focus to its row. Clear search and filters returns to the prior browse page in the same collection. Opening results keeps the query and result page.

If saved notes or memberships change while paging, refresh starts a new result page instead of silently skipping or repeating rows. No-results and query-error states keep open editors intact. Title search includes available linked Markdown filenames and indexed paths. Turn on saved content to include indexed linked Markdown text. Managed UTF-8 text, Markdown, CSV, JSON, XML and supported code-file formats can contribute body matches, subject to the 4 MiB input and 500,000 UTF-16-unit text limits. Text-bearing PDFs up to 20 MiB and 100 pages can contribute body matches through 500,000 UTF-16 units. Search opens the document-level result. Password-protected, image-only and unsupported PDFs can still have title matches. Saved Searches remain unavailable. Search outcomes show safe marked snippets and a linked hit's relative path. Best match gives exact and partial title matches priority. Search options also offers managed or linked ownership, up to 12 selected tags, and matches for all or any selected tags. Use **Inspect search coverage** for counts and **Rebuild managed file search** to update existing managed originals. The rebuild appears in Activity and can be cancelled.

In the command palette, **Resources · saved titles** also finds collection and tag names. Opening one takes you to its resource list. Open **Used in / links** from a resource's action menu to see the same saved relationships for managed and linked resources. **Linked from** and **Links to** report references in pages of 30. Expand a row to inspect occurrences, or choose **Explore links** to focus the related resource in the same dialog. Opening a managed occurrence selects it when its saved revision and target still match. A linked occurrence opens its source document.

## Saving and recovery

Edits are protected after about 250 ms without typing; continuous typing requests protection at least once per second. Disk/processing delays can extend that window. Autosave uses the workspace delay, from 0–1000 ms after typing stops; the default remains 1000 ms. A zero delay still journals before committing. Pending means the newest edit is not yet durable. Draft protected means SQLite has acknowledged it. Saved means the committed note contains it. Ctrl+S, navigation and normal closing flush pending work.

After unexpected termination, protected drafts appear in the sidebar footer’s Recovery menu. Open one to compare its text and title with the saved note. Restore draft resumes it. Discard draft and use saved explicitly removes the protected evidence. Keep draft for later closes its editor and retains the draft in Recovery. Unrecorded edits cannot survive a crash or power loss.

If another writer changes the saved revision, autosave refuses to overwrite it and opens the same comparison. Use draft over reviewed saved version is an explicit replacement of that reviewed revision; another concurrent change requires another review. Keep the draft for later if you need manual reconciliation. There is no automatic merge. Both panes stay consistent when a version is chosen.

A successful protected save removes only the matching draft, in the same transaction. Recovery holds at most 64 notes / 32 MiB per workspace; reaching the limit refuses new protection rather than evicting old drafts. Review or discard older drafts to free space. There is no timed deletion of unresolved evidence. Notes have an 8 MiB serialized size limit. This remains experimental software; keep independent copies of important information.

Use **Link external folder** and choose an ordinary local NTFS folder. Expand folders to browse Markdown and PDFs in pages of up to 100 entries. Row actions can open the original externally, reveal it in Explorer, or copy its path or resource link.

Registration queues a cancellable Activity task. Windows notifications normally refresh changed Markdown and PDF files automatically. Linked PDFs open in a read-only preview. Their text stays in the local search index and is unavailable to connected browser and Android clients. Folder changes or lost event details can trigger a larger Activity scan. Use **Refresh folders and search index** to verify the source or retry interrupted work. A refresh inspects up to 20,000 entries. Saved-content search includes supported UTF-8 Markdown text through 256 KiB per file, within a 16 MiB extracted-data budget per source. Larger supported Markdown can still appear by filename and path. Linked PDF extraction shares the managed PDF file, page and text limits and the source extraction budget. Activity reports discovery, indexed revisions and skipped files. **Search this source** scopes the existing search to one registration. Collection and tag filters apply to linked resources in the Library.

A refresh can retain the same resource after an in-root rename, case-only rename or move when NTFS identity matches. Memberships, tags, pins and resource links follow that identity. A replacement at the old path receives a separate identity. Missing documents stop appearing after a successful refresh. If a root moved, select the same physical folder with **Authorize folder again**. Removing registration withdraws indexed content and retains protected drafts and organization. It leaves every external file untouched.

Click a relative Markdown link or press Enter on a focused link to follow it. Shift opens beside. References with heading fragments can jump to the destination heading. Relative paths can include encoded names and parent folders within the originating registration. HTTP and HTTPS links use the system browser. **Links and backlinks** shows indexed relationships and counts for repeated relative references. Select a linked PNG, JPEG, GIF or WebP reference for an on-demand preview. A linked raster preview admits up to 2 MiB and 16 million pixels.

The external file remains authoritative. Editing protects a private draft after about 250 ms of quiet or one second of continuous typing, subject to the SQLite acknowledgment. Select **Save linked Markdown** or press Ctrl+S in that pane to publish deliberately. Navigation and normal close protect drafts. A no-op Save leaves bytes and timestamps unchanged.

Rich editing can admit supported UTF-8 Markdown through 1 MiB when it fits the shape and draft limits. Large documents may take longer to open and save. Shape limits include 2,000 table cells, bounded nesting and text runs, and a 2 MiB serialized draft. Supported content includes paragraphs, headings, basic inline formatting, links, lists, tasks, code blocks and simple unaligned tables. Save validates a source-range patch. BOM, line endings, frontmatter, reference definitions and unrelated ranges are retained where the edit passes validation. Unsupported or complex content uses a bounded read-only preview with **View source**. The reading limit is 1 MiB.

If the source changes, disappears or is replaced, Save refuses to overwrite it. Review compares protected content with the current source; keep the draft for manual reconciliation or explicitly discard it and reload. There is no force overwrite or automatic merge. After interruption, the footer Recovery menu offers Restore draft or explicit discard. Only acknowledged edits survive a crash.

Publication flushes a same-directory candidate and captures the original before a non-replacing rename. This is not atomic compare-and-swap: another program can occupy the brief path gap. It is left untouched, with original/candidate evidence and the draft retained. Review shows evidence paths. Verify Save outcome acknowledges only an exact original or candidate identity/hash; uncertain outcomes require manual attention and are never replayed. Do not remove evidence files while resolving an interrupted Save.

At most eight non-overlapping fixed local NTFS roots are supported. Junctions/reparse points, cloud placeholders, hardlinks, alternate streams/extended attributes and unsupported metadata are refused or read-only. Ordinary owner/group/DACL, creation time and attributes are checked and transferred; file identity and write time change on a real Save. Optional audit/exotic metadata and concurrent security administration are not qualified. SMB, removable/non-NTFS storage and other platforms are unsupported. Linked drafts have a separate 64-document / 32 MiB bound in the same workspace database; unresolved drafts are never evicted silently. Registration persists. Eligible open panes can restore by resource identity. The main Linked Sources browser restores saved expansion when workspace session restoration is enabled.

Use **Export selected resources** from a managed resource or page selection. Choose Markdown, plain text, Word, PDF, Markdown with assets, relationship data or imported originals. Export uses the committed document. A parked draft requires review first. Non-note files retain their bytes. The Markdown ZIP includes available managed attachments and images with relative links. Markdown writes tables with merged cells as HTML tables. Use a Markdown reader that supports HTML tables to see the spans. The relationship JSON contains selected nodes and saved outgoing edges. Word keeps the note title, heading levels, highlights, list markers, code whitespace, horizontal and vertical table spans, clickable HTTP/HTTPS links and available managed PNG/JPEG images within the export limits. Activity reports an image as a text label when it cannot be embedded. PDF lays out selectable text, headings, lists, inline formatting, web links, merged tables and managed images. Tables wider than eight columns use row records. GIF and WebP use the first frame. Word and PDF retain the labels of unavailable resource links. If a PDF glyph is unavailable, choose Word or Markdown to keep the full text. Linked Markdown has a separate **Export current Markdown files** action to copy the current authorized external bytes while keeping protected editor drafts separate.

The review accepts 20,000 entries at up to 32 folder levels, 1 GiB per file and 10 GiB total. It expires after 15 minutes. Export creates a new folder or file at the chosen destination.

## Portable workspace transfers

Choose **Export workspace** in Import and transfers or Workspace actions. For a smaller archive, use **Export selected archive** on managed resources or **Export collection archive** on a collection. Collection archives include its descendants. A selection includes referenced managed files. Whole workspace archives contain committed managed content, collections, memberships, tags, pins, lifecycle state, Review evidence and supported workspace settings. Selected archives include Reviews for the managed resources they contain. Markdown with assets includes scoped Review evidence in its own file. Resolve affected protected drafts before archiving. Whole archives also require review of uncertain linked publication evidence.

Vaultor Next `.vaultor` archives contain checksummed plaintext, including original managed bytes and inactive relative descriptors for linked Markdown and PDFs. External source contents, absolute source roots, source access grants, protected drafts, panes and Activity history stay outside the archive. Store the archive wherever you keep private local files. The same Restore and Merge pickers also accept compatible Electron workspace ZIP versions 1–8. Layout settings must fit the Next limits. ZIPs containing linked references or legacy Review evidence require the original app. The review shows the Electron version before you proceed.

**Restore archive as new** verifies the archive and shows what it contains. Choose a parent and a new folder name, then open the restored workspace from Activity. **Merge archive into current workspace** shows the same verification before you confirm. Merge adds records with new identities, remaps saved resource links, and preserves the destination's content and drafts. Matching tags with the same color are reused. Name collisions are given a suffix. Repeating the same archive returns the existing receipt. Restart Vaultor to retry cleanup of interrupted transfer staging after closing any program using those files. Activity retains cleanup errors. Inactive linked descriptors carry no access to their source. In **Workspace transfers → Locate archived linked references**, select references that share a source root, then choose that root. Vaultor checks every selected path and saved checksum before binding the group. A different revision or an existing local identity stops the group from binding. A match restores the reference ID and any included memberships, tags or pin without changing the external file.

After restoring, open the new workspace from Activity and check notes, collections and original files. Use the workspace selector to reopen your previous workspace. Remove an old workspace separately under your ownership and backup procedures. External linked originals belong to their source folders. Vaultor Next intentionally omits destructive in-place restoration.

If startup reports a missing or invalid workspace database, choose an existing verified workspace or restore a backup to a new folder. Use **Create local workspace** to start an empty workspace.

In managed or linked draft review, choose **Export protected draft** to write a JSON recovery copy. It contains the draft and its base revision. Linked copies include captured and draft Markdown. The export leaves the draft, saved version and external file in place.

## Experimental HTTPS hosting

Open **Settings → Hosting**, choose an address, then select **Start hosting**. Choose **This computer only** for local access or select a private IP address that your device can reach. Vaultor for Windows creates a host certificate on first use and renews the server certificate while sharing. Its CA fingerprint stays the same when you stop and start with a different address. For a private network firewall prompt, allow access only for the network and devices you intend to use.

Sharing starts off unless you turn on **Start hosting on launch**. For a listed private address, **Recover address changes** can follow a single new address on the selected network interface and subnet. If Vaultor cannot identify a suitable address, select the new address and start hosting again. **Stop hosting** also turns off start on launch.

Pairing requests appear in **Settings → Hosting**. Compare the pairing codes, approve the device, then grant access to the current workspace. You can withdraw that grant or revoke the device. A device can retain files it already received.

Stop hosting before switching workspaces. Closing to the tray keeps sharing running. Quit ends it.

### Connect Android on the same Wi-Fi

## Background Activity

Activity in the upper-right toolbar opens a compact anchored panel. The Windows taskbar shows measured progress when totals are comparable, or an indeterminate state otherwise. Windows can show a quiet notification for a long task or an operation requiring attention while the window is in the background. Tasks continue while it is closed. Queued/running tasks show actual processed items/bytes, or indeterminate progress when totals are unknown. Completion includes output paths and committed counts; expand Details for failed inputs or errors. Cancel task stops at safe boundaries. Committed import items remain; unpublished export/restore staging is cleaned up. Final verification/publication cannot be interrupted and is labelled accordingly.

Close hides the window when the Windows tray is available. Open Vaultor Next or Activity from the tray. Choose **Quit Vaultor Next** from the tray or Application menu to close the workspace after protecting edits and ending Activity safely. Linked files still require explicit Save.

The last64 summaries (up to30days) remain across navigation and ordinary restart. Interrupted tasks appear in Activity and require you to select the source again. Import reuses matching entries that already committed. Startup only retries cleanup of managed originals recorded in the workspace journal. A forced process termination can leave uniquely named staging files. Activity identifies completed outputs.

## Trash and permanent deletion

Resource actions → Move to Trash asks for confirmation and saves/protects current editing first. Unresolved managed recovery drafts refuse lifecycle changes. Trash keeps identity, content, tags, pin state and collection memberships; normal Library, tag, pin and search views exclude it. Trash uses the same100-row pages and page-scoped selection. Row activation selects there; contextual Restore returns the selected resources to active browsing. Surviving renamed collections retain their identities. Deleted collections are not recreated; resources remain accessible through Library.

Permanently delete operates only on Trash and asks for confirmation. Empty Trash is one action across all Trash pages, regardless of the current search/page. Activity reports processed resources and protected/failed inputs; eligible resources commit independently and cancellation can leave partial completion. Deletion cannot be undone. Protected drafts are never bypassed.

Metadata removal and managed-file removal are separate durable steps. A committed cleanup receipt retains the exact owned UUID file obligation until removal succeeds. Startup and Empty Trash retry those receipts; failures remain visible in Activity. External linked originals are never candidates. No recursive cleanup of unknown directories or external export stages is performed.

## Deleting a collection hierarchy

Collection actions → Delete hierarchy removes its nested collections while keeping every resource in Library by default. The explicit Trash-exclusive option reviews the hierarchy count and exclusive resource count; resources with another membership outside the hierarchy stay active. A changed review is refused and must be reopened. Collection hierarchy restoration is not implemented. Removing linked-source registration continues to keep its external files.

Settings actions offers confirmed resets for appearance, sidebar, workspace behavior, keyboard or all preferences; resets leave documents and drafts unchanged. Settings remains floating over mounted editors. Appearance includes Density, all eight accent colors and a manually triggered motion preview.

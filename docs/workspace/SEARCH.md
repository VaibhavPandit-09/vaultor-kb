# Saved-resource search and Ctrl+K

## Palette

Ctrl+K opens search. Empty input groups deduplicated Open, Pinned and Recent items. Typing searches resource titles only by default, with collection-name matches grouped separately in global title mode. Search options offers Include saved content and a searchable collection selector. Ctrl+K resets to Titles only / Entire workspace on each opening. Title mode shows type metadata; content mode additionally shows safe note/file excerpts. Enter opens the highlighted result; Arrow keys change the highlight, Tab focuses the highlighted resource’s Actions button, Enter/Space opens it, and Shift+Tab returns to input using native tab order. Escape returns one step before closing and restores the parent result identity/query. Highlighting a file never opens a preview.

The Actions button names its highlighted resource. It fetches fresh metadata before offering collections, pins, tags, applicable rename/export, explicit file preview/download and Move to Trash confirmation. Commands or a leading > switches modes. Commands include the existing note/upload/settings/navigation actions plus Library, collections, organization, pins, exports and Diagnostics. Targeted commands capture the focused resource or explicit Library selection when the palette opens; hidden notes are not implicit targets. Step titles, Back and target labels remain visible. Failures retain input and prevent duplicate in-flight execution. IME confirmation does not execute a result. Organization handoffs restore the captured workspace focus on dismissal. Organization/export/Trash may deliberately hand off to their existing dialogs.

Opening an existing note uses the existing pane and save coordinator, retaining its draft. Search reflects saved titles and, only when enabled, saved content. Content mode labels saved-only behavior and explicitly warns when drafts are pending. New-note creation uses the retry-safe import contract and retains the same UUID across retry within a palette session. Closing/replacing a pane still passes through the save barrier.

Search is debounced 150 ms. The palette displays at most 50 resource and 20 collection matches, with a refinement/Library hint for more. Empty state fetches up to 30 mixed pins and shows up to 20 recent resources after deduplication. Library provides full pagination. Collection names use the collection service; supported saved PDF/text bodies are searched only in content mode. Collection-scoped mode returns member resources even when the input is empty, excluding global Open/Pinned items and collection-name result groups. Scope changes preserve query text and abort/disregard old requests; failures never broaden the scope.

## Search contract and ranking

GET /api/resources/query accepts q (required, up to 500 characters/30 terms), page (zero-based), size (1–100, default 50), type, repeated tag names (all required), collection ID and favorites. Unicode letters/numbers/underscore become literal prefix terms joined with AND. Punctuation does not expose FTS operators; an input without terms returns no matches. Matching is accent/case insensitive using SQLite unicode61. This is token-prefix search, not arbitrary substring matching.

Results are {items:[{resource,snippet}],page,size,totalItems,totalPages}. Resource is the existing metadata summary, enriched with tags/collections in batches without hydrating note bodies. Ranking uses BM25 with title weight 10 and body weight 1, then lowercase title and ID. Snippet text is bounded to 600 UTF-16 units with half-open {start,end} highlight offsets; clients render text and mark elements, never HTML. File/title-only matches may have no highlighted body excerpt.

Library uses FTS only for nonempty queries with Include saved content enabled. Titles-only is the initial default; mode is retained while the mounted Library is used. The collection Add resource picker deliberately uses metadata title search to find existing resources and offer note creation. Library disables its ordinary sort only during content/relevance search. Title mode uses the existing literal substring metadata query and the selected browsing sort; palette title matches sort by title then stable ID. Search options changes Library collection destination and breadcrumb, retaining the typed query. Empty-query browsing retains the existing recent/updated/title sorts. The frontend SearchMode type (title | content) is part of the retained query key and is stripped before the HTTP request. Collection/tag/type/pin filters pass through either path; changing mode resets Library pagination and selection. GET /api/resources and legacy /api/resources/search retain their documented title-substring contracts for other callers. GET /api/resources/{id}/summary supplies fresh metadata for palette actions.

## Derived index and diagnostics

ResourceSearchService owns resource_fts, an FTS5 table containing resource ID, title and derived body. Recursive traversal follows document content arrays in order and extracts text nodes, resourceLink labels and managed-image captions/alternative text. Headings, lists, code and table cells are included through that traversal. Arbitrary attributes, resource IDs, raw JSON and arbitrary binary contents are excluded; supported file text is extracted separately under the limits below.

SQLite insert/update/delete triggers maintain the index in the same resource transaction, including rename/edit, file-to-note import, link replacement and archive merge/replace. A rollback rolls back index changes. The index is disposable derived data and is not exported in logical workspace archives.

Hibernate first inspects mapped tables individually (jdbc_metadata_extraction_strategy=individually), avoiding untyped FTS5/shadow-column metadata during schema update. This setting prevents a restart-only startup failure; do not replace it with grouped inspection. Startup rebuilds asynchronously. GET /api/diagnostics/search returns rebuilding, processed, resources, indexed, invalidDocuments, complete, failure and originating requestId. POST /api/diagnostics/search/rebuild starts a single worker or returns the current run; poll status for completion. Diagnostics exposes status, refresh and rebuild controls and includes status in downloaded reports.

Rebuild clears the index then rebuilds batches of 100 IDs, taking the shared workspace mutation gate exclusively per batch and committing each batch transactionally. Normal mutations resume between batches and triggers cover changes concurrent with the rebuild. Resource operations may briefly return WORKSPACE_BUSY (409); search returns 503 during rebuild/failure. Failure is visible with correlated backend logs; restart starts rebuilding again. Invalid stored note JSON yields an empty body and incomplete coverage in status. Correct source data before expecting complete coverage. This gate is process-local: use one backend per database.

## Validation and limits

Focused tests cover palette deduplication, normal Tab, explicit targeting, safe snippets, Escape, failed rename/retry; service tests cover ranking/prefix/literal input, attribute exclusion, filters, CRUD/import/rollback, rebuild with concurrent mutation and archive search after merge/replace/rollback. The isolated palette fixture was visually checked in light/dark themes, including highlighted snippets and selected-result contrast. It was removed afterward. This is not a full integrated Dashboard or assistive-technology pass. No routine live API smoke or Docker verification was performed.

OCR, office-document extractors, fuzzy matching, synonym expansion and full scale integration remain future work. Rebuilding temporarily makes full-text search unavailable; ordinary browsing remains usable between gated batches. Palette and shared dialogs do not yet implement a complete focus trap.

## Shared type presentation (0.3.1)

Ctrl+K, pickers and browsing use the same resource-kind labels/icons. Files show concise format metadata where known; unknown types retain a neutral icon and refuse unsupported opening rather than becoming file previews. Library uses a single searchable Type filter alongside search; changing it preserves query/mode/scope while resetting the page and bulk selection. Mixed browsing remains bounded at 100; title-first/content-opt-in search semantics and saved-only draft behavior are unchanged.

## Lifecycle exclusion — 0.5.0

Title browsing, Ctrl+K and saved-content search exclude trashed resources on the server. FTS rows remain derived data, but queries join active originals; restore makes them searchable again transactionally. Collections themselves can remain empty. Actions hand off to revision-checked Trash; the old combined reference-rewrite/delete flow is retired. See [RESOURCE-LIFECYCLE.md](RESOURCE-LIFECYCLE.md).

## File-category isolation — 0.6.0

Title and saved-note-content services accept category=image|pdf|audio|video|text|other, intersecting existing type/collection/tag/pin filters before totals and paging and echoing appliedCategory. File bodies are included only in explicit content mode on a 0.7.0 host, under the extraction/coverage limits below. The shared registry identifies image/PDF/etc. consistently in palette/pickers/inline links without changing domain kinds. Category filtering cannot silently fall back on an older host; update that host. See [REFERENCES.md](REFERENCES.md).

## Saved file text — 0.7.0

Content mode now searches titles, saved notes, text-bearing PDFs and UTF-8 text files (text/Markdown/CSV/JSON/XML/code MIME categories). Titles only remains the default. Queries preserve collection/tag/type/category/pin scope. SearchPage.fileCoverage counts active files within those filters, independently of matching terms, so pending/limited extraction cannot be mistaken for complete no-match coverage. Snippets remain bounded plain text/highlight ranges; no executable HTML. PDF opening uses the ordinary preview; no page-location promise is made.

The pinned Apache PDFBox 3.0.8 dependency is Apache-2.0 and stays compatible with the existing PDF export stack. [Official releases](https://pdfbox.apache.org/download.html) and [security guidance](https://pdfbox.apache.org/security.html) inform the process limits. No OCR, remote URL fetch, attachments, JavaScript, macros or external code execution. PDF extraction refuses encryption/restricted permissions. Image-only PDFs report no-text. Unsupported formats remain title-searchable. UTF-8 is strict; binary/NUL or invalid encoding is rejected.

Exact limits: PDF 20 MiB and 100 pages; text 4 MiB; maximum 500,000 UTF-16 output units per file. A single subprocess inherits only minimal OS/temp/locale environment (no host credentials) and uses the bundled Java, a 128 MiB heap/96 MiB metaspace cap and 15-second timeout, then is terminated. These are not a total process RSS guarantee or OS security sandbox. One file runs at a time; no SQLite connection/admission lock is held during copying/decoding. Static text is extracted without rendering images. Originals are copied privately, hashed and left unchanged. Scratch copies/results live in a private .file-search-scratch directory under storage, are deleted after work, and known stale scratch files are removed on startup.

file_search is disposable derived SQLite data (ID, version, generation, state, bounded text/hash/detail); it is excluded from logical archives. Resource-version or workspace-generation changes synchronously invalidate old derived bodies, and commit validates both before updating FTS. Rename/organization may requeue extraction because optimistic revision changes. Trash/purge cannot resurrect matches; Restore and archive merge/replace requeue current originals. Startup reuses valid cached text and resumes interrupted indexing; explicit full Rebuild clears derived bodies. Only one host process may own the database. Unsupported source-byte edits made directly outside Vaultor are not automatically detected; use rebuild.

Diagnostics status includes files coverage; GET /api/diagnostics/search/files pages 1–100 entries (default30), exposing title/state/detail without paths or bodies. States: queued, indexing, indexed, unsupported, limit-exceeded, encrypted, invalid, no-text, failed. POST /api/diagnostics/search/files/retry retries unavailable entries, or id reindexes a chosen file. Diagnostics provides Inspect file coverage and Retry unavailable files. Full POST /diagnostics/search/rebuild rebuilds note/title FTS and requeues file text; title browsing remains separate. Storage/parse failures retain originals and visible status. Pending results have Refresh results; no background worker edits mounted documents/drafts.

API/minimum client 3 and archive 3 are unchanged. Use host/client 0.7.0 for these semantics and coverage. Older protocol-3 hosts produce an explicit unavailable-coverage message; their file title matches are not certified as file-body search.

# Library and resource browsing

This guide describes desktop/browser controls. Current Android implements title-first mixed browsing with native paged destinations, type/scope controls and a retained immutable reader; original organization/lifecycle writes are retired. [ANDROID.md](../android/ANDROID.md) owns its interaction, cache/session bounds and validation.

The Library is the main browsing surface. Library, Recent, collection contents, Collections and Pinned share compact headings, title search, content-sized mixed lists and row spacing. Main sidebar destinations remain available independently of quick-access sections. New note is a primary split button: its adjacent creation dropdown offers New collection; Import is one secondary entry point for file/folder browsing and native drops; [IMPORTS.md](IMPORTS.md) owns acquisition and Activity.

Pinned and Recent each show one mixed list of up to 12 shortcuts: pins alphabetically across resources/collections, Recent by last-opened time across resource types. Type icons remain visible without repeated category headings. Each section has an on-demand searchable Type filter; All is the default. Pinned includes Collections as organizational shortcuts, while Recent includes resource types only. Pinned, Recent and Tags retain accessible disclosure headers and separate View all. Sidebar options → Customize sidebar controls hiding and Restore defaults. Device settings retain visibility/collapse/type, outside portable archives; old settings default to visible/expanded/All. Hidden/collapsed sections retain cached rows and suspend queries. Reopening refreshes without discarding matching rows. Recency/navigation are independent. Hidden Tags never clears active filters. The connected host must be 0.3.1+ to persist type choices and apply basic pin filters; 0.6.0 adds Images/PDFs/Audio/Video/Text/Other file categories and acknowledged category paging.

## Linked documents

The Windows Linked sources tree follows the external hierarchy; ordinary collections remain Vaultor organization. Linked resources can have multiple memberships, tags and pins without copying or moving their file. [Linked external folders](LINKED-SOURCES.md) owns access, editing, recovery and portability.

## Behavior

Page headings keep the title at the left and actions at the same right edge as search and results. Long titles and action groups wrap rather than overlap. Desktop window controls occupy only the top edge; page actions below them use the full content width. New collection has a small plus icon; collection rows share padded icon/title/pin alignment. Empty Library and Recent explain how to populate them; a collection search with no matches is distinct from having no collections.

First use opens Library; subsequent startup restores the last Library or note workspace from the local session. Library destination, collection, query, mode, tags, type and sort are restored; page/bulk selection and dialogs start fresh. See [SESSIONS.md](SESSIONS.md). Opening a note returns to the note workspace; opening a file shows its preview. Return to notes restores the active pane. Switching to Library hides, rather than unmounts, open editors: documents, selections and pending saves remain owned by the existing editor/save coordinator. Hidden editors do not receive active-editor focus or the close-note shortcut. Library titles represent saved metadata; unsaved drafts stay in their note panes.

Search defaults to resource titles only. Search options enables Include saved content and chooses Entire workspace or a searchable collection scope. Content mode uses FTS5 snippets/relevance and disables ordinary sorting; title mode keeps the selected sort. Pending drafts are excluded from saved-text search and explicitly labeled. Scope changes update the destination/breadcrumb while retaining query text. See [SEARCH.md](SEARCH.md) for prefix terms, ranking, diagnostics and limits. Collection membership, type, all-selected-tag names, favorites and sorting are evaluated by the server. Recent sorts by last-opened time (new resources also initialize this timestamp); other sorts are recently updated and title A–Z. One searchable Type filter isolates resources; no permanent type tabs or duplicate selector remain. Search options contains content/scope/sort. Active criteria remain visible, and empty filtered results offer Clear type filter. Resource checkboxes and modifier-clicks enter selection; scoped Select All/Select page and bulk controls cover the loaded page. Resource counts reflect all matching results. Changing criteria resets pagination. Empty, pending, failure/retry and pin-update failure states are explicit.

Library, Recent, collection contents and Pinned use one bounded server page of 100 matching items, for All and filtered views. Pagination is shown only when needed. Queries fetch metadata, never note bodies or all workspace rows. Mixed resource queries preserve the server sorting and true matching totals. Pinned uses /organization/pins with optional kind/category and appliedKind/appliedCategory acknowledgment; older hosts that cannot confirm a filter show an update message rather than silently broaden the results. Resource pin summaries batch-enrich tags, collections and file metadata. Collections remains a directory of organizational destinations with the same row spacing. Borders end at the last row, and each page has one scroll container. Bulk selection covers only the visible resource page, excludes collections, and clears when criteria/page changes.

All resource/pin views and the Collections directory use bounded server pages of 100. Pagination appears beside results only when multiple pages exist (or to recover an out-of-range page). Rows use normal document flow within one page scroll container; the former fixed virtual viewport and filler panels are removed. List borders end after the last row. Long titles ellipsize in rows; headers wrap within their available width and native controls keep their separate top clearance. Empty collections prompt Add resource; empty Library/Recent/Pinned and unsuccessful searches have distinct compact messages.

Responses are cancelled or ignored when superseded; hidden views stop requests. Same-query refreshes retain rows and local retry feedback; initial loads/changed criteria show loading. Workspace replacement clears caches, including hidden views. Pagination is deterministic by ID tie-breaker but not a snapshot; concurrent changes can move items between pages. No browsing query hydrates note bodies or enumerates the workspace.

Pins persist in the existing favorite fields in the database and do not change modified timestamps. Current full workspace ZIPs (organization/lifecycle sections introduced before/at3) preserve resource favorites, collections, collection favorites and memberships. See the organization rules below. Resource bodies and binary paths are absent from browsing responses. Opening a resource retrieves its full detail independently of sidebar contents. The palette searches titles by default, with explicit saved-note-text opt-in and collection/global scope, using bounded results and directs users to refine searches exceeding 50 matches. Link/replacement pickers retain bounded title search.

## Resource lifecycle

Actions menus are shared across browsing, sidebar shortcuts, note panes and previews, including Open in another pane for notes/linked documents, Rename, organization, pins, Copy title through the platform clipboard, applicable exports/downloads and Move to Trash. Right-click or ContextMenu/Shift+F10 invokes the same actions as ellipsis without primary activation; editable text keeps native context behavior. Collections/hierarchy, pinned collections, Trash, Open Notes, tags, linked source management and browse backgrounds expose their applicable existing commands. Menus remain viewport-clamped and keyboard navigable with source focus restoration. Selected-row context invocation uses applicable shared bulk commands; outside the selection it targets the clicked resource. In collection contents, Remove from [name] changes only that named membership through the shared atomic helper. Bulk Trash retains failed targets; closing a collection does not delete resources. Trash is a separate sidebar destination with bounded metadata pages and Restore/Delete permanently. Ordinary browsing/search/pins/counts exclude Trash while original bytes, IDs, favorites and surviving organization are retained. See [RESOURCE-LIFECYCLE.md](RESOURCE-LIFECYCLE.md) for draft safeguards, confirmations, cleanup, portable lifecycle state and protocol3.

## Collections, tags and bulk organization

### Desktop selection and drag organization

Library, Recent, collection contents, full Pinned resource entries and Trash use one loaded-page resource selection controller (maximum100). Checkboxes or Ctrl/Cmd-click toggle; Shift-click replaces with a displayed-order range, Ctrl/Cmd+Shift-click adds that range. Ctrl/Cmd+A selects the loaded resource page when focus belongs to it; search/editor inputs and portaled controls retain their own text behavior. Escape clears selection after higher-priority overlays close. Ordinary resource title clicks still open; Trash titles select because trashed resources cannot open. Collections and compact sidebar/Open Notes/source-tree shortcuts keep direct navigation. Secondary linked-folder search results and supported source-tree leaves now support single-resource dragging, with lazy metadata resolution preserving the external document identity. No workspace-wide selection or session-persisted selection is implied.

Criteria/page changes and hiding a list clear its selection; same-page refresh/deletion prune missing IDs and preserve survivors. Ranges use current visible order, with stale anchors safely replaced. Selected fill/accent, hover, keyboard focus outline and opened-resource marker are distinct. The compact selected count and Export/Organize/Clear controls use existing browse compression. Selected-row right-click menus use that selection; an unselected clicked resource keeps single-target actions.

Organize selection offers collection/tag changes, pin/unpin and protected Trash. In a collection, Remove from this collection removes only that membership. Collection/tag membership changes use the existing atomic endpoint: a missing, trashed or unauthorized target fails the batch without silently applying to survivors. Other memberships remain intact. Pin changes use the shared favorite command per resource, retaining individual failures and removing only completed IDs from the current selection; newer selections are not overwritten. Dialogs freeze their target IDs. Trash/Restore keep their existing review, save/recovery, revision and partial-result behavior. Cleanup-pending items remain unavailable for Restore. Commands capture connection epoch and workspace generation; delayed work cannot retarget another source.

Drag resource titles to organize/link them; a selected row snapshots its selection, otherwise only the dragged resource participates. The same identity from Library, Recent, Pinned, collection contents, search, sidebar shortcuts or Open Notes has the same destinations. Collections ADD membership; tags apply metadata; Pinned pins; Trash uses protected review. Collection sources reparent through host hierarchy checks. Linked references organize metadata without moving originals. Recent stays chronological, and all loaded resource lists freeze for the gesture so reveal-driven recency updates cannot move its source; chronological refresh resumes afterward. Sidebar session rows/counts and linked directory pages also remain stable for the gesture, including while a new note opens.

Every eligible managed note row can reveal its editor after a stable900ms/6px hover. Normal pane navigation reuses a visible note, activates an inactive session, or opens an unopened note using current capacity and Save/recovery safeguards. The navigation lease is checked after load/Save; cancellation or moving away cannot commit a late switch. Failed Save keeps the original pane. Source rows remain mounted and unpainted at full size when the workspace is revealed. Dropping on a row inserts nothing: continue into the editor, choose the caret position, and drop through the existing mapped resourceLink transaction, ordinary Undo/Redo and autosave. Linked/read-only/unsupported/trashed targets preserve their actual restrictions. No second opener or importer exists.

Hold over Collections navigation to discover destinations within the existing sidebar navigation rectangle. Current parent, Back, child branches and paging remain in that allocation without shifting resource rows or opening a floating menu. Browsing a branch is separate from admitting a final membership/move. Sidebar disclosure expands temporarily for the gesture without saving preferences; the existing scroll owners handle edge scrolling, including gaps. One inline contextual message replaces the Review inbox row while dragging. Preview, highlight, reveal state, insertion caret, operation status and error are separate: no competing pseudo-tooltips or native title hints remain. Escape, drop/end, blur and source changes clear the ticket, lease, hints, caret, discovery and scroll. Routine success expires after3seconds with shared notice exit motion; errors remain dismissible/actionable. Reduced motion retains the same immediate endpoints.

Open Notes titles are ordinary resource sources. Explicit grips and existing earlier/later menu actions reorder sessions; pane grips also arrange panes with mounted editor/history/draft continuity and configured capacity checks. Resource-title drops on pane chrome use normal opening, consistently across sources. Alt+Shift+Left/Right on a grip arranges visible panes. Normal navigation, collection/tag pickers and editor resource-link commands remain keyboard alternatives.

External files/folders onto a collection preserve its destination through native acquisition/review/Activity. One non-image file into a managed editable note uses existing retry-safe foreground inline review and inserts only after success. Cancel/failure creates no dangling link. Folder/multi-file inline insertion and native drag-out remain deferred; import normally then link resources. Existing editor text/image acquisition stays unchanged; browser folder drops refuse flattening. [The tracker](../plans/DESKTOP-EXPERIENCE-TRACKER.md) owns exact validation/platform/deferred status.

Collections are hierarchical topic/project groups, bounded to 32 levels. A resource can belong to several collections, including a parent and its descendants; membership always refers to one underlying resource. Names trim surrounding whitespace, contain 1–100 characters without control characters, and must be unique ignoring case among siblings. Identical names in different branches are allowed. Tags remain independent and normalize to lowercase. Collection paths are derived presentation, never identity.

Open **Collections** in the sidebar to browse topics, search, pin, or create a collection. Its header offers Path, Pin, Add resource and More. More holds rename/delete, organization management and refresh. Resource counts describe the current result set. Ancestor breadcrumbs return to Library or any parent. Collections defaults to All: one metadata-only, alphabetically paged entry per collection at any depth, with its parent path as secondary context. All / Hierarchy shares the same directory, search, identities, pins and row management. Hierarchy starts at roots and loads child pages on demand; indentation stops growing after four levels. Search spans all branches in either mode and presents independent matching entries with their paths, rather than filtering away a matching descendant beneath a non-matching parent. Counts distinguish all matches from root collections. The selected mode is local.collectionView (all/hierarchy), scoped to the device in the selected workspace, persisted through the shared optimistic settings queue; older/absent values default to All. A 0.18.1 host is needed to retain this new preference. Up/Down/Home/End move between loaded row buttons; Right expands or enters children and Left collapses or returns to the parent. Tab still reaches pins and row management, while menus retain shared Escape/focus handling. A selected collection shows a labeled Child collections group above direct resource memberships, with the same pins, contextual creation and management actions as the directory, without implicit descendant aggregation. More → New subcollection creates inside the current collection. Rename / move / delete offers a paged destination search; Move preserves the entire subtree and rejects descendants and sibling conflicts. Management keeps rename and confirmed deletion secondary. One shared deletion dialog covers the directory, row actions, selected detail and collection/tag manager. It counts the complete subtree (root included), distinct managed resources, shared originals and linked references from the database. **Delete collections only** is selected initially: all underlying originals keep their contents, independent tags/pins, outside memberships and existing active/Trash state. **Delete collections and move exclusive resources to Trash** requires explicit selection; only active managed notes/files with no membership outside the subtree enter existing resource Trash. Multiple memberships inside the subtree count as one original. Linked references lose memberships only; linked sources, physical files and private recovery evidence remain independent. Deleted collections and their pins are removed, not restored by resource Trash. Saved-reference impact is shown concisely for surviving source notes. After success the selected subtree navigates to its nearest surviving parent or Collections, with unrelated Library criteria and mounted editors retained. [RESOURCE-LIFECYCLE.md](RESOURCE-LIFECYCLE.md) owns draft, transaction and retry safeguards. Create/import actions inside Add resource capture the visible collection and assign it automatically. File-import review names the captured destination and applies it to every successful row; a failed row retains its original ID and destination for retry. Ordinary note/slash imports do not inherit a hidden collection. Tags and the secondary Collections & tags manager remain available in Library. Rename collisions fail visibly instead of merging.

Use row checkboxes or **Select visible resources**, then **Add to collection** to open the same membership picker used by individual Library row Actions menus, note headers and file previews. It searches collections, shows selected memberships first, and displays mixed bulk membership as “some”. Each checkbox immediately adds/removes only that collection, with independent pending, rollback and retry; the picker stays open for more changes. Inline **Create “name” and add** creates and assigns atomically. One request applies to at most 100 current-page resources; changing page or criteria clears selection. Tags / manage retains the tag bulk workflow. Add resource in a collection searches titles and immediately adds a clicked/highlighted result, without replacing other memberships. Bulk Move to Trash is available; permanent deletion is confined to Trash.

Note titles and file-preview headers show two collection chips, then +N; expanding reveals the other memberships. Clicking a chip opens that collection. Add to collection remains visible even with no memberships. Pin/Unpin is available on notes, previews, collection headers and Library rows. Membership/pin changes do not flush, replace, or modify note drafts.

Organization writes publish typed organization changes, while pin updates publish pin changes. Only affected query scopes refresh. Tag changes refresh affected open-note metadata while preserving the save coordinator’s latest document/title. Organization browsing uses abortable queries and retains existing rows on background failures. The existing sidebar tag chips and note tag pickers still load the tag list; replacing those with fully server-paged pickers remains scale work, while the management dialog is paginated.

### Persistence and transfer

The collections table has UUID id, nullable parent_id, display name, unique internal sibling-name key normalized_name, favorite flag and internal creation_fingerprint. resource_collections is a many-to-many join owned by Resource, so resource deletion removes its memberships. OrganizationService uses metadata-only SQL for counts, paging and membership updates, avoiding document hydration. Creation with PUT /collections/creations/{UUID} validates initial members and stores a fingerprint in the same transaction. Identical retries return the collection without reapplying memberships; changed requests conflict. Existing flat SQLite tables gain nullable parent_id through the existing Hibernate schema update, preserving IDs, names, favorites, fingerprints and joins. Root name keys remain unchanged; child keys include the parent ID, so the original SQLite unique constraint also enforces sibling uniqueness. Moves update only parent/key, not descendants or resource documents. Fingerprints are not portable archive data. Optional collectionId on note creation/import commits initial membership with the resource; import fingerprints include the destination. Bulk changes validate all IDs, then commit atomically; repeated add/remove calls are idempotent. Tag renaming preserves its ID, color and membership. Tag deletion now removes join rows directly rather than loading all resource documents.

Workspace ZIP organization contains collections ({id,name,parentId,favorite,resources:[resource IDs]}) and favorites ([resource IDs]). Hierarchy-bearing full archives use version 7 and partial packages version 8; flat exports retain versions 5/6. Old hosts reject 7/8. The workspace.json checksum covers this section. Parent references, cycles, sibling duplicates and depth are validated before mutation; parent-first restoration accepts any input ordering. Partial exports include all required ancestor collection nodes. Preview validates collection identities, normalized names and membership/favorite references before mutation, and reports organization counts in review information.

Replace restores collection/resource favorites and memberships, retaining archived collection IDs. Merge allocates new resource IDs, rewrites memberships, unifies collections by normalized name under the already remapped parent and preserves existing collection favorites; newly created collections keep their imported favorite state. Imported resource favorites apply only to the newly created resources. Metadata, membership and favorite restoration share the existing import transaction and rollback/recovery boundary. Version 1 plain archives remain readable without organization; replacing with one yields no collections or favorites.

## Navigation refresh behavior — Sprint U1

resourceEvents.ts defines one typed notification contract with opened, metadata, organization, pins and workspace categories. An opened notification invalidates only Recent requests; it never reloads favorites, collection shortcuts or tags. Metadata changes refresh resource summaries; create/import/delete also signal changed membership counts. Tag/collection organization changes identify their scope; resource and collection pin changes use separate targets. Workspace replacement invalidates every cache.

RecencyRecorder groups rapid activations over 300 ms and records only the final resource in each burst. This deliberately omits intermediate keyboard-switch visits from recency writes. Requests are serialized and consecutive activations of the same resource are deduplicated. The active highlight/focus changes immediately; saving and navigation never await the recorder. Once the final write settles, Recent reconciles after 150 ms. Starting another activation aborts/invalidates old list reads immediately. Recorder reset cancels pending work on unmount or workspace replacement.

Recent keeps its existing rows/order while switching, then updates keyed rows in place; the sidebar scroll region disables automatic scroll anchoring. useRetainedQuery keeps same-query data through pending/failed refreshes and exposes a separate refreshing state. Initial loads still show placeholders; changed criteria never show the previous query as matching results. Retry controls stay beside the retained list. Background API failures still log locally/to diagnostics with request IDs but do not trigger the global error banner. Failed recency writes expose Retry in Recent and do not affect drafts or saves.

POST /api/resources/{id}/open performs a metadata-only last_opened_at update. It does not modify title, content, updatedAt, tags, collections or favorites.

## Add resource to a collection

Use Add resource to find existing notes/files by title. Click a result or select with arrows and press Enter to add immediately; the picker stays open. Added resources are marked and cannot be added twice. Each mutation has its own pending/error/retry state. Existing membership APIs preserve other collections.

For a nonempty title without an exact note match, Create note creates and opens a note in this collection. More → Create new note explicitly permits duplicate titles (or Untitled Note for empty input). A stable UUID and collectionId are sent through the existing multipart import API; retrying a lost response/open failure reuses that identity. A new title is a new creation intent. Exact-note checks cover all matching pages, requesting metadata in batches of 200; broad searches can require multiple requests, aborted when criteria change. Visible mixed results are paginated at 30.

Import files closes the picker before invoking the existing native file picker and review flow; the collection destination remains captured. Empty collections show an add-resource prompt; unmatched searches retain their distinct no-results state. Search options/More use shared positioning/Escape behavior, outside dismissal and trigger focus restoration.

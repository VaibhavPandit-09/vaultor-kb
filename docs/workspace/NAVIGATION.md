# Open Notes, viewing panes and reading journeys

Reviewed 2026-10-24 for desktop/browser 0.18.2. [SESSIONS.md](SESSIONS.md) owns persistence and protected recovery; [RESOURCE-LIFECYCLE.md](RESOURCE-LIFECYCLE.md) owns Trash/Restore/purge. Android navigation is unchanged.

## State and ownership

`PaneNavigation` owns an ordered `sessions` collection, visible `panes` assignments, focused session, per-visit positions, request tokens and retry state. Each session owns its current resource, journey/cursor and selection. The legacy `paneId` field is retained as the stable **session** ID for migration and editor routing. A visible assignment adds a separate stable `slotId`: switching sessions reuses that viewing surface; closing a pane preserves neighboring slot/editor identity. Dashboard mounts editors only for visible assignments (including responsive compact peers), never for the whole session collection. Clean inactive document bodies are evicted from its cache; metadata, visits and reading positions remain lightweight.

Session order is stable opening order, without rows moving beneath a pointer on selection. New sessions append. When an active session is removed, the last opened inactive surviving session fills that slot; otherwise the rightmost surviving pane gains focus. Closing an inactive session leaves visible assignments unchanged. Closing a pane removes only its assignment, retaining every session and its journey. Closing the last pane leaves the session list available; selecting a session creates the viewing area again. Closing all sessions leaves the compact empty workspace.

## Direct opening, switching and splitting

Library, Search/Ctrl+K, pins, Recent, creation/imports, references and Open Notes use the same opening coordinator. Ordinary direct opening defaults to **Fill available panes, then replace**. It adds a pane while below both the configured maximum and the existing side-by-side capacity (workspace width >1200px: three, >850px: two, otherwise one). At capacity it reuses the focused viewing slot, saving the departing note first. **Always reuse focused pane** skips automatic filling. Placement is rechecked after asynchronous loading and save barriers. The displaced session remains in Open Notes. Five, seven or more sessions do not consume extra panes. An already open current destination focuses its existing session without resetting its journey, cursor or caret; if already visible, focus moves to that pane. There is no ordinary pane-capacity prompt.

Open Notes lives in the existing sidebar's shared secondary scroll area. Rows identify active state and visible pane number, offer Close, and have a contextual Close other notes action. The section menu offers Close all notes. At more than five sessions a title filter appears; an active filter stays editable as the collection shrinks. Menus retain centralized Escape/portal/focus handling; native buttons support Tab, Enter and Space. Ctrl+K's Open suggestions include inactive sessions too.

Splitting is deliberate: use **Open in another pane** on an inactive session's menu, or Ctrl/Cmd-click a linked destination. Visible panes are bounded to 1–3 by **Maximum visible panes** (the existing shared `maxOpenNotes` wire key). At capacity, an explicit split falls back to the focused slot without a confirmation. Explicit splitting can use responsive pane navigation; ordinary clicks never add a hidden pane. Lowering the maximum does not discard live assignments; restoring retains excess sessions but caps visible assignments. The workspace-wide **Opening new notes** preference uses `noteOpening: fill | reuse`, default fill. Legacy `openBehavior: split | replace` migrates deliberately to fill; the old control/key is no longer emitted. Narrowing preserves sessions and assignments, with existing responsive pane navigation.

Files remain temporary side/modal previews, never note sessions or journey visits, and retain source-focus restoration. Unsupported resource kinds stay identifiable without guessed editing/preview behavior.

## Journeys and navigation transactions

A new direct session starts a journey. An ordinary linked note navigates within its source session, extending that session's path; Back/Forward returns within it. If a destination already has an open session, that session is focused instead, preserving both paths. A deliberate new linked pane copies the source path/positions with fresh visit IDs. Independent explicitly split journeys can later revisit the same resource through history; the existing shared-document layer safely supports those distinct historical views. Direct opens deduplicate current resources and hydration canonicalizes legacy duplicate current destinations.

Back/Forward retains forward visits until a new link branches the trail. Self-links are no-ops. Each visit has its own ID, so A → B → A keeps distinct positions. Histories/positions are bounded to 200 visits per session; scroll recording does not rerender the workspace. Scroll/caret offsets restore, with selections clamped to current document bounds. Undo history belongs to mounted editors and is not retained after a session's last view unmounts or after restart. Numeric positions are not semantic anchors across remote edits.

The existing shared journey bar shows the focused session's trail, horizontal overflow and accessible full-path menu. Deleted historical destinations remain unavailable and adjacent unavailable steps disable Back/Forward; other valid steps remain reachable through the path menu. Restored destinations become available without reopening them. Loaded titles and renames update trail metadata, not stored inline labels.

Desktop JSON requests queue at eight in the shared connection adapter, below the unchanged native admission limit; queued work cancels on source departure and mutations never retry. Saved-state reconciliation is serialized and inactive sessions use summaries to avoid unbounded request bursts. Per-source tokens and a workspace epoch reject superseded loads/saves, departed sources and workspace-reset responses. Resource invalidation generations also reject loads begun before Trash/purge; direct opens recheck deduplication after an asynchronous save. An explicit focus change prevents a completing navigation stealing focus. Loading, source-note saving (including staged titles), switching and closing commit before unmount; failure preserves assignment/session/input with Retry. Close others/all stops on the first failure. File previews, visible-pane focus changes and explicit splits do not flush unrelated notes. Workspace switching/Quit retain their global strict durability barriers.

## Lifecycle, keyboard and presentation

Confirmed local or foreign 404/410 removes all current sessions for that resource and reconciles visible assignments immediately. Recovery captures happen before editor removal; no temporary transport/host failure is interpreted as deletion. Restore clears historical unavailable flags without creating a session. Startup independently validates every current session and retains journals even when nothing restores. See the linked lifecycle/session guides for details.

Alt+Left/Right keeps its existing pane-focus behavior; the shortcut labels now say Focus previous/next pane. Ctrl/Cmd+Alt+PageUp/PageDown selects previous/next Open Notes session in stable order, including inactive ones (configurable in Settings). Existing Back/Forward and Ctrl/Cmd+Shift+Backspace close-note bindings remain; closing a note removes its session, while **Close pane** retains it. Composition, dialogs, fullscreen and centralized Escape/focus conventions remain authoritative. Sidebar toggle remains Ctrl+Alt+B / Cmd+Option+B.

Existing WorkspacePaneLayout geometry, focus depth, shared motion tokens, NoteOrientation compression and journey transitions are retained. Slot identity survives session changes and surviving panes retain their editors on close. Session switches do not add a tab strip, nested scroll owner or animation delay. At 850px for two panes / 1200px for three, only the focused assignment is presented; compact peers stay mounted/inert. Reduced motion has immediate endpoints and correctness never waits for animation.

## Shared editing and references

SharedNoteDocuments provides live document synchronization for duplicate views in this workspace. Editors share one ProseMirror schema instance (including the extension manager), broadcast original and appended transaction steps synchronously, map each receiving view's own selection, and share history plugin state. Mirrored updates never enqueue duplicate saves. Titles and save status come from the existing per-note Dashboard/cache/coordinator; editing a title is reflected in both headers. A newly joined view receives the live document/history once. Ordinary synchronization never repeatedly calls setContent. Explicit authoritative content replacements reset shared undo to prevent stale links returning after server-side link replacement.

Each view keeps its own DOM scroll position, selection and table-filter/fullscreen state. Valid source transactions cannot be rejected by another view's local table filter. A remote structural change clears affected filters with a local explanation; ordinary local filtered editing restrictions remain. The shared history lives while a note has mounted editors; it is not durable across closing every view or reload. This is in-browser synchronization, not multi-tab conflict protection.

Saved references now open on demand through **References** in the focused-note workspace header or **Used in / links…** in shared Actions. The paginated metadata-only view distinguishes source notes from occurrences and includes outgoing links/image placements, unavailable destinations and local draft warnings. It does not automatically add a backlinks column or fetch note bodies when switching. Validated saved occurrence paths can select a link/image; revision changes or local drafts safely fall back to the source note. Inline reference labels remain stored text while current metadata supplies shared category icons. See [REFERENCES.md](REFERENCES.md).


## Validation and limits

Focused state tests cover independent capacity, direct deduplication/journey preservation, explicit splits, historical positions, active/inactive/bulk close, lifecycle invalidation/restore, concurrent requests, failed save barriers, v1/v2 hydration, offline retry and workspace isolation. Component checks cover Open Notes filtering/actions, pane identity/reduced-motion geometry, settings, shortcuts and recovery. Actual native/build/release evidence is recorded in [0.17.0 release notes](../desktop/releases/v0.17.0.md), including any unverified platform cases. Older N-series evidence is historical, not qualification of this redesign. No Android product code, protocol, resource schema or security boundary changes.


## Linked external documents

Windows This computer adds a distinct Linked sources hierarchy; directories are source-owned, not generated Vaultor collections. Markdown uses ordinary Open Notes sessions and existing pane placement/journeys. Ctrl+click scoped relative links opens the target while preserving its Markdown URL; scoped raster images/PDF are read-only previews. Traversal cannot escape consented roots. Collection memberships reference logical documents without moving files. External replacement/rename is conservative: an old session cannot silently become a reused pathname. [Linked sources](LINKED-SOURCES.md) owns reauthorization, cache and size limits.

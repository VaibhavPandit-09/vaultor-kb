# Vaultor for Android

Reviewed 2026-10-09. A1–A2 are published; A3 browsing/navigation is implemented with release verification in progress. Current Android 0.1.0-alpha.3 (versionCode3) adds native browsing and journeys; actual publication evidence is recorded below. [The tracker](../plans/android-plan.md) owns sprint scope. This guide owns the implemented mobile boundary, local setup and APK delivery. Desktop/Mac 0.7.1 remains unchanged.

## Prototype boundary

`mobile/` contains React Native 0.87.1 / React 19.2.3, WebView 14.0.1 and a locally bundled Tiptap 3.31.4 editor. Permanent package `com.vaultor.app`, current version `0.1.0-alpha.3`, versionCode 3; the original application ID and signer remain unchanged. Minimum API 36 (Android 16); compile/target API 37 (Android 17). Android-only tags use `android/v…`; desktop versions/update feeds are separate.

The mobile client implements manual private IPv4 HTTPS enrollment, matching-code host approval, remembered native credentials, capability/workspace identity checks, paged mixed Library/Recent/Pinned/Collections, conditional editing, remembered host switching, scoped sessions and protected recovery drafts. Native code owns transport and AndroidKeyStore AES-GCM/AtomicFile storage in noBackupFilesDir; credentials never enter React state, WebView, URLs or logs. Android backup is disabled. The observed host CA is enrollment-only: no HTTP or credential is sent through the observation socket. All actual requests validate the selected CA chain, hostname and host identity; redirects and public addresses are refused. Approval must be matched on the host. A1 uses the existing server's `desktop` enrollment kind with the explicit device name **Vaultor Android**, avoiding a server contract change.

The bundled `file:///android_asset/editor.html` has a restrictive CSP and bounded, typed bridge. Network/image loads and arbitrary navigation are disabled; native API operations are allowlisted. Current schema nodes/marks/attributes are retained. Unsupported JSON is kept and unsafe editing/saving is blocked. Image placements currently show descriptive placeholders, preserving their resource IDs and attributes; real image previews/insertion belong to A4. Saves require If-Match; failures retain the journal. An acknowledged save clears only its exact edit version. A conflicting draft blocks editing instead of overwriting either version; Recovery offers an explicit recovered copy or the saved version while retaining the former draft independently.

This is a narrow prototype, not desktop parity. No discovery, binary adapter, full browsing, ordinary note creation, image upload or in-app updater exists yet. Recovery-copy creation is implemented through the existing UUID import API. Authenticated change notifications and remembered-host switching are implemented. No offline synchronization or Android-hosted server. Themes/motion/mobile browsing follow their planned gates.

## A2 recovery, sessions and connection boundary

Native encrypted schema 2 migrates A1 approval/draft data without uninstalling. Up to eight remembered hosts, 32 recovery records and 32 scoped sessions are retained. Scope includes host identity, workspace identity and replacement generation. Clean-note cache is LRU-bounded to 12 notes/8 MiB; total encrypted state is bounded to 24 MiB. Drafts are never automatically evicted: exhausted storage reports an error and prevents unsafe switching/saving until protection succeeds. Protected local storage is not a backup or full offline synchronization.

Every changed edit is journaled on the separate storage executor before conditional Save. Only its matching version is acknowledged. Continued typing during Save remains editable and is rebased only after the saved revision returns. An uncertain Save is not automatically replayed; retry reconciles through revision checks. Recovered-copy requests persist their UUID and exact payload/destination before dispatch; uncertain retries use the same identity. Choosing Use saved version archives the former draft under an independent version key, so subsequent edits cannot overwrite it. Discard recovery requires explicit confirmation and exact-version acknowledgment. Removing a remembered host clears its approval/clean cache/session, but retains separate drafts; server-side revocation is still performed on the host.

App startup restores the selected host, active note, protected draft and bounded caret/scroll position with the keyboard closed. Explicit Notes clears the active-note destination. Transient Hosts/Recovery panels remain closed after restart. The editor remains mounted while those panels are displayed. Offline restart can reopen the last cached note and pending draft; it does not enumerate an offline workspace. Changed server revisions present a conflict instead of replacing dirty content. Foreign Trash retains the local version for a recovered copy, never editing a trashed original. Restored targets reconcile on reconnect. Workspace replacement returns to Notes and retains former-generation drafts separately.

Native requests capture host identity and connection epoch; switching invalidates queued requests and closes streams. Hosts are saved first or switched through explicit Keep drafts after failure; a failed local recovery write still blocks the switch. Pairing a new host follows the same rule. Manual address changes must verify the existing CA and host identity; a changed trust identity requires explicit enrollment. Native authenticated SSE exposes bounded metadata only. Foreground reconnect coalesces events, refreshes clean notes and marks dirty conflicts; reconnect backoff is 1–30 seconds, streams stop in background, and no mutation is replayed on resume. Cursor gaps/reset events reconcile current identity/state rather than trusting stale data. Revocation blocks editing/saving and retains recovery. Android Back dismisses an open native picker/preview, editor keyboard, Recovery/Hosts, then moves the journey back or opens Library; collection Back returns to global Library. Root exit warns about protected recovery. AndroidX receives committed predictive Back; custom gesture-progress animation is deferred to A6.

## A3 browsing and navigation

Native mixed lists use one metadata query per view, server pages of 100 and a three-page in-memory cache. FlatList renders an initial 12 rows with a five-window virtualization bound. Recent retains server recency ordering; Pinned retains mixed alphabetical ordering and distinguishes collection shortcuts from resources. Notes/Files are storage kinds, Images/PDF/Audio/Video/Text/Other are file categories. Unknown kinds show a neutral descriptor and refuse guessed actions. Type and collection pickers search bounded choices; Collections open a scoped Library. Row menus expose safe open/file-information actions; mutation actions belong to A5.

Titles are the default. Saved content is explicit and uses the existing FTS endpoint, plain bounded snippets and file-coverage status; unsaved drafts are excluded. Query/type/sort/scope/page/scroll survive returning and encrypted session restart. Scope changes clear unrelated rows. Superseded requests cancel their dedicated native connection and cannot apply; background failure keeps usable rows with Retry. Browsing requests stop while hidden, preserving cached metadata and the mounted editor. No entire-workspace body enumeration or full offline browsing is added.

One active note owns a maximum of 200 visits. Direct opens reset the trail, inline links extend it, current-link activation does nothing, A→B→A is three visits, and following a new link from an earlier visit drops its forward branch. Back/Forward and the searchable Journey sheet select retained visits; reading positions are restored. Failed destinations leave the source intact; missing visits remain identifiable and retryable. Files open a temporary information sheet without replacing the note or advancing its trail. Actual file/image previews are A4. Library retains the live editor/draft without remounting it; manual Save remains explicit. More contains Hosts/Recovery, reducing header height. Inline resource atoms have keyboard names/focus and capture activation before editor Enter handling.

The scoped browsing bridge allowlists metadata endpoints, parameters and page bounds. Credentials/trust remain native-only; collection changes and workspace replacement cannot broaden scope or reuse another workspace's cache. The fixture host can import only checksum-verified marked Small/Atlas baselines into its newly created temporary workspace; it never runs replacement against personal storage. Native benchmark tests require an explicitly paired loopback fixture and log only timing/counts.

Publish an Android-only GitHub prerelease from a clean pushed immutable source tag, with verified APK/checksum and bounded compatibility notes. A source push, debug APK or draft release is not completed delivery.

Agents own each Android release. Complete the authorized sprint's installed-APK checks and update this guide/tracker/CODEBASE and `docs/android/releases/<version>.md`; commit/push the intended source and immutable `android/v<version>` tag. Build fresh from that tagged source, run `node mobile/scripts/verify-apk.mjs`, install the exact staged bytes in both emulator generations, then run `node mobile/scripts/publish-apk.mjs` for read-only preflight and again with `--publish`. It requires clean tagged/pushed source, original public signer/package policy and checksum, creates a prerelease draft, uploads APK/SHA256SUMS.txt/android-release.json, downloads and compares all assets, then publishes. Existing assets are immutable: identical retries are accepted, differing bytes refused. Never move a published tag. Record actual final checksum/URL/results in a documentation-only follow-up. Desktop stable updater ignores this Android prerelease; no desktop installer is rebuilt for mobile-only changes.

A6 will use credential-free HTTPS update metadata plus expected Android APK signing identity, package and monotonically increasing versionCode. Metadata alone never authorizes installation; Android signature verification and user installation consent remain required. No silent installation is promised. Before then, download the APK directly from its published release and install over the existing app; do not uninstall as an update instruction because that removes protected local data. The first install may require Android's per-source APK permission. Check Android version is at least 16 before installation.

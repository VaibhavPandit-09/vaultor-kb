## Prototype boundary

`mobile/` contains React Native 0.87.1 / React 19.2.3, WebView 14.0.1 and a locally bundled Tiptap 3.31.4 editor. Permanent package `com.vaultor.app`, current version `0.1.0-alpha.7`, versionCode 8; the original application ID and signer remain unchanged. Minimum API 36 (Android 16); compile/target API 37 (Android 17). Android-only tags use `android/v…`; desktop versions/update feeds are separate.

The mobile client implements manual private IPv4 HTTPS enrollment, matching-code host approval, remembered native credentials, capability/workspace identity checks, paged mixed Library/Recent/Pinned/Collections, conditional editing, remembered host switching, scoped sessions and protected recovery drafts. Native code owns transport and AndroidKeyStore AES-GCM/AtomicFile storage in noBackupFilesDir; credentials never enter React state, WebView, URLs or logs. Android backup is disabled. The observed host CA is enrollment-only: no HTTP or credential is sent through the observation socket. All actual requests validate the selected CA chain, hostname and host identity; redirects and public addresses are refused. Approval must be matched on the host. A1 uses the existing server's `desktop` enrollment kind with the explicit device name **Vaultor Android**, avoiding a server contract change.

The bundled `file:///android_asset/editor.html` has a restrictive CSP and bounded, typed bridge. Remote network loads and arbitrary navigation are disabled; native API operations are allowlisted. Image thumbnails use transient native-provided data URLs under the editor CSP. Current schema nodes/marks/attributes are retained. Unsupported JSON is kept and unsafe editing/saving is blocked. Image placements now use native authenticated thumbnails, mapped insertion anchors and touch-accessible tools. See [MEDIA.md](MEDIA.md) for insertion, encrypted pending inputs, preview/cache bounds and platform limitations. Saves require If-Match; failures retain the journal. An acknowledged save clears only its exact edit version. A conflicting draft blocks editing instead of overwriting either version; Recovery offers an explicit recovered copy or the saved version while retaining the former draft independently.

This is a narrow prototype, not desktop parity. A5 implements the drawer-led navigation foundation described below. A6 adds writing/autosave; A7 adds organization/references/lifecycle; A8/A9 retain settings/discovery/updates and integration. [DESIGN.md](DESIGN.md) distinguishes the implemented foundation from the remaining planned interaction behavior. Quick note creation and automatic saving are implemented; A7 [organization/lifecycle](ORGANIZATION.md) is implemented; full theme/motion parity, discovery and in-app updates remain planned. [WRITING.md](WRITING.md) owns the writing/accessory/receipt/creation contract. A4 provides the bounded native binary/media adapter. Recovery-copy creation is implemented through the existing UUID import API. Authenticated change notifications and remembered-host switching are implemented. No offline synchronization or Android-hosted server. Full settings and integrated motion follow A8/A9; baseline visual/input correctness moves into A5/A6. Native paginated browsing is implemented.

## A2 recovery, sessions and connection boundary

Native encrypted schema 2 migrates A1 approval/draft data without uninstalling. Up to eight remembered hosts, 32 recovery records and 32 scoped sessions are retained. Scope includes host identity, workspace identity and replacement generation. Clean-note cache is LRU-bounded to 12 notes/8 MiB; total encrypted state is bounded to 24 MiB. Drafts are never automatically evicted: exhausted storage reports an error and prevents unsafe switching/saving until protection succeeds. Protected local storage is not a backup or full offline synchronization.

Every changed edit is journaled on the separate storage executor before debounced conditional automatic saving. Only its matching version is acknowledged. Continued typing during Save remains editable and is rebased only after the saved revision returns. An uncertain save receipt is persisted before dispatch; retry/restart reconciles the exact sent content and base revision before another conditional write. Recovered-copy requests persist their UUID and exact payload/destination before dispatch; uncertain retries use the same identity. Choosing Use saved version archives the former draft under an independent version key, so subsequent edits cannot overwrite it. Discard recovery requires explicit confirmation and exact-version acknowledgment. Removing a remembered host clears its approval/clean cache/session, but retains separate drafts; server-side revocation is still performed on the host.

App startup restores the selected host, active note, protected draft and bounded caret/scroll position with the keyboard closed. Home and Library retain the active note; Return to note restores it. The originating Home/Library destination is retained for leaving the first journey visit. Transient Hosts/Recovery panels remain closed after restart. The editor remains mounted while those panels are displayed. Offline restart can reopen the last cached note and pending draft; it does not enumerate an offline workspace. Changed server revisions present a conflict instead of replacing dirty content. Foreign Trash retains the local version for a recovered copy, never editing a trashed original. Restored targets reconcile on reconnect. A connected workspace replacement returns to Library and retains former-generation drafts separately. Startup in a newly identified workspace without a session starts at Home.

Native requests capture host identity and connection epoch; switching invalidates queued requests and closes streams. Hosts are saved first or switched through explicit Keep drafts after failure; a failed local recovery write still blocks the switch. Pairing a new host follows the same rule. Manual address changes must verify the existing CA and host identity; a changed trust identity requires explicit enrollment. Native authenticated SSE exposes bounded metadata only. Foreground reconnect coalesces events, refreshes clean notes and marks dirty conflicts; reconnect backoff is 1–30 seconds, streams stop in background, and no mutation is replayed on resume. Cursor gaps/reset events reconcile current identity/state rather than trusting stale data. Revocation blocks editing/saving and retains recovery. Android Back dismisses transient pickers/previews/drawer first, then the IME, then Edit to reading, then the note journey and its Home/Library origin. Collection Back returns to global Library; root browsing returns to Home. Root Home exit warns about protected recovery. AndroidX receives committed predictive Back; A9 will revisit predictive gesture presentation.

## A3 browsing and navigation

Native mixed lists use one metadata query per view, server pages of 100 and a three-page in-memory cache. FlatList renders an initial 12 rows with a five-window virtualization bound; native clipping is disabled, page/editor boundaries remain non-collapsible, and busy restoration gates drawer navigation to avoid the observed Fabric mounting race. Recent retains server recency ordering; Pinned retains mixed alphabetical ordering and distinguishes collection shortcuts from resources. Notes/Files are storage kinds, Images/PDF/Audio/Video/Text/Other are file categories. Unknown kinds show a neutral descriptor and refuse guessed actions. Type and collection pickers search bounded choices; Collections open a scoped Library. Row menus, note More and preview Actions open the shared organization sheet: create/rename, pins, tags, immediate membership, saved References and lifecycle review. Long-press starts contextual resource selection. Trash is a separate title-only bounded destination; successful items leave selection and failures retain local retry state. See [ORGANIZATION.md](ORGANIZATION.md).

Titles are the default. Saved content is explicit and uses the existing FTS endpoint, plain bounded snippets and file-coverage status; unsaved drafts are excluded. Query/type/sort/scope/page/scroll survive returning and encrypted session restart. Scope changes clear unrelated rows. Superseded requests cancel their dedicated native connection and cannot apply; background failure keeps usable rows with Retry. Browsing requests stop while hidden, preserving cached metadata and the mounted editor. No entire-workspace body enumeration or full offline browsing is added.

One active note owns a maximum of 200 visits. Direct opens reset the trail, inline links extend it, current-link activation does nothing, A→B→A is three visits, and following a new link from an earlier visit drops its forward branch. The note More menu opens the Journey sheet for direct earlier/later retained-visit selection; native/header Back returns to the preceding visit; reading positions are restored. Failed destinations leave the source intact; missing visits remain identifiable and retryable. Files open a temporary authenticated preview without replacing the note or advancing its trail; unsupported preview formats offer Save/Open with. [MEDIA.md](MEDIA.md) documents A4 bounds. Library retains the live editor/draft without remounting it; automatic saving retains its local-first safety contract. The workspace drawer owns Hosts/Recovery; connection details are on demand. Inline resource atoms have keyboard names/focus and capture activation before editor Enter handling.

The scoped browsing bridge allowlists metadata endpoints, parameters and page bounds. Credentials/trust remain native-only; collection changes and workspace replacement cannot broaden scope or reuse another workspace's cache. The fixture host can import only checksum-verified marked Small/Atlas baselines into its newly created temporary workspace; it never runs replacement against personal storage. Native benchmark tests require an explicitly paired loopback fixture and log only timing/counts.

## A5 Android-first shell

The compact native top bar and workspace drawer replace the permanent destination tabs and journey strip. Home provides search, up to six Recent and six Pinned previews plus View all. The drawer provides Home/Library/Collections/Search, up to four shortcuts per collapsible section, workspace connections and Recovery. One shared quick-access controller requests mixed 12-item Recent then Pinned metadata sequentially on the native browse channel; it cancels while hidden/backgrounded, retains rows on failure and clears them across host/workspace/generation changes. No per-type query or workspace enumeration is introduced.

Existing notes open read-only with Edit and More. The same mounted editor changes editability without replacing document contents or undo state; selecting a read-mode image opens a temporary preview. A6 replaces explicit Save and separate strips with the compact Insert/Format/Undo/Redo accessory. New-note editing waits for the loaded editor and dismissed creation sheet before requesting the keyboard. Done means reading mode, not a save promise; protected unsaved status remains visible. The Edit action uses a narrow native editor-focus/IME request, cancellable before its delayed dispatch; it accepts no script, credentials or resource IDs. KeyboardAvoidingView reserves IME space under Android's edge-to-edge window. Ordinary saves and theme changes do not repeatedly focus the editor.

Library's search plus Filters sheet replaces stacked permanent filter controls. Short action/sort sheets do not autofocus a search field; real searchable type/collection/history pickers do. Queries, scope, scroll, draft and editor instance survive temporary navigation. Drawer dismissal restores accessibility focus to navigation. At widths of at least 840dp the drawer is docked beside content; smaller windows use a modal overlay. Shared native palette/spacing/48dp actions follow OS Light/Dark, with true-black dark canvases, and the editor receives semantic theme variables. Explicit OS/Light/Dark/OLED/accent preferences remain A8 work; this is not full desktop-theme parity. Reduced motion disables drawer fade.

[The comparison study](design/a5-navigation-comparison.html) contrasts drawer-led and minimal bottom navigation; its keyboard/document are simulations, not native input evidence. DESIGN.md records the decision and remaining work.

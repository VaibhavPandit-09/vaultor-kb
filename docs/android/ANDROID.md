## Implemented reader boundary

React Native0.87.1/React19.2.3 with a restricted local WebView renders structured documents through DOM construction in mobile/reader. It **does not mount an editable Tiptap engine**. The generated assets are reader.html/reader.js/reader.css; the existing build:editor command is a compatibility alias for the reader build and removes old generated editor assets. MinimumAPI36/targetAPI37, package com.vaultor.app and the original APK signer are unchanged.

Compact native navigation provides Home resume/Recent/Pinned, a workspace drawer, mixed metadata Library/search/collections, one saved-note reading surface, bounded 200-visit journeys and temporary authenticated file previews. Title search remains default; content mode is explicit. There is no Edit/Done, Save/accessory, New note, organization write menu or Trash destination. Android native JSON requests allow GET plus the existing POST /resources/{id}/open recency event only. Media bridge permits read/preview/copy/share/save originals; upload/bind/remove/picking/clipboard insertion are refused. Incoming editor share intents are no longer advertised; explicit imports arrive in R7. Native pairing and selected-workspace APIs retain their separate approved transport boundary.

The reader supports headings, text marks, lists/read-only tasks, quotes, horizontal rules, tables/code with horizontal overflow, resource links and resource-backed images/captions/width/alignment. Unknown blocks show an explanatory placeholder; original JSON is retained and never autosaved. Stored HTML, scripts, arbitrary CSS and remote image URLs are not interpreted or fetched. CSP disables connections; navigation is limited to the local reader asset/about:blank. Visible images request authenticated native thumbnails using the captured host/workspace/generation/epoch. Files remain temporary previews, never note-history visits. R2 owns richer typography controls, outline/find, external links, media refinements and reading-position integration.

## Legacy recovery and upgrade safety

R1 preserves AndroidKeyStore encryption, existing AtomicFile storage version2, protected drafts/sent receipts, creation IDs, organization/lifecycle IDs and encrypted pending media bytes. It never acknowledges or deletes a legacy item on reconnect, never displays a draft as the saved original and never automatically retries a legacy mutation. Saved-note caches/sessions remain bounded (12 notes/8MiB, 32 sessions); this is **not complete offline companion storage**. Reading can continue despite cache/session write failure, with a visible storage error.

Drawer and unconnected Workspaces provide **Legacy recovery**. Its inventory names drafts (including uncertain sends), pending creations/operations, and upload inputs with original source scope. Unknown outcomes remain explicitly unknown rather than being inferred as failures. Export opens Android's system file destination and writes a ZIP containing README, human-readable note Markdown, original recovery JSON/identities, upload metadata and original locally retained bytes. Credentials/profiles/CA/device tokens are excluded. Uploaded orphan files remain normal host files. Export leaves every encrypted recovery record intact; no host recovery-copy write is offered. Review the ZIP on desktop before creating any separate recovered resource. Export failure/cancellation retains the originals and supports retry. Native/UI locks prevent duplicate exports; Saved feedback appears only after the selected destination stream has closed successfully. Source removal/offline operation does not prevent export. These recovery ZIPs are private handoff material, not portable workspace archives or automatic import inputs.

The native bridge remains the write enforcement boundary even if old JS code calls it. Host/workspace switching reads destination identity before committing the native selection/epoch and never flushes retired drafts. Existing approved workspace lists, pin/Recent metadata, media transport and SSE retain workspace routing. Storage corruption/key loss cannot be repaired by clearing data; retain records and report the failure. Full downloads, offline search/reviews/import queues and full/partial workspace exports are later sprints.

## Android interaction and design

The note body gets the reading area: a 58dp topbar reserves only navigation/title/contextual More. Drawer navigation is on demand; no permanent editing toolbar or desktop panes. Home offers resume and mixed quick access, while Library uses one virtualized page. More contains reading journey, Refresh saved note and Legacy recovery. System Back dismisses previews/pickers/drawer/recovery/connection surfaces first, then keyboard, journey/origin and browsing scope. OS Light/Dark follows existing mobile semantic colors; dark content is true black. Explicit theme/accent controls follow R9. Text selection/copy uses the WebView's native selection. No claim of Samsung/physical OLED verification is made.

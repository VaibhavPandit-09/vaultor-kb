## Authority and host contracts

Android collects new inputs; the selected source is not a writable local workspace. `GET /api/companions/import-capabilities` advertises version1, 64MiB inputs, 5MiB text conversion, supported modes and owner-approved ZIP workflow. `PUT /api/resources/collected-imports/{uuid}` receives multipart `intent` and original `file`. Intent freezes generation, filename, MIME, original SHA-256/length, original/text/Markdown mode and collection ID or explicit root. Workspace routing remains `X-Vaultor-Workspace`; native credentials remain private. Host generation is checked within the resource/receipt transaction while normal workspace admission excludes replacement. Device approval/grant is rechecked at mutation admission.

`companion_import_receipts` stores source generation/device, exact request fingerprint and acknowledged resource identity. Receipt, new resource and collection membership commit together. Receipt fingerprint is SHA-256 of UTF-8 fields joined with NUL: generation, filename, MIME, original SHA-256, decimal length, mode, collection ID (empty for root). The importer never accepts an occupied ID without its receipt. Same UUID with changed immutable input refuses; duplicate filenames with separate confirmed UUIDs remain distinct. Receipts outlive edits/Trash/purge and do not recreate removed resources. Receipt/rejection limit10000 per workspace fails explicitly without evicting history. Definitive removed-collection/unsupported-encoding/conversion-limit refusals leave immutable rejection tombstones. Exact retries remain rejected; changing their intent under the same UUID refuses. Only an explicit new-import action after such a verified refusal copies the retained original into a new unassigned operation requiring confirmation. Unknown outcomes cannot fork. These private retry receipts and rejections are not portable archive content. `GET /api/resources/collected-imports/{uuid}?generation=...` reads an authorized matching-device receipt; exact PUT replay remains authoritative after uncertain delivery.

Text conversion uses strict UTF-8 or BOM-marked UTF-16 and rejects binary NUL, malformed encoding, unsafe size/depth/node counts and structured output above1MiB. CommonMark Java0.30.0 parses Markdown directly to a bounded AST; host converts headings, lists, blockquotes, emphasis, links and code into structured Tiptap JSON. No HTML rendering, remote fetch or mobile editor. HTML, images and unsupported/local link targets remain literal references with warnings. GFM-specific features outside core CommonMark are not promised. Original File mode preserves arbitrary host-supported bytes without conversion.

Converted inputs create one visible note. Nullable Resource provenance fields retain original filename, MIME, SHA-256, length and a separate private original file. Ordinary note edits and Trash/Restore retain it. Confirmed permanent purge deletes its original along with the note; the nonportable import receipt remains so a retry cannot resurrect it. `GET /api/resources/{id}/import-original` provides authorized original-byte recovery, including while trashed but excluding pending purge. Normal rendered note exports are reading formats, not provenance recovery. Full workspace transfers preserve provenance under archive5: each affected note has `importOriginal` metadata and checksum-covered `originals/{resource-id}` bytes. Merge remaps attachment ownership with the note; replace/new workspace restores it. Read archives1–4 as before; provenance in older formats is refused. Older hosts reject archive5 rather than silently discard originals. No credentials, routing generation or pending device journal are archived.

## ZIP owner authorization

`PUT /api/collected-zips/{uuid}` lets an approved paired device submit exact bounded bytes plus original source, hash, filename and proposed new-workspace name. It cannot create a workspace. The private host request retains device/provenance/operation through retries; same UUID/different intent refuses. Source grant/generation is checked on submission and reconciliation. The host caps pending ZIPs at32/256MiB, with a separate10000 receipt bound. Existing local-owner checks are unchanged.

The owner inspects requests in existing Workspace transfers. Owner-only `/api/owner/collected-zips` lists requests; `/{uuid}/preview` runs W3 dangerous-archive/path/checksum validation without publication. Only a later explicit `/{uuid}/approve` durably records owner authorization before W3 import-as-new. `/{uuid}/reject` releases uncommitted staging/reservation. Android polls its own receipt and retains its local original until exact successful new-workspace acknowledgment. New workspace access still requires an explicit owner grant. No Android replacement, merge-into-current-workspace, owner credential forwarding or general administration.

## Android queue and presentation

Native `VaultorImports` owns `noBackupFilesDir/collected-imports-v1`, independent of legacy recovery, Reviews and downloads. SQLite FULL-synchronous records encrypt payload metadata with Android Keystore; originals use independently authenticated256KiB AES-GCM chunks. Copy streams count/hash original bytes, fsync file and directory, then expose Collected. Partial acquisition is never a collected input. Uploads use owned staged bytes rather than retained provider grants; credentials remain in the existing protected native profiles. Cold/warm SEND/SEND_MULTIPLE and Files/Photos feed native acquisition before a JS event is required; recreated acquisition tokens prevent accidental repeat delivery. Two intentional shares remain separate inputs. Temporary grant loss after successful staging cannot remove owned bytes.

Defaults:64MiB/item, eight inputs/acquisition, 256MiB private staging, 128 retained rows and16MiB free reserve. Existing bytes, partial files and encryption overhead count toward the storage budget. Staging budget is adjustable64–2048MiB; lowering it never evicts. Full/quota/provider failures remain per-item and visible. Acquired originals have explicit SAF recovery/removal. Unknown dispatched items cannot be removed before reconciliation. Uninstall/clear-data still destroys app-private data; key loss is not repaired by resetting journals.

Pending imports is a Home action, with contextual Library and Settings & tools access; it is not a fourth tab or part of Review. No source is inferred on cold Share. Confirmation chooses the current approved reading source and collection or explicit root; another source/collection uses existing navigation. Once queued, exact source/generation/mode is frozen. Host resources are only claimed after validated receipts; new checkpoint availability requires normal refresh. Retained reader, Aa, theme/motion/Back/focus owners remain unchanged. Queue updates stay silent.

`VaultorImportDelivery` is a separate single native dispatch owner. It verifies original integrity before upload, uses captured-source pinned TLS and explicit scope, records sending before stream dispatch, and validates the full acknowledgment including fingerprint. Unknown outcomes retry the same UUID/intent/bytes. One item's failure does not erase successful siblings. Source switching cannot redirect uploads. Automatic uploads default to unmetered; explicit per-item metered override and policy live in Pending imports. Acquisition uses its own worker so a slow network upload cannot hold the temporary URI grant in a dispatch backlog. Foreground/resume and bounded opportunities are authoritative; suspended/force-stopped delivery is not guaranteed. Stop prevents further attempts and cannot undo an uncertain host commit. No automatic staging eviction or new rich haptic pattern.

## Implementation and validation ledger

The host capability/conversion/receipt/provenance slice and native acquisition/staging/delivery/UI slice are implemented. [R7 acceptance ledger](releases/0.1.0-alpha.24.md) owns final artifacts, actual checks, compatibility, limitations and S24 procedure. No public release, master merge or R8 work.

Integration-sensitive files: Resource/lifecycle provenance fields; TransferService/ZipWorkspaceExporter archive5; CollectedZips and owner transfer controls; VaultorModule restricted import transport; MainActivity Share handling; WorkspaceScreen contextual entry. Review journals and original apiFor write restrictions remain separate. CommonMark0.30.0 is the only new host dependency. Native queue schema is version1 and fails closed on unsupported upgrades.

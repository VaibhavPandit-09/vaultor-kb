# A0–A3 motion and haptic remediation

Reviewed2026-10-16. **A3 alpha.15 failed the user's Samsung Galaxy S24 Ultra acceptance:** tactile feedback and structural movement were not meaningfully perceptible. A0–A3 are not interaction-approved. A4 is blocked until explicit user approval. Work stays on ai/codex-r6-android. This document records the pre-change source audit at2cce663 and the remediation candidate; it does not certify device feel.

## Shipped haptic inventory (before remediation)

Native requires resumed lifecycle, attached/shown/focused initiating view, isHapticFeedbackEnabled, Settings.System.HAPTIC_FEEDBACK_ENABLED==1 (missing value defaults0), app SharedPreferences haptics!=off and unique token. A supported capability never proves perceptibility. Touch usage, VIBRATE for rich effects, no ignore-settings flags; pause cancels vibration.

## Remediation interaction specification

1. Keep one native contextual window through capture preparation/composer/receipt. Gate entrances on native onShow plus measured geometry. Use the measured sheet travel and a less front-loaded curve; do not rely on slowing every token. Retain the same source reader/viewer, input, UUID and evidence.
2. After protected composer enters, evidence settles24dp into its source-labelled lock region; H2 fires at that actual endpoint. On durable queue success, the same comment collapses and a saved-status band claims space; H3 fires at completed geometry, with queued state correct immediately even if interrupted. Failure becomes visible with H4 immediately. Reduced motion uses immediate endpoints and corresponding single feedback; disabling haptics never suppresses visual feedback.
3. Find rises from its bottom edge by its own height; focus begins immediately but H1 awaits visible settle + successful focus. Reader source caption/title compress within their existing object, with a clearly visible source-band collapse rather than a7dp drift. Offline/source-unavailable identity remains visible. Drawer/sheets begin only after their native windows are visible. Source confirmation follows actual activity window focus, not a guessed two-frame delay. No animation of whole documents or arbitrary row entrances.
4. Standard H1 uses deliberate CLOCK_TICK, H2 GESTURE_END, H3 CONFIRM, H4 REJECT, H5 LONG_PRESS (rare diagnostic deliberate hold signature, no new destructive action). Respect system/app settings. Return actual admission/playback results. Rich anchor uses a supported crisp CLICK; rich completion uses two supported CLICKs with perceptually separate spacing/strength, or a supported predefined effect/system fallback. Envelope remains a manually comparable optional supported route, not presumed superior. A device-local rich policy permits platform fallback when custom feedback is weak; no brand checks or legacy buzzy waveform.
5. Build-gated development diagnostics expose H1–H5, both rich profiles, platform fallback and supported custom routes; display real capabilities/settings/admission/selected mechanism and requested-vs-accepted results. Default production build has the gate false and native diagnostic methods refuse entry. Candidate is explicitly a development acceptance APK, original signer/package retained for install-over; no USB/ADB phone access.

Legacy weak profiles exist only as explicit build-gated probes. Five standard levels, both rich profiles and all auto/system/primitive/preset/envelope/legacy comparisons are independently triggerable. The panel shows selected and persisted app preference separately, and an immediate selected Off sends inspection only even if protection is pending. Ordinary builds default diagnostics false; native probe methods reject them. Candidate metadata/APK filename and panel explicitly identify development acceptance.

Home/Library/resource route changes, ordinary PDF/gallery navigation and dismissal remain direct/H0; no false shared-element identity or whole-document slide was added. Full-screen download management retains its existing platform fade. Those are explicit limits, not claimed structural-motion demonstrations. ## S24 Ultra acceptance script

Install the **development acceptance APK** over the current app; do not uninstall/clear data. No phone ADB/pairing is needed. Choose app Transitions: Smooth and turn Android Remove animations/reduced motion off for the positive motion comparison; confirm the panel reports effective reduced motion off. Record/report if it stays on rather than forcing a bypass. Keep a fixed comfortable Android touch-vibration intensity, test in hand in a quiet place, and record the intensity. In Samsung Settings search for touch/system vibration and enable touch feedback; app Appearance & reading → Touch feedback → System. Do not change strength between comparisons. The panel's native system-setting read may be unknown; Android remains authoritative. Never interpret `requested` as proof the actuator moved.

1. **Independent vocabulary:** navigation → Appearance & reading → scroll to **Developer haptic diagnostics**. Open it; note System/App/Focus, actuator, primitive, envelope support/usability. Select Probe route:auto. Tap each Trigger H1…H5 twice, with a pause between taps. These isolated probes fire when tapped, with no fake document-save animation. H1 should be light but detectable; H2 a crisp snap; H3 a short firm completion; H4 a clearly different rejection; H5 a deliberate hold-like confirmation or supported THUD impact (see mechanism), distinct from the others. H5 has no product action in this build. Record perceived0=absent,1=weak,2=clear,3=too strong, and whether you can distinguish adjacent levels. Report the displayed mechanism/status/fallback if any is absent. Diagnostic clicks do not delete or save resources.
2. **Custom comparison:** trigger Rich evidence anchor and Rich local capture using auto, system, primitives, predefined, envelope and legacy. Unsupported routes must visibly identify the fallback. Clear anchor should feel like one crisp contact; clear local capture a separated light→firm pair. Legacy is the alpha.15 weak profile for comparison. An envelope is optional, not automatically superior. Record which route you actually feel. Appearance → Capture tactile profile → Platform fallback is a persistent way to use Android feedback if custom effects are weak; Clear clicks is the candidate default. Expressive if supported opts into the bounded envelope. Retest capture after choosing a policy; no manufacturer hardcoding exists.
3. **Shell/context:** close Appearance, open navigation. Notice the drawer travel from the left after its window becomes visible; underlying reader stays put. Open Sources: the bottom surface should visibly claim space. Choose an already approved connected/downloaded source. Its orientation region should visibly settle after the source has actually changed and the activity regains focus; feel H2 at that settle, not while the old sheet closes. Cancelled/failed source changes must not emit success. There are no haptics on ordinary drawer opening, list taps or passive navigation.
4. **Reader/Find:** open a long note. Scroll into reading, then upward. Notice the same source caption compress and return while the same title remains; the document must not jump or reload. Offline/source-unavailable identity must stay readable. Reading options → Find within note: the control surface should emerge upward from its own bottom edge, with the native IME. H1 occurs only when the surface has settled and focus succeeded. Typing, next/previous match and ordinary reading are silent. Close Find: reading position/find DOM identity remain valid. Open image/PDF → controls → zoom, then Fit: original pixels should move from the zoomed bounds into Fit and H2 occurs at the final Fit endpoint. Already-Fit is silent. Invalid PDF page shows its error and H4 immediately; successful ordinary page browsing is silent.
5. **Main proof—passage capture:** return to the note, select a passage with native selection handles, verify Copy still appears, then tap Flag for review. Notice one contextual bottom window over the retained source; no preparatory-window flash/replacement. Composer visibly rises, then the source-labelled evidence settles into its lock position. **Feel one H2 exactly when evidence finishes settling**, not at button-down or arbitrarily at keyboard appearance. Read the quote, title/source and locator. Enter a unique comment; keystrokes/autosave protection are silent. Tap Save on this phone once. The software keyboard should release; the same comment region contracts while a saved-status region emerges; **feel one H3 exactly when the saved band settles with the keyboard hidden, after durable persistence succeeded**. The message must say local/pending sync, never synced. Expand saved comment should visibly reclaim comment space without a second completion haptic. Done returns to the same passage/position.
6. **Other capture targets:** Reading options → Add review item retains that resource; image/PDF Preview options → Add review item retains the file; Review PDF page N captures the actually rendered one-based page. Repeat local save, checking the same evidence lock/completion timing. From navigation → Captures on this phone reopen a saved item: read-only evidence, no repeated anchor/completion haptic. Create a draft, wait for Protected, force-close through normal Android app controls and reopen: exact comment/source remain. Original note/file content must remain unchanged throughout.
7. **Themes/navigation/insets:** Appearance → Light → Dark → OLED, pausing between choices. Notice a coordinated reveal starting at the chosen control; document geometry remains fixed, bars stay legible. No theme haptic. Repeat main capture in all three themes with gesture navigation, portrait and landscape/software keyboard; first Back hides IME, next Back dismisses capture without discarding protected text. Repeat at normal and one practical larger system font scale. Check headings, actions, source identity and saved message remain reachable, with no gesture-bar collision. Record any clipped/flashy/jumpy surface.

Restore System, turn Android touch feedback off → same silence. Restore Android feedback. Enable Android Remove animations/reduced motion where available → immediate clear endpoints, same protected evidence/local receipt, no hidden controls; semantic H2/H3 still occur once at the immediate endpoint.

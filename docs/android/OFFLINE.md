# Android offline reading companions

Reviewed 2026-10-14. R4 targets Android **0.1.0-alpha.11 / versionCode15**; the [execution tracker](../plans/workspace-companion-plan.md) and [release ledger](releases/0.1.0-alpha.11.md) own current validation/publication status. Hosts require **0.11.0 or later** with `companionSnapshots:1`. Protocol3/archive3 remain unchanged. Do not rebuild desktop for this Android-only change.

## Using downloads

Open navigation → **Offline downloads**. Existing downloads come first. **Download content** expands selection controls for the connected workspace, current collection or note. A file preview's More menu opens this destination with that resource captured. Choose selection only, note images, or the outgoing linked chain; readable originals are default, with all original formats optional. The estimate/confirmation explains coverage, omitted originals, storage and replacement before starting. Ready status retains resource and omitted-original/link counts. Selection replaces that workspace's previous reading selection only after verification; it does not accumulate silently or change host resources.

**Read downloaded** selects a source-bound reading companion, independent of whether its host is reachable. It stays local until an explicit connection is made, including after process restart; it does not request LAN permission or post recency events while in explicit local mode. Local Library/search/collections/pins/Recent, links, images and PDF previews use that source's activated checkpoint. Not-downloaded links fail without replacing the current reader/journey. Downloaded-only labels distinguish this from current server data. Saved host recency is a checkpoint view; offline reads do not post delayed recency commands.

**Refresh** captures a new checkpoint for the same selection; **Resume / retry** retains incomplete operation identity and verified files. Expired/failed server checkpoints require a new preparation identity, never reuse an identity for different intent. Pause/dismiss/background/process death cannot activate incomplete content. Android may terminate background work; foreground Resume is authoritative. Optional Refresh on reconnect starts only for an existing selected download in the foreground, at most once per minute, respecting policy. It never initiates a first full download or scans every remembered host, and waits for incomplete work to be resolved.

Default storage budget512MiB, editable64–2048MiB. Metered downloads and downloads below15% battery while unplugged default off. A lowered budget does not evict existing content. Both the old readable dataset and new staging count toward budget; keep16MiB free-space reserve. Storage failures leave old reading data intact. Remove requires confirmation and affects only the selected download/staging; encrypted legacy drafts, uncertain receipts, pending original bytes, credentials and host resources are separate. Legacy recovery/export remains available. Forgetting a host does not erase retained downloads or pending work; reapprove its original identity to use them again.

## Storage and threat model

VaultorCompanions owns app-private `noBackupFilesDir/companions-v1`: schema3 SQLite/WAL metadata, parameterized bounded search, UUID checkpoint directories and original/JSON payload files. Android application backup is disabled. This retained store is separate from evictable96MiB preview cache, encrypted legacy recovery AtomicFile and encrypted pending upload originals. No credentials/CA/device tokens enter the companion database, files, WebView, logs or portable exports.

Reading files and local text index are **not separately encrypted by Vaultor**. They rely on Android's app sandbox and device encryption/screen lock. They are not protected from someone using an unlocked/compromised device. The first download confirmation states this. Key loss makes approved credentials/legacy encrypted recovery unavailable; do not clear app data as repair. Uninstall/clear-data removes downloads. This does not introduce encrypted portable archives or an independently editable Android workspace.

One native download owner per private root across bridge instances. SQLiteOpenHelper schema creation and the additive schema1/2→3 coverage/progress migrations are transactional; unsupported future migration fails without clearing files. Interrupted jobs become resumable. Each payload uses bounded256KiB copying, a partial file, length/SHA256 verification, file fsync and final rename. Canonical manifest bytes are independently hashed; inventory/coverage/payload requests pin its hash. Manifest schema/id/workspace/generation are validated with a streaming reader. The dataset directory is synced before a FULL-synchronous SQLite transaction changes the active pointer. Old data is removed only after that commit. Completed host byte caches are cancelled after local activation (best effort; host expiry handles disconnection). Scoped ready/lock events refresh mounted local views and immediately hide verified locked sources; they never replay a command on restart. Startup removes only orphan UUID directories inside this store. Missing/corrupt originals are detected before reading, with Refresh required; optional offline-store failure does not disable connected reading or erase recovery.

The native adapter alone holds pinned HTTPS credentials, rejects redirects and captures host/workspace/generation/epoch. Its only host preparation writes are POST companion estimate, PUT caller-UUID checkpoint and DELETE completed host byte caches; it cannot write original resources. Switching sources cancels acceptance through epoch checks. Current identity is checked before capture and before activation; host streams recheck grants/generation. Verified revocation/replacement locks the affected companion. Locked copies cannot be reopened via saved-note-cache fallback; currently mounted data is hidden after verified access refusal. Lock tombstones survive removing downloaded bytes and do not count toward the eight retained-source limit; removing a download is never a way to regain revoked access. Offline devices cannot promise immediate remote erasure. A later valid download/refresh can activate the current authorized generation; old pending recovery remains separate.

### Verified source invalidation (R7–R9 integration)

Native source transports share VaultorSourceAccess and VaultorCompanions.observeResponse. Only the captured pinned-TLS/approval boundary supplies observations: exact workspace-unavailable and domain-specific generation problem codes invalidate the corresponding scope; unrelated status codes, transient failures and TLS/host failures do not. Grant loss invalidates retained copies of that workspace; generation refusal invalidates the captured generation, including inactive sources, without locking an independently authorized replacement. General selected profiles resolve their default workspace explicitly during verified activation.

Lock tombstones persist in the existing FULL-synchronous companion catalog; no original/journal cleanup is performed. Shared in-process denial is immediate even while an offline snapshot holds its file lease. The activation admission version prevents an older in-flight download from clearing a newer lock. Only a subsequent successfully verified download/refresh can activate/unlock its own scope. Native cache/original/media/export/provider paths recheck admission, and foreground local-mode restoration rechecks native state to catch a missed bridge event. Already handed-off external copies cannot be recalled.

## Bounds and search

Up to8 source scopes and32 retained active/incomplete jobs; one active selection per host/workspace/generation. Max10,000 resources,64MiB original/manifest,1MiB note JSON,8MiB organization JSON on Android. Inventory is fetched25 rows at a time (native JSON response limit1.5MB); coverage100 at a time. Notes/files are not passed wholesale into JavaScript. Search/count/sort/paging happen in SQLite with100-row output (quick access12); no one-query-per-type expansion. The cache does not download arbitrary remote URLs or host storage paths.

Title search remains default. Explicit content mode matches downloaded titles plus saved note text, including visible link labels and image captions/alt text; literal substring matching uses a derived local text column, not the host FTS relevance index. Collection/type/category/favorite scope remains explicit. Extracted PDF/file text is **not** locally indexed. Resources outside the selection remain unavailable; there is no automatic broadening. Collections/pins retain checkpoint organization and resource metadata; previews retain R2 image20MiB/40MP/PDF20MiB renderer bounds even when larger originals were transported. Existing Save/Share/Copy uses retained originals when local mode is selected.

No reviews/import synchronization or workspace ZIP/partial export is added in R4. R5–R8 own those capabilities. Legacy recovery export remains independent and never acknowledges anything as synced.

## Verification

`test-offline.ps1` requires an explicit emulator-5554/5556 and disposable loopback fixture for transport/UI stages. Store tests use isolated app-private roots with deterministic truncation/hash/quota/source failures; they do not bypass production TLS. Real transport uses normal matching-code approval. Cold tests remove the fixture's emulator forwarding route; they do not access a phone or personal server. Release notes record actual passed stages, native screenshots and remaining checks. Stock API36/API37 do not certify Samsung OneUI, physical OLED, real Wi-Fi/battery behavior or power-loss survival.

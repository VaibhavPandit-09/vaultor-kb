# Android interaction foundations

Reviewed 2026-10-23. This is the current hybrid motion/theme/haptic implementation guide, governed by the [Android design contract](../design/ANDROID_UI_PHILOSOPHY.md). [Shell](SHELL-NAVIGATION.md), [reader](READER-CONTEXT.md), [capture](REVIEW-CAPTURE.md) and [delivery](REVIEW-SYNC.md) own workflows. The user rejected alpha.15 motion/haptic perceptibility on S24; alpha.16/17 remediation and diagnostic evidence survive in their release ledgers. Later authorized R6 delivery is implemented; old stop-before-A4 gates are closed. Emulator wiring is not tactile approval.

## Small shared foundation

The application is intentionally hybrid: React Native owns product UI and most motion, with restricted local reader/media WebViews; thin native Kotlin modules own platform capabilities. Motion leads and most interactions are silent. No Compose migration, animation dependency, scene manager or new network path is introduced. src/motion.ts owns Smooth/Snappy timings: micro120/80, anchor200/180, utility300/220, structure300/240, navigation360/280, theme420/320; cubic-bezier(.2,0,.2,1), no overshoot. OS reduced motion gives zero-duration endpoints and is initially assumed until the system query completes. ReadingProvider supplies the same preference to native presentation and reader; system events supersede a late query. Measured travel, visible geometry and native-window gates make the difference; duration alone is not acceptance.

MotionSheet enters from its measured full lower bounds only after the native modal is shown and caller data is ready. One entrance freezes travel while later keyboard/rotation layout changes retain the same surface. Controls are usable immediately; Done/Back releases ownership without waiting for exit motion. ContextSheet/ReadingControls share the gate; the drawer has its own native onShow gate. Capture preparation, composer and receipt share one window. One ScrollView retains settings scroll; safe-area/IME policy remains native.

## Haptic semantics and policy

src/haptics.ts exposes microConfirm/selectionSnap/actionComplete/reject/destructiveConfirm and playAuthoredPattern(REVIEW_CAPTURED), forwarding meaning only. Kotlin rejects unknown/mismatched product patterns and owns every primitive/amplitude/API choice. The facade sends named events through VaultorPresentation to VaultorHaptics; no screen supplies raw actuator calls. H0 is absence of a call. Standard mappings: H1 CLOCK_TICK, H2 GESTURE_END, H3 CONFIRM, H4 REJECT, H5 LONG_PRESS. Five distinct platform constants replace frequent-segment/same-H3-H5 mappings. H5 has no ordinary product caller. If Android declines a standard request, a known-supported short predefined effect may be used only with known-enabled system feedback; otherwise silent. H5 decline uses supported THUD.9 or explicit silence instead of sharing H3 completion fallback. Actual accepted/requested/rejected/suppressed results remain distinct from felt sensation.

Only REVIEW_CAPTURED is an authored product pattern. Evidence lock uses standard H2. The named pattern uses the same clear native composition as alpha.16: device-local Clear clicks(default) chooses supported CLICK.65 then CLICK1.0 with60ms delay; known-supported predefined DOUBLE_CLICK then system feedback are fallbacks. Old rich anchor/capture profiles are diagnostic comparisons only. Platform fallback opts out of custom feedback. Expressive if supported opts into an envelope(.75 then optional1.0,40ms control points), checking device timing/point/total limits before use, else Clear routing. There are no brand checks or legacy buzzy one-shots. Development-only probes can compare the original weak rich profiles, but ordinary product routing never chooses them. Physical tuning is pending.

Native playback checks resumed lifecycle, attached/shown/focused source view, its feedback flag, Android touch settings and persisted app preference. Known system Off suppresses all feedback. Unknown system preference delegates to performHapticFeedback only; it never authorizes raw vibration or assumes Off. JS also rejects disabled/background calls and duplicate identity is suppressed. Effects use touch usage, no ignore-settings flags; VIBRATE serves custom/preset routes. Pause/destroy cancels app vibration. DevelopmentFeedbackPanel and native diagnostic entry points require build-time VAULTOR_DIAGNOSTICS(default false), explicitly enabled with build-release.ps1 -Diagnostics and marked in APK metadata/filename. Normal builds expose neither UI nor callable probes. Native reports settings/capabilities/fallback/admission and Android request acceptance, not actuator feel.

Touch feedback is device-local System(default)/Off, normalized in TS and native preferences. It is excluded from portable content and recovery. Appearance accent changes and Find entry are H0; themes, scrolling, ordinary navigation and background work are silent. Explicit Preview selection/Preview completion controls let the user assess H2/H3; their small indicator settles before one feedback event. Repeated previews, preference changes, backgrounding and unmount invalidate stale callbacks. Labels say preview, never pretend that a resource was saved. Haptics-disabled behavior retains exactly the same visible/semantic feedback.

## Theme and system bars

Explicit theme choice captures old activity/modal pixels, then commits the real preference. One circular reveal originates at the control across both windows. Actual DOM/view/position/focus remain; overlays are inaccessible and cannot own input. Memory-only snapshots scale proportionally to stay within32MiB total instead of rejecting high-resolution dual windows outright. Allocation/capture failure, background, interruption, resize, missing source, reduced motion or timeout falls back to the latest committed palette. JS capture wait is bounded200ms; native cleanup has independent watchdogs. No correctness depends on animator completion. Real S24 reveal approval is pending.

Startup/system-driven preferences apply immediately. Main and appearance-modal status/navigation icon styles follow resolved Light/Dark/OLED; original image/PDF pixels are never recolored. Theme transitions remain H0. Palette geometry stays stable. The source-bound reader and media security/write refusals are unchanged.

## Validation and physical review

Focused tests cover latest-intent theme races, capture timeout/failure, cancellation, reduced-motion routing, preference migration and feedback suppression. Native tests exercise capability routing and actual emulator foreground/system/app preference admission. Installed UI checks cover the existing appearance surface, theme changes, previews, Back, rotation and retention. Actual commands/results, failures and corrections are recorded in the release ledger.

The user owns real-device acceptance: install over the existing app; open Appearance & reading; compare Preview selection/completion with system touch feedback on/off and app Off; try Light/Dark/OLED, rotation, keyboard and Back. Assess crispness, fatigue and whether the sensation settles with the indicator. Agents never access/pair the phone. Physical interaction quality remains unqualified until the user accepts the actual hardware behavior. No Samsung/OneUI, actuator quality, physical OLED or real-Wi-Fi certification is implied.

A3 [Review capture](REVIEW-CAPTURE.md) uses standard evidence lock and the one named authored REVIEW_CAPTURED completion. After the protected composer enters, a separate evidence-settle endpoint owns H2; after durable queue commit, the visible saved band at its endpoint with the IME hidden owns H3. Visible explicit failure owns H4. All raw effects remain centralized; the rich route preference is device-local. Automatic Review delivery/status is implemented and intentionally silent; see REVIEW-SYNC.md.

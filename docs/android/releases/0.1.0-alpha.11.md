# Vaultor Android 0.1.0-alpha.11 — R4 offline reading

Status: implemented; installed-release gates passed. Source tagging and GitHub publication are pending.

Android-only prerelease, versionCode15, minimumAPI36/targetAPI37. Original signer retained; protocol3/archive3 unchanged. Downloads require host **0.11.0+** advertising companionSnapshots:1. Connected reading on an older compatible protocol3 host remains available. This sprint does not rebuild desktop. Mac host0.11.0 native artifacts remain unavailable; use the exact v0.11.0 [Mac handoff](../../desktop/MAC-HANDOFF.md), without substituting another source version.

## What changed

- Source-bound downloads for workspace, collection or resources, with dependency/original policies, coverage/size estimates, progress and last refresh. Only a completely verified checkpoint replaces the current readable copy.
- Durable local Library/collections/pins/Recent, title-first search and explicit saved-note-text search, linked-note journeys, original images/PDFs and resumable byte downloads. Source isolation, storage budget/removal, metered/battery controls and opt-in foreground refresh preserve previous content on failures.
- **Appearance & reading** is now reachable from navigation and Workspaces: OS, Light, Dark, OLED, accents and reading controls. R2 had these controls only under a note's More menu.
- Pinned requests are admitted by the native reader boundary. Shortcuts have an independent cancellation/execution lane, retaining cached rows while refreshing.
- Long code blocks keep their background across the full locally scrollable line; inline code wraps without overflowing the page. Initial session restoration mounts a coherent native reader rather than losing fast local content.
- Verified revocation/replacement locks retained sources; removal keeps lock tombstones. Recovery and credentials remain separate, and original resource writes remain refused.

## Install and use

Download **Vaultor-Android-0.1.0-alpha.11.apk** from this GitHub release and open it on Android to update the existing app. Do **not** uninstall or clear app data. The JSON/checksum assets are verification metadata; manual installation needs only the APK. Retained legacy recovery and approvals survive install-over with the original signer.

Navigation → **Appearance & reading** changes this device's appearance. Navigation → **Offline downloads** → Download content offers the connected workspace/current collection/note; a file preview's More → Download for offline captures that resource. Confirm coverage/privacy/storage, then choose **Read downloaded**. Explicit local reading remains local across restart until you connect deliberately. Refresh needs the original approved host/workspace generation. A download replaces that source's earlier selection after verification; it does not silently accumulate selections.

## Boundaries and remaining checks

[OFFLINE.md](../OFFLINE.md) is authoritative for limits, plaintext app-private storage and source locks. The local search index covers downloaded titles and saved note text/visible link labels/captions/alt, **not extracted file text or host FTS relevance**. Renderer limits still apply to larger transported originals. Reviews, queued imports and workspace/partial exports remain future R5–R8; legacy recovery export remains separate. Android can stop background work; foreground Resume is authoritative.

Quota/hash/stream failures are exercised deterministically; actual OS disk exhaustion, physical power loss and full10,000-resource stress are not certified. Stock Windows emulators do not certify Samsung S24 Ultra/OneUI8.5–9, physical OLED, real Wi-Fi, battery hardware or TalkBack. No user phone access, broad API smoke run, Docker rebuild or personal workspace mutation occurred.

Stop after R4. R5–R10 require separate authorization. An older disposable loopback fixture on port51106 remains running: automatic approval review rejected its terminal stop because approval is unavailable under the current policy; no alternative shutdown channel was used.

Use disposable notes/files/workspaces and a host backup. No agent phone/ADB pairing is authorized.

1. Install host0.15.0 and install the APK over R6. Check retained source, downloads, reading position, Aa/theme/motion preferences and protected Reviews.
2. Go offline. Cold-share text/Markdown plus a PDF/image, then use Files/Photos for another input. Open Home → Pending imports: each input must remain private and unassigned; recover one original and compare its checksum. Cancel a picker and return with Back.
3. Select an approved source, open a collection in Library, inspect an input and explicitly confirm that collection or workspace root. Reconnect on Wi-Fi; verify one host note/file per confirmed input. Switch source during delivery and force-stop/reopen once: no retargeting or duplicates. Confirm text produces one note and retains original provenance through host full ZIP transfer.
4. Try metered delivery without then with an explicit override. Try a removed collection/unsupported text conversion: retain bytes and clear explanation; only a verified refusal offers a new separately confirmed import. An unknown outcome must offer exact reconciliation.
5. Collect a workspace ZIP. Verify the host owner must Inspect then Authorize new workspace; Android cannot replace a workspace or authorize itself. Reject a request/unsafe ZIP and retain local bytes. Check existing reader/Aa/Review/source transitions, large text/TalkBack focus and meaningful system haptics.

## Limits and acceptance boundary

Automatic delivery uses foreground/resume and bounded retry opportunities. Android suspension/force-stop does not promise background execution; reopening resumes the durable queue. Defaults64MiB/item, eight inputs/acquisition,256MiB staging,128 retained rows, unmetered default; private budget64–2048MiB is adjustable without eviction. Whole bounded uploads replay after uncertainty; no resumable-chunk protocol is required at64MiB. Text/Markdown conversion caps5MiB input/1MiB structured output; core CommonMark only. Per-item states and aggregate counts/retained bytes are progress, not a claimed byte-progress meter.

Physical S24/One UI content providers, Photos/SAF recipient behavior, real metered/Wi-Fi, TalkBack and subjective motion/haptics/OEM battery behavior are user-owned acceptance. This Windows machine cannot build/validate Mac arm64; no Mac/Linux artifacts are ready. Mac must use the exact accepted R7 source, original key, native fresh UI/server/runtime/DMG and install-over/native/API checks before publication. No speculative redesigned UI is authorized.

R8 remains connected full and online/offline partial exports; R9 remains settings/discovery/connection management/verified APK updates beyond R6's delivered UI; R10 remains integrated performance/scale/lifecycle/accessibility/release readiness. R7 does not implement those milestones. Stop for user acceptance before master merge/publication/R8.

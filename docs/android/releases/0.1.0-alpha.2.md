# Vaultor Android 0.1.0-alpha.2 — durable editing and recovery

Android-only prerelease, versionCode **2**, package **com.vaultor.app**. Requires Android16+ and protocol3 host (Windows/Mac0.7.1). Desktop/browser/server/archive contracts are unchanged. Original APK signing identity is retained.

## What changed

- Restores the selected host, active note, caret/scroll and protected pending draft after restart; transient panels stay closed.
- Stores recovery separately per host/workspace/replacement generation, with exact edit acknowledgments and bounded clean caches. Earlier retained versions cannot be overwritten by later typing.
- Detects other-device edits. Dirty notes retain their local version; choose **Open recovered copy** or **Use saved version** deliberately. Recovered copies reuse a persisted UUID after an uncertain reply and leave the original unchanged.
- Remembers multiple hosts; save before switching or explicitly keep drafts after failure. Cancelled connection epochs cannot redirect old requests. Removing a host retains recovery records.
- Reconnects native authenticated change notifications on foreground. Clean notes refresh, unavailable originals retain local content, revoked access blocks edits, and reconnect does not replay mutations.
- Keeps the editor mounted behind Hosts/Recovery and editable during ordinary Save. Back protects edits before leaving; offline cached reopening is not full offline synchronization.

## Installation / update

Download **Vaultor-Android-0.1.0-alpha.2.apk** from this release and install over alpha.1. **Do not uninstall or clear app data**: that removes approvals and local recovery. The two metadata assets are for verification, not installation inputs. No desktop update or repeat enrollment should be needed. In-app Android updates arrive in A6.

Save explicitly. If a host is unavailable, local pending edits remain protected; reconnect before saving. On conflict, inspect Recovery and create a separate copy or keep the saved original. Use saved version retains the old draft until explicitly discarded. Recovery-copy confirmation names the selected destination. Pending copies cannot silently move to another destination. No journal is a disaster backup.

## Verification and limits

TypeScript/release compilation, 22 focused Jest tests, schema/refusal checks and scoped lint (zero errors/13 warnings) passed. Four native tests passed on Android16/17; Android17 pairing/editor+storage suite passed five cases with permission denial/retry. Android16 install-over-alpha.1 retained approval and pending draft. Installed checks exercised dirty/clean foreign edits, conflict choices, recovery copy, force-stop/restoration, offline cached reopening, foreground reconnect and revocation. Final tagged-source artifact checks/publication are recorded in the living Android guide.

The UI remains a prototype: first30 note list, manual Save, image placeholders, no full Library/journeys, image input or updater yet. User-reported poor editing look/feel is assigned to A3/A6 and image tools to A4. No physical Samsung, real Wi-Fi/Mac fault, CJK/full selection, native simultaneous two-host race, battery restriction, or Atlas performance certification is claimed. Existing RN tooling advisories remain documented. Never let an agent connect to your phone.

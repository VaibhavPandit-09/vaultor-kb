# Android media and original-file output

## Viewer and original-file output

Reviewed 2026-10-23. Image placements open a full-screen temporary viewer, never editing tools. Fit, Actual size (bounded to4× fit),1–4× zoom, drag pan, pinch and double-tap keep original pixels/colors. Images remain sampled static previews up to2048pixels per edge/40MP/20MiB input; reduced resolution is disclosed. Original Save/Share/Copy/Open with use original bytes. A note gallery keeps the first128unique image resource IDs in document order; swipe at Fit or Previous/Next opens only another source-note image. Gallery metadata is fetched per selected resource, not by loading every original at once. File previews never add a note-history visit.

PDFs render one page at a time: compact Previous/Next and rendered-page label; contextual editable page number with explicit Go, Fit/Actual size/zoom/pan and remembered position. Preparing/error/status overlays retain viewport geometry, and the label advances on the current render acknowledgment. Original-file and viewing controls share a contextual sheet; gallery changes retain the preview window while captured resource content changes. Fit uses a bounded transform and one current-ticket semantic settle; interruption/reduced motion has a safe immediate endpoint. Preview input remains20MiB; rendering uses at most2560×4000pixels, preserves aspect ratio and paints white paper without theme inversion. Page count is bounded100,000. Password-protected/malformed/large files explain the limit and offer Retry/Open with/Save original. Unsupported formats offer explicit external opening. Text preview remains100KB; general original-file transport remains64MiB.

One restricted local media WebView displays only native-produced file URIs. Its fixed internal scroll viewport keeps fit/zoom independent of oversized content; browser zoom is disabled to avoid competing gestures. Its CSP denies connections and arbitrary navigation/scripts; no credentials or document HTML enter it. UI request tickets discard stale replies; host/epoch/workspace/generation remain captured natively. Per-resource page/zoom/pan persists in encrypted device metadata, keyed by full source scope and resource ID, at most100entries; previews stay closed after restart. Failed storage never alters originals. Scope/epoch changes reset viewing ownership. Position/preview cache remains evictable reading metadata. In R4 downloaded mode, native preview/output uses separately retained, hash-verified originals from the captured source, including generated local image thumbnails; it never falls through to a different host. [OFFLINE.md](OFFLINE.md) owns retention/budget/lock semantics. Retry remains local. More groups original-file Save/Share/Open with/Copy and Download for offline, which captures the selected resource before dismissing the preview. Native destination writes must complete before Saved feedback; cancellation is not success.

## Cache, recipient and legacy input boundaries

Private preview cache is96MiB/32rendered entries; temporary recipient copies80MiB/16files. Source changes cancel requests/clear temporary caches. Clipboard uses a content URI; Share/Open with grant read access only to the selected recipient. These URIs are temporary and may expire. OS handoff does not prove recipient persistence; native SAF Saved feedback requires successful stream close. Source locks recheck provider/original/export access, but externally handed-off bytes cannot be recalled.

Retired image insertion/editing no longer runs on Android. Legacy encrypted noBackupFilesDir/media-inputs originals/catalog (historical8inputs/80MiB) and placement/UUID acknowledgments remain recovery-only: a host resourceId never proves a placement or protected draft commit succeeded. Unacknowledged inputs must not be evicted or replayed. [READER.md](READER.md) owns private recovery; [IMPORTS.md](IMPORTS.md) owns the distinct current streaming encrypted collected-input queue, without editor anchors or camera insertion.

Historical media artifact checks remain in [alpha.4](releases/0.1.0-alpha.4.md); current installed source/lock/output evidence is in [R7–R9](../development/qualification/R7-R9.md) and [R10](../development/qualification/R10.md). Samsung clipboard/SAF providers, actual Wi-Fi/Mac transfer, TalkBack and OEM lifecycle remain user-owned; emulator checks cannot certify them. No video/audio playback or original media transformation is promised.

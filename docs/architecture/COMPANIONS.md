# Companion checkpoints — schema 1

Reviewed2026-10-22. R3/host0.11.0 introduced the reading-dataset service, consumed by current Androidalpha.28. The R10 host0.16.1 candidate reduces repeated manifest parsing without changing this schema or authority contract; [qualification](../plans/R10-ACCEPTANCE.md) owns measured outcomes and approval status. [OFFLINE.md](../android/OFFLINE.md) owns native retained storage, activation and local-search bounds. This is neither a portable workspace ZIP nor bidirectional synchronization. Protocol3 and original-resource APIs stay unchanged; current portable full5/partial6 formats are separate.

## Identity and authorization

`GET /api/capabilities` advertises `companionSnapshots:1`. Every `/api/companions` request retains ordinary owner/paired HTTPS/CSRF checks and explicit `X-Vaultor-Workspace` routing. Missing workspace header means the fixed default, never another client's selection. Snapshot receipts bind workspace, generation, initiating device (owner is separate) and normalized selection. Another approved device cannot read that receipt. Current grant/device approval is checked before dispatch and again during preparation/byte delivery. Replacement returns409 `COMPANION_GENERATION_CHANGED`; grant loss refuses access, never redirects to default. Downloaded bytes cannot be remotely erased; R4 locks on verified revocation and keep unsynced work separately.

## Selection and request sequence

Selection is `{generation,scope,ids,dependencies,files}`. Generation and IDs are canonical UUIDs. Scope `workspace` requires empty IDs; `collections`/`resources` require1–100 IDs, sorted/deduplicated for retry comparison. Dependencies are `none`, `images` (managed image placements only), or `linked` (transitive saved resource links/images/table provenance, cycle-safe). File policy is `originals` or `readable`. Readable includes original PNG/JPEG/WebP/GIF/PDF/text bytes; it does not convert arbitrary formats or extract PDF text. Remote images are never fetched. A broken image placement pointing to a note/non-image file is metadata-only unsupported-reference in images mode; it cannot broaden that policy into note-body downloads. Unknown kinds retain metadata with `unsupported` state.

1. POST `/api/companions/estimate` with selection: resource/note/file counts, estimated payload bytes, omitted-file/unavailable counts. No binaries copied. `exactBytes:false`: later capture can differ, and manifests/receipts add overhead. Estimates have no side effects on originals.
2. PUT `/api/companions/{callerUUID}` with the same selection. A receipt is durable before dispatch. Identical retries return that receipt, changed intent409. IDs must never be repurposed by clients. Receipts retain retries for seven days; after that a missing ID requires a fresh explicit request, never treating an old local checkpoint as current.
3. GET `/{id}`: QUEUED → RUNNING → READY, or FAILED/CANCELLED/EXPIRED. READY exposes workspace/generation, manifest SHA-256, counts, payload bytes and fixed creation/expiry times. Only READY permits inventory/downloads. A failed preparation needs a new UUID; status/download retries reuse the existing READY checkpoint.409 WORKSPACE_BUSY is retryable.
4. Pin the quoted READY manifest SHA-256 as **If-Match** on all inventory/coverage/payload/comparison requests. Missing428, differing412. Do not follow a response from another workspace/generation or replace the pin silently.
5. GET `/{id}/inventory?page=0&size=100`: immutable metadata entries, payload descriptors, references and organization descriptor. Size1–200; no note bodies or storage paths. GET `/{id}/coverage` pages omitted reference targets. GET `/{id}/payloads/manifest.json` optionally downloads the original manifest bytes for independent SHA verification; it contains metadata, selection and coverage, never note bodies.
6. GET `/{id}/payloads/{key}` downloads each available note JSON, original binary and organization JSON. Keys are generated resource UUID + `.json`/`.bin`, `organization.json`, or `manifest.json`; never filesystem paths. Content is attachment/octet-stream. Single `Range: bytes=start-end` or `bytes=start-` returns206; invalid/multiple/suffix ranges416. ETag and X-Vaultor-SHA256 refer to the **whole payload**, not a range. Persist bounded progress and assemble/verify size+SHA before activation. A truncated stream is not successful, even after200 headers.
7. Activate a complete verified checkpoint atomically on the client. Preserve the preceding readable checkpoint until then. “Complete” means all available payloads under the declared selection/policy, with omissions visibly disclosed—not a complete portable workspace archive.

DELETE `/{id}` requests cancellation, prevents publication/delivery and removes retained bytes. QUEUED/RUNNING status may remain until the worker acknowledges cancellation. Originals, client recovery and future review/import queues are never altered. Cancellation/storage failure remains retryable; never clear a client queue because a reading download failed.

## Manifest and coverage

Schema1 manifest contains id/workspaceId/generation, normalized selection, createdAt/expiresAt, ordered resources, excluded targets, organization descriptor and payload-byte count. Entries contain resource identity/type/title/opaque revision, MIME/original size, timestamps, favorite, tags/collections, saved reference IDs, document/binary descriptors and state. Descriptor is `{key,bytes,sha256,mediaType,state}`. Only `available` descriptors have downloadable keys/hashes. File states include `policy-omitted`, `missing`, `too-large`; selected/dependency targets can be `unavailable` or `trashed`/`unsupported-reference`. Unselected outgoing targets are listed as `not-selected`, without fetching their bodies. No missing original is guessed into existence. Saved note JSON remains structured and is never stripped/autosaved by this service.

Organization JSON contains relevant collection names/pins/memberships and tags; workspace scope also includes empty collections/unused tags. Membership lists contain only checkpoint resources. Device preferences, credentials, journals, operational IDs, host catalog/grants and server storage paths are excluded. This source-bound dataset deliberately includes workspace/generation/revisions for restoration isolation; it is **not portable archive format3** and must not be passed to archive import.

## Consistency, refresh and deletion signals

One worker per workspace acquires its exclusive maintenance gate and a SQLite transaction while capturing metadata, documents and copying originals. All normal resource/organization edits, Trash/Restore/purge and workspace transfers are excluded for that capture. Requests receive retryable409 rather than observing an inconsistent snapshot. Other workspaces remain independent. Files are copied into private staging, hashed and length-checked; READY is published only after the immutable manifest is written. Failures/cancellation remove partial bytes. Damaged/unwritable optional checkpoint storage disables this service with503 COMPANION_STORAGE_UNAVAILABLE while retaining originals and allowing ordinary workspace startup. Repair host disk/permissions/private checkpoint metadata and restart; never clear original storage to fix a cache. Restart preserves READY checkpoints and marks interrupted preparation FAILED, removing its partial files.

Streams remain hints with bounded replay. Never build an offline checkpoint by assuming no change events were missed. Prepare another coherent checkpoint, then GET `/{new}/delta?from={old}` using If-Match for the new manifest and **X-Vaultor-Base-Manifest** with the quoted old hash. Both must be READY/current/unexpired and have identical workspace/generation/selection. Paged changes are added/changed entries and `not-in-checkpoint` removals. A removal means absence from that selected reading dataset, not proof of irreversible deletion. Selected unavailable/trashed entries give explicit state. Always reconcile the new organization/coverage descriptors too. Reuse local bytes only by verified payload SHA/size. If old state expired or selection changed, compare the full new inventory with local metadata; no unbounded change history or silent broadening exists.

Byte streams recheck cancellation, expiry, grants and generation at each256KiB chunk. A bounded chunk already in flight can arrive after revocation. A read lease excludes replacement/capture/search-index maintenance while each immutable payload streams, preventing routine index writes from truncating ranges; already admitted bytes can finish before replacement commits. Shutdown, cancellation, expiry or access loss interrupts delivery; the client must retain progress without accepting incomplete bytes. Requests and worker state participate in private host stop/drain. No new note-writing endpoint is needed.

R10 retains at most one softly referenced parsed manifest per workspace context, only for manifests up to4MiB. Every manifest/inventory/coverage/payload request still checks its receipt owner, current approval/grant, expiry/cancellation, generation and exact If-Match, then reads and SHA-256-verifies the current manifest bytes before using a parsed value keyed by that verified hash. Same-length/unchanged-mtime corruption cannot reuse the cache. Cached lists are immutable; cancellation/expiry/shutdown clear the matching value, and memory pressure may reclaim it. Larger manifests keep the original verified parse path. No cached authority, persistent index, portable-format change or skipped per-chunk check is introduced.

## Bounds and storage

- Four active QUEUED/RUNNING/READY checkpoints,128 retained receipts per workspace. Full quota429; no automatic eviction of a live checkpoint.
- Fixed one-hour lifetime from request (test override may shorten). Reads do not extend expiry. Seven-day receipt retention; cleanup runs at startup and subsequent requests, not as a background eraser of user work.
-10,000 selected/dependency resources;100 seed IDs;10,000 collections/tags;20,000 omitted targets; bounded paged metadata.
-64MiB maximum per original,1MiB per note JSON (stored UTF-8 length checked before parsing),64MiB combined note/organization JSON and64MiB manifest. At most2GiB retained payload bytes per workspace, plus bounded manifests/receipts. Oversized files are explicit omissions; oversized datasets/notes fail rather than publish incomplete coverage.
- Preparation checks a120second deadline while traversing/copying/organization capture; filesystem operations are not an absolute OS-level deadline guarantee.
- Private sibling `companions/{UUID}/receipt.json`, `manifest.json`, `blobs/` under each workspace's storage parent. Atomic private receipt/manifest publication; filenames never come from resource titles. Symlink/path/length checks and SHA validators fail closed. These are evictable host artifacts, not backups and not portable exports.

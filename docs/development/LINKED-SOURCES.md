## Practical filesystem policy

Windows x64, local NTFS (fixed/internal and external), ordinary user-owned Markdown. Main/renderer remain unelevated. No elevated helper is currently justified: exact optional SACL parity is no longer universally required. Unreadable SACLs are **not assumed absent**; custom audit/security-resource metadata is not promised preserved. Explicit integrity labels and detected special files are read-only. Initially refuse EA/ADS/encryption/compression/reparse/sparse/cloud/readonly and existing multiple-hardlink source writes. Ordinary Unicode names/generated8.3 names must work. File identity/hardlink changes on replacement are documented semantics.

Preserve exact validated bytes, supported encoding/BOM/EOL, current owner/group/DACL, ordinary flags and creation time. Other timestamps may change. Prepare the new inode with a protected copy of current source access rules; restore ordinary inheritance through the held new inode at its authorized parent. Never modify original content/security in place. Interrupted metadata reconciliation leaves a restrictive owner-accessible replacement and explicit recovery, never COMMITTED. Final success requires content/identity/ordinary-metadata checks. Optional auditing limitations are declared, not falsely called exact parity.

Use directory read-data leases and native RootDirectory-bound operations. Retain captured original and flushed B/L/V before exclusive publication. Gap occupants survive; postpublication changes produce conflict/uncertainty. No hash CAS claim, overwriting rename, original-object writer, silent replay or automatic evidence purge. Check workspace/root/revocation throughout.

Windows0.20.0 extends the same-volume contract through RecoveryCarriers: primary drafts stay available on C:, while detached source publication uses a source-volume store. Volume GUID + directory identity bind immutable carrier descriptors beside the primary journal; journals resolve operations across available verified carriers. Native Windows volume discovery remains in WindowsFiles, private source grants in LinkedStore, and renderer/editor contracts remain platform-neutral. Registry source volume GUIDs permit verified remount discovery without granting authority to reused drive letters. Native-picker carrier setup is main-process signed and refuses source/repository/protected/reparse/different-volume locations. See the [product contract](../workspace/LINKED-SOURCES.md) for lifecycle and retention.

NTFS on the actual external E: drive recomputed inherited ACLs during capture into a private directory. PracticalMetadata.prepareCaptureDirectory supplies the source parent's rules as INHERIT_ONLY on the private operation directory, preserving captured-file ACLs without granting access to that directory or setting security on the original inode. Journal/draft files receive private ACLs before any bytes; source/stage/capture metadata checks remain enforced. The existing object-ID admission behavior remains unchanged.

Final native regression command: native/linked-markdown/check-production.ps1 -SecondaryVolume 'E:\'. It compiles maintained Java plus existing fixtures, runs 11 affected suites, prints compact totals and retains full failure logs under ignored desktop/cache. Actual external NTFS evidence: Save/exact bytes, interrupted publication, process termination after capture, explicit restoration, multiple roots/shared carrier, wrong-volume/unsafe placement refusal, disconnect/restart and replaced carrier identity.

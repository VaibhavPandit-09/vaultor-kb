## Product and architecture

Vaultor is a personal, locally hosted knowledge workspace. Notes and uploaded files are resources, organized by nested collections and tags and connected through inline links. The desktop restores its selected server/workspace, starting the owned server when needed; browser access uses a local owner handoff or host-approved LAN device session. There are no accounts, master passwords, note lock controls, note/archive encryption, or encrypted archive compatibility. D5 adds owner/device access credentials separately from workspace data. Obsolete credentials stored in an existing database are ignored; startup does not delete resources.

React 19 + TypeScript 5.9 + Vite 8 + Tailwind 3 + Redux + Tiptap 3 call Spring Boot 4 / Java 25 through a shared Axios client at /api. Spring Data JPA stores metadata and serialized Tiptap documents in SQLite; file bytes live separately on disk. Hikari uses one connection per workspace to serialize application transactions and avoid concurrent SQLite read-to-write lock upgrades; reads also queue, so keep transactions short. W1 adds up to eight isolated host workspaces: the adopted default uses the main context; each additional workspace uses a separate database/file root and independent Spring domain/JPA/worker context in the same JVM. Explicit X-Vaultor-Workspace routing never changes a global active datasource. [WORKSPACES.md](architecture/WORKSPACES.md) owns catalog, grants, migration/checkpoint, API and bounds. Backend JSON uses Jackson 3 tools.jackson. Exact versions are in the package lock and pom.xml. Vite proxies /api and /access to 127.0.0.1:8080 on fixed port 5173; only exact loopback development Origins are rewritten. Docker embeds the frontend in the Spring JAR and serves one origin.

The backend is authoritative. This is not an offline browser database or a synchronization system. Docker publishes to loopback by default. Host-approved LAN access is explicit and off by default; never expose this personal deployment publicly or bypass device approval for debugging.

## Agent-owned release delivery

Installed-app changes are not complete at a development build: agents own version/package-lock bumps, fresh UI plus embedded browser/server builds, focused/native target checks, original-key-signed artifact pairs, source commits/tags, GitHub draft assets and publication under [RELEASE-PROCESS.md](desktop/RELEASE-PROCESS.md). The user-facing exact Windows/Mac/browser/Docker/Ubuntu status and update steps are in [INSTALLATION-AND-UPDATES.md](desktop/INSTALLATION-AND-UPDATES.md). Documentation/test-only changes with no shipped behavior do not require installers. `desktop/scripts/release-artifacts.mjs` verifies installer identity/size/checksum; `publish-release.mjs` defaults to dry-run and requires a clean source tree and matching pushed tag for draft upload, preserving existing assets. Explicit --add-platform permits a missing verified platform pair on an existing published release and byte-identical retries; differing assets are rejected, and the original source tag remains immutable. It does not certify native validation or publish a draft automatically. GitHub Releases are the default public update source. Updates checks on opening and once after normal installed startup, selecting the highest stable complete per-platform pair from at most 100 records. Bounded credential-free GitHub asset redirects are supported; custom feeds still reject redirects. Installed Windows uses one Update and restart action, verified download/save/backup, a hidden parent-waiting silent installer helper and relaunch. Manual import is Advanced; development/portable/Mac replacement remains explicitly manual. No CI key storage or paid feed is configured. Missing native Mac access/original key/verification must be reported, not presented as a successful release.

### Host companion checkpoints

Host0.11.0 advertises companionSnapshots:1 at unchanged protocol3/archive3. [COMPANIONS.md](architecture/COMPANIONS.md) owns the source-bound dataset/API contract. CompanionSnapshots/CompanionController implement generation/device-bound durable receipts, bounded selection estimates, coherent private immutable note/file/organization captures, paged inventory/coverage and checkpoint comparison, hashed payloads and single-range byte resume. Whole manifest bytes are downloadable and SHA-verifiable. This is not archive ZIP export, a write queue or Android offline storage; Android R4 consumes it through the native retained store described below; R5 host triage is complete; R6 A0–A5 engineering is integrated below, with physical acceptance pending; R7–R9 are published on master; R10 quality/scale/upgrade engineering is integrated.

One worker per workspace captures under its exclusive WorkspaceGate/SQLite transaction. Existing resource/organization/Trash/Restore/import requests cannot mix metadata and bytes. Other workspaces are independent. Companions routes participate in workspace authorization and private stop/drain, without retaining a request EntityManager/SQLite connection during network writes. The shared host catalog is explicitly registered in child contexts for grant rechecks. HostFiles' atomic private-file helper is public for domain artifact use; no keys/credentials are stored in checkpoints.

Limits: four active checkpoints/128 receipts; one-hour fixed byte lifetime/seven-day receipts;10,000 resources and collections/tags;100 seed IDs;64MiB per original,1MiB per note,64MiB JSON/manifest;2GiB retained payloads per workspace plus bounded metadata. Oversized/missing/policy-omitted originals and unselected links are explicit. Partial preparation fails/cancels without READY; restart removes interrupted staging. Damaged optional storage disables companion downloads with503, without disabling original-workspace startup. Immutable streams hold a maintenance read lease; every byte chunk rechecks current access/generation/cancellation; If-Match pins manifests and client final hashes reject truncation. Deltas compare two matching immutable selections; expired/gapped streams require full reconciliation, never silently broader scope. Current validation/publication evidence is recorded in desktop/releases/v0.11.0.md.

The R10 host0.16.1 caches one reclaimable immutable parsed manifest per workspace when its serialized bytes are at most4MiB to avoid re-deserializing an Atlas manifest for every payload. Current bytes are still read and SHA-256-verified on every request after receipt/source/validator checks; cached authority is never admitted. Cancellation/expiry/shutdown clear the matching parsed value, and larger manifests keep the verified parse path. [COMPANIONS.md](architecture/COMPANIONS.md) owns the exact boundary; [R10 qualification](development/qualification/R10.md) owns baseline/candidate measurements and acceptance status. Protocol/schema/Android app remain unchanged.

## Data model and persistence

| Entity | Contract |
| --- | --- |
| Resource / resources | UUID string id, type note/file/linked, title, serialized content, filePath, MIME, size, createdAt/updatedAt/lastOpenedAt, favorite, internal optimistic revision_number/revision_seed, nullable trashed_at/purge_pending/trash_organization, many-to-many tags and collections |
| Review / review_items | Generation-scoped immutable evidence, target/provenance, open/resolved/dismissed status, private review validator; no resource cascade; portable representation in REVIEWS.md |
| ResourceCollection / collections | UUID id, nullable parentId, display name, unique parent-scoped normalized_name key, favorite, internal creationFingerprint for retry-safe creation; resource_collections joins resources to multiple collections |
| Tag / tags | UUID id, normalized unique name, persistent color |
| Relationship / relationships | fromId/toId/type=link, derived from resourceLink and image nodes; IDs are plain strings |
| Setting / settings | key_name/value; app_settings_v2 holds workspace/local/keybindings |
| resource_fts | Derived SQLite FTS5 resource titles/visible saved-note and extracted supported file text; resource triggers maintain transactional consistency; startup/Diagnostics rebuild in gated batches |
| file_search | Derived bounded saved-file text/status/hash keyed by resource version and workspace generation; subprocess decoding, no archive inclusion |
| LifecycleRequest | Durable per-item operation ID/resource/action/expected revision/result, including irreversible purge cleanup and completed purge tombstones; nonportable |
| TransferOperation | persisted kind, status, phase, progress, mode, detail, requestId, timestamps, cleanup journal |

SQLite uses Hibernate ddl-auto=update with hibernate.hbm2ddl.jdbc_metadata_extraction_strategy=individually; there is no versioned migration framework. Individual inspection is required because existing SQLite FTS5/shadow tables expose untyped columns that crash Hibernate grouped metadata extraction on restart. Keep schema updates enabled and leave the derived search tables/data intact. Resource DTOs omit internal file paths and expose note content as a JSON object (never a JSON-encoded string).

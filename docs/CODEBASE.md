# Vaultor: living codebase and agent guide

Last reviewed: 2026-10-04. This is the current implementation reference. Update it in every change as required by [AGENTS.md](../AGENTS.md). Historical specifications are context only. See [API.md](API.md), [OPERATIONS.md](OPERATIONS.md), and the [documentation index](README.md).

## Product and architecture

Vaultor is a personal, locally hosted knowledge workspace. Notes and uploaded files are resources, organized by flat collections and tags and connected through inline links. The desktop opens its owned workspace directly; browser access uses a local owner handoff or host-approved LAN device session. There are no accounts, master passwords, note lock controls, note/archive encryption, or encrypted archive compatibility. D5 adds owner/device access credentials separately from workspace data. Obsolete credentials stored in an existing database are ignored; startup does not delete resources.

React 19 + TypeScript 5.9 + Vite 8 + Tailwind 3 + Redux + Tiptap 3 call Spring Boot 4 / Java 25 through a shared Axios client at /api. Spring Data JPA stores metadata and serialized Tiptap documents in SQLite; file bytes live separately on disk. Hikari uses one connection to serialize application transactions and avoid concurrent SQLite read-to-write lock upgrades; reads also queue, so keep transactions short. Backend JSON uses Jackson 3 tools.jackson. Exact versions are in the package lock and pom.xml. Vite proxies /api and /access to 127.0.0.1:8080 on fixed port 5173; only exact loopback development Origins are rewritten. Docker embeds the frontend in the Spring JAR and serves one origin.

The backend is authoritative. This is not an offline browser database or a synchronization system. Docker publishes to loopback by default. Host-approved LAN access is explicit and off by default; never expose this personal deployment publicly or bypass device approval for debugging.

## Data model and persistence

| Entity | Contract |
| --- | --- |
| Resource / resources | UUID string id, type note/file, title, serialized content, filePath, MIME, size, createdAt/updatedAt/lastOpenedAt, favorite, internal optimistic revision_number/revision_seed, many-to-many tags and collections |
| ResourceCollection / collections | UUID id, display name, unique normalized_name, favorite, internal creationFingerprint for retry-safe creation; resource_collections joins resources to multiple collections |
| Tag / tags | UUID id, normalized unique name, persistent color |
| Relationship / relationships | fromId/toId/type=link, derived from resourceLink nodes; IDs are plain strings |
| Setting / settings | key_name/value; app_settings_v2 holds workspace/local/keybindings |
| resource_fts | Derived SQLite FTS5 resource titles/visible saved-note text; resource triggers maintain transactional consistency; startup/Diagnostics rebuild in gated batches |
| TransferOperation | persisted kind, status, phase, progress, mode, detail, requestId, timestamps, cleanup journal |

SQLite uses Hibernate ddl-auto=update with hibernate.hbm2ddl.jdbc_metadata_extraction_strategy=individually; there is no versioned migration framework. Individual inspection is required because existing SQLite FTS5/shadow tables expose untyped columns that crash Hibernate grouped metadata extraction on restart. Keep schema updates enabled and leave the derived search tables/data intact. Resource DTOs omit internal file paths and expose note content as a JSON object (never a JSON-encoded string). Entity persistence still stores content as text. Dates use LocalDateTime without a timezone suffix. Opening a resource updates only lastOpenedAt through a metadata SQL write; it does not change updatedAt or hydrate/save its document. Some tag mutations can still change updatedAt, so it is not strictly a content timestamp. Import preserves archived IDs on replacement and allocates new IDs on merge.

ResourceService saves the note and rebuilds outgoing link relationships transactionally. LinkExtractionService extracts resourceLink.attrs.resourceId; table sourceResourceId is checked/remapped by DocumentService but is not a backlink edge. Replacing links rewrites stored note references and table source references, rebuilds edges, and deletes the old resource. Replacement with itself is rejected. Ordinary deletion can leave incoming document references; the read-only integrity API reports them. Tag names trim/lowercase and unify case-insensitively; default colors are deterministic. FileStorageService confines paths to its configured directory.

## Backend and API contracts

Use [API.md](API.md) for flows and /api/openapi.json for the machine contract. The same APIs serve agents and UI, without a privileged execution interface. Explicit DTOs cover resources, tags, settings and operations. List responses include items/page/size/totalItems/totalPages (size 1–200). Browsing returns metadata-only summaries with title/collection/type/all-selected-tags/favorites filters and recent/updated/title sorting. GET /resources/query supplies relevance-ranked saved-note/title search with metadata and safe snippets (size 1–100); legacy /resources/search still caps title matches at 50. See SEARCH.md for search/index contracts. GET resource detail supplies document content. Resource details and list summaries include collections [{id,name}]; list enrichment batches tags and collections without reading documents. PUT /resources/{id}/favorite persists a boolean without changing modification time. GET /organization/pins pages mixed shortcuts; POST /organization/selection reads membership counts for selected IDs. PUT /collections/creations/{id} creates once with initial members, and optional collectionId on note creation/file imports assigns membership transactionally. See [Library workflows](LIBRARY.md).

Resource details expose an opaque revision; the UI sends quoted If-Match on note updates, returning 412 NOTE_REVISION_CONFLICT for stale writes. JPA optimistic locking guards concurrent updates. GET /workspace/identity returns persistent identity/replacement generation; generation changes inside the replacement transaction. Internal identifiers are excluded from portable archives.

All API responses carry X-Request-ID. Errors use problem details with status, code, detail, fieldErrors and requestId. Default logs contain request method/path/status/duration and mutation outcomes, not complete request payloads, note bodies or binary contents. Unexpected failures include stack traces. Frontend boundaries and network errors retain diagnostic references and correlate server request IDs.

D1 capabilities explicitly expose serverBuild, apiProtocolVersion and minimumClientProtocolVersion; current protocol is 1. BuildInformation uses BUILD_VERSION (default desktop-d1) consistently for capabilities/health and request/transfer logs. The client uses VITE_BUILD_VERSION separately. Deploy frontend/backend together; the UI intentionally rejects old servers lacking compatibility metadata before mounting settings/workspace. Details and examples: [API.md](API.md).

RequestLoggingFilter supplies correlation/logging around HostAccessFilter. Only approved requests reach WorkspaceRequestFilter's shared gate for resource/tag/settings/collection/organization calls. Transfers take the exclusive gate during snapshot/commit and search rebuild takes it per batch of 100, and concurrent approved calls receive 409 WORKSPACE_BUSY. The gate is process-local: run a single backend against a data directory. Health requires approval and reports readiness/busy state; integrity checks never repair data. Compose rotates JSON logs at three 10 MiB files; desktop logs retain their existing bounded ring/disk rotation.

## Frontend state and workflows

main.tsx owns the shared Escape provider above DesktopRoot and application boundaries. In browser mode DesktopRoot passes through without desktop calls; in Electron it verifies/activates a profile before mounting ConnectionGate/SettingsProvider/Dashboard. API delegates to platform.ts's connection adapter; native main owns bounded network requests while raw bootstrap/diagnostics avoid recursive reporting. Relative paths, caller/epoch cancellation, stale responses, binary problems and optional stream ownership remain shared. D4 native imports use opaque file tickets; note/workspace/file downloads and PDF/image previews stream in main, while generated blobs use bounded chunks. Main reports actual disk success/cancellation, owns a bounded cache and gates profile switches/Quit during file work. Tray hiding retains editors; explicit Quit validates recovery/layout and drains server transfers. Login startup is opt-in and OS-checked. See DESKTOP.md for current limits and pending manual/Mac coverage. Reports distinguish frontend build (default desktop-d7), Electron package version and server build/protocol. [PLATFORM.md](PLATFORM.md) and [DESKTOP.md](DESKTOP.md) own these contracts.

Desktop has a stable vaultor://app origin, per-profile IndexedDB and a persistent installation session owner; browser database/tab records remain unchanged. Profile scopes isolate copied workspace IDs, with workspace/generation keys retained internally. A switch validates destination, checks current identity before saving, flushes changed settings/titles/notes, then strictly writes layout/recovery before activation. Failed note saves permit explicit Keep drafts; settings/storage failures block. Current identity replacement retains drafts separately rather than writing old content to the new workspace. Upload/import dialogs, active exports and native mutations block switching. Old save timers clear on unmount, requests cancel and transient state resets. Relaunch/refresh restores the selected server and working view. Session writes support a strict failure path used by this barrier; browser autosave behavior stays best-effort. No document/archive/API schema change is required by D2.

IndexedDB restores panes, journeys/positions and Library context after refresh. A sessionStorage token plus Web Locks separates tabs; new tabs can seed their own layout. Current notes load before historical visits. Recovery auto-applies only same-tab, same-generation drafts whose server revisions match; others are separate recovery copies. Menus, previews, export dialogs and commands never replay. Snapshots poll changes every 500 ms; workspace identity checks run on focus/every 15 seconds. Undo history remains memory-only. See [SESSIONS.md](SESSIONS.md) for limits and exact contracts.

Design rule: **Simplicity is sophisticated**. Expose primary actions, group secondary actions, and preserve discoverability and basic keyboard access. Collection/create/rename forms use native submission with shared composition guards (`lib/useFormKeyboard.ts`); Enter and clicking submit run the same handler. Synchronous in-flight guards prevent repeat submission; pending name inputs remain read-only/focused and failed values are retained. Collection creation sends the current trimmed name directly to the existing retry-safe server contract, independently of debounced suggestion results; the server resolves uniqueness and uncertain-response retries. Non-submit buttons inside forms explicitly use type=button.

AppModal optionally reads settings so native update/recovery dialogs also work before workspace SettingsProvider mounts; ordinary dialogs retain shared transparency/Escape/focus behavior. Root composition is StrictMode, Redux, application ErrorBoundary, SettingsProvider and EscapeManagerProvider. App mounts Dashboard directly. Redux owns selected-resource highlighting and filters. PaneNavigation owns stable pane IDs, active pane, per-visit histories, bounded reading-position records and navigation requests/errors. Dashboard owns resource caches, previews and modals. SharedNoteDocuments synchronizes live Tiptap documents/undo between views; selections remain per view. See [NAVIGATION.md](NAVIGATION.md). Settings context owns the normalized configuration. The API client converts legacy internal string content into JSON at the HTTP boundary; resourceBrowse/useResourcePage fetch bounded metadata pages through useRetainedQuery. Frontend SearchMode (title | content) joins the retained query key and is omitted from HTTP parameters: title uses GET /resources; nonempty content uses GET /resources/query. Scope/mode changes invalidate stale data, and only content mode renders body excerpts. Same-query background refreshes retain mounted rows; changed queries and workspace replacement clear stale results. Sidebar Recent and mixed Pinned shortcuts each show at most 12 entries; the Library virtualizes 100-entry server pages. Note editors remain mounted while Library is visible, with active focus and close-note shortcut disabled. Detail fetching is independent of the quick-access lists.

Ordinary linked-note clicks replace only their source pane; Ctrl/Cmd-click opens another pane, including duplicate views of one note. Direct opens use replace/split settings and reset the destination trail; an already displayed direct destination focuses that view. At capacity, panes remain intact and Open here offers explicit replacement. Configured capacity is 1–3; lowering it does not silently remove existing panes. Closing is distinct from deletion. Files remain temporary side/modal previews with source focus restoration and never enter note history. Library filtering combines collection, type and all selected tags. Collections is a visible destination with search and New collection. Note headers and file previews show two membership chips plus overflow and a shared Add to collection picker. The same picker serves Library rows and bulk selections of up to 100 resources, with per-toggle pending/error/rollback/retry. Inline creation uses a stable UUID and atomically adds selected members. Collection headers offer Pin and Add resource; More holds rename/delete and management, and deletion keeps resources. Add resource searches titles, immediately adds existing notes/files with per-row feedback, creates notes with atomic initial membership, and hands off imports with the captured destination. Secondary creation permits duplicate titles. Library uses breadcrumbs, compact Search options (type/sort), removable filter chips, and selection-only bulk controls. Creation/import inside the visible collection captures that destination. Pinned combines notes, files and collections, alphabetically ordered, with 12 shortcuts and searchable paged View all. Pin controls appear at each resource and collection. Existing favorite fields remain authoritative; no reset or migration is needed. See [LIBRARY.md](LIBRARY.md) for exact semantics. Ctrl+K defaults to title-only search and Entire workspace on each opening, with deduplicated Open/Pinned/Recent items. Search options enables saved note text and collection scope; global title mode includes collection-name matches, while scoped mode lists only member resources. Library starts title-only and uses its current collection, with query-preserving scope changes updating the destination/breadcrumb. Commands mode uses > or a visible button. Actions name the selected resource; captured focus/Library selection determines command targets, never hidden notes. Errors retain input, in-flight actions cannot repeat, Tab remains native focus navigation: Actions follows the palette input in DOM order while CSS retains its footer position. Tab focuses Actions, Enter/Space activates it, and Shift+Tab returns to input. Escape returns one step with the previous highlighted resource/query restored. Files preview only on explicit opening. See SEARCH.md for limits, index lifecycle and diagnostics.

Backlinks appear only on request through the journey bar's **Linked from** menu for the focused note. Opening a linked or sidebar note never adds an automatic backlinks column or squeezes the editors. Results are associated with the fetched note so stale backlinks do not flash after activation. Inline resource references use a soft theme-aware background, restrained underline and small type icon, with explicit keyboard focus; stored labels and navigation semantics are unchanged.

One shared, stable-height journey bar above the note workspace displays the focused pane's full trail, with Back/Forward and a full-path overflow. Short paths show every step when space allows; longer paths scroll horizontally, revealing the current step on navigation and resize. Narrow layouts retain scroll access and the keyboard-accessible full-path overflow instead of forcibly hiding neighboring visits. Escape dismisses it and restores trigger focus; leaving for Library unmounts the bar and its portal. Each visit has an independent ID, so A → B → A preserves distinct scroll/caret positions. A linked new pane copies the path and positions with fresh IDs; subsequent history is independent. Returning preserves forward visits until a new linked navigation branches. Histories and their position records are bounded to 200 visits per pane. Scroll recording does not rerender the workspace. Revisiting restores scroll and clamped document selection without remounting a same-note editor. Local renames and loaded resource titles update trail labels without rewriting stored link labels. Deleted/404 destinations remain unavailable steps; transient errors retain Retry and leave the cursor unchanged. Adjacent unavailable visits disable Back/Forward; other valid visits remain reachable from overflow. Forward/back use directional 200 ms smooth or 100 ms snappy transitions, pane changes crossfade, and reduced motion disables animation. Typing, saves and title updates do not replay transitions.

SaveCoordinator holds latest title/content per note, debounces and serializes writes, coalesces newer edits, and exposes Saving / Saved / Save failed with Retry. The title bar has a compact status icon at the top right (spinner/check/cloud alert), hover/focus tooltip, accessible status announcement and clickable retry on failure. Editor editability changes do not emit content updates or queue saves. Title actions wrap below the title in narrow panes. Editor changes reach the coordinator immediately so unmount cannot silently discard a debounce. Pane closing/replacement and history navigation flush only the departing note, including title edits; unrelated save failures cannot block them. Deletion and workspace transfers retain their existing save barriers. Navigation loads and source saves commit before changing a pane; stale requests cannot navigate and failures provide Retry. The configured close-note shortcut is registered in the window capture phase by lib/closeNoteShortcut.ts so ProseMirror cannot swallow it at empty document boundaries. Only this action is reserved; ordinary editor keys remain untouched. Composition, dialogs/modal overlays and fullscreen suppress closing; held/repeated keys and an in-flight close cannot close additional panes. The action still calls the existing save barrier, leaving failed drafts visible for retry. Import clears all stale draft caches after refresh. beforeunload warns while notes/staged titles are dirty or journal writes remain outstanding. NoteRecovery writes versioned local recovery records; conditional server saves acknowledge only their matching version. Conflicts preserve drafts with recovered-copy/saved-version choices. IndexedDB storage failures remain visible and do not block server saving; abrupt termination cannot be guaranteed safe. See [SESSIONS.md](SESSIONS.md).

Application and independent editor/settings/preview/transfer/diagnostics boundaries show recovery UI and copyable diagnostic details. Regional recovery preserves sibling editor state. Action/network failures normally show a banner. Background browsing and recency failures retain diagnostics/request IDs but use local retry feedback, avoiding a global banner during navigation. Settings writes are serialized with visible failure/retry. Preview requests abort/ignore stale results and clean up object URLs. Diagnostic delivery failures never trigger further diagnostic requests or break UI: queue 100, batch 20, three delivery attempts, local history 100; backend history 200 events/24 hours/process lifetime.

## Editor and content contracts

`BlockEditor` composes StarterKit (with custom code block), headings 1-3, placeholder, Lowlight code block React node view, resizable tables, highlight, nested tasks, underline, slash commands, resource links, and symbol replacement. Existing marks include bold, italic, strike, inline code, underline, and highlight.

Slash menu actions: Text, Heading 1/2/3, Bullet List, Numbered List, Task List, Code Block, Quote, Divider, Highlight, Insert Symbol, Table, Link Resource, Upload Markdown, Upload CSV as Table. Symbol candidates are sourced from `lib/symbols.ts`. `:symbol_name:` converts on space/Enter; punctuation patterns such as `->`, `=>`, `<=`, `!=`, `...`, and `--` convert on space.

Inline links are atomic Tiptap nodes:

```json
{"type":"resourceLink","attrs":{"resourceId":"uuid","label":"Resource title","type":"note"}}
```

The `[[` picker searches resources and offers note creation/file upload. Preserve the `resourceLink` node name and `resourceId` attribute when evolving editor schemas: backend backlink extraction depends on them. The displayed label is stored in the node, not dynamically joined to a resource title. ResourceLinkView uses a native focusable button and per-editor registration with explicit source pane and here/new destination; both inline link opening and [[ picker arrow navigation avoid last-mounted-editor globals.

All ordinary upload entry points (sidebar/palette, slash Markdown/CSV and inline resource links) use `lib/filePicker.ts`. It creates a temporary connected input, releases editable focus, waits for Enter/Space release if called during keydown, and cleans up on change/cancel. Menus close before opening. Native Windows/Vivaldi pointer visibility remains unverified: component tests establish event ordering, not OS pointer behavior.

Slash actions read the current plugin range at invocation. `lib/importTarget.ts` captures the originating editor, maps its command range through unrelated edits and rejects changed/closed targets. Cancellation never deletes the command. Successful insertion replaces the complete range as one undoable edit after review. Inline-resource keyboard executors are keyed by editor view so uploads cannot target another pane. Focus restoration registers on mount/create and unregisters on unmount; never read view.dom before mounting.

Current cross-component bridges include `window.__vaultor_editor`, `__openResource`, `__executeResourceLink`, `__executeSlashCommand`, and a per-editor `__slashCommandExecutors` map. Multi-pane changes must preserve correct editor ownership and cleanup; replacing these bridges requires coordinated edits, not a single call-site change. `BlockEditor` is memoized with a custom comparison; new props may require comparator updates.

Markdown paste detection converts text using `marked` with GFM, then inserts HTML into Tiptap. Slash Markdown upload inserts into the captured originating editor after review and does not create a binary resource. `tiptapToMarkdown` is a best-effort helper, not a lossless serialization format for all supported nodes.

CSV editor import both uploads a file resource and inserts a table. The custom parser handles comma/tab/semicolon delimiters, quoted fields, BOM/newline normalization, and pads uneven rows. It validates content against the editor schema, falling back to a resource link plus code block/text. Imported table attrs retain `sourceResourceId`, `sourceResourceTitle`, `sourceResourceType`; these are not themselves `resourceLink` nodes and do not produce graph edges. File CSV preview separately uses Papa Parse.

Tables use WorkspaceTable.ts, TableControls.tsx and tableCommands.ts in the editor directory. In-note editing of the selected table in the active pane has a compact floating toolbar: Row, Column, Filter, Expand and More. It is a portal outside note layout, aligned above the table's right edge when space allows, otherwise following its visible upper edge within its own pane. It disappears offscreen; narrow panes use icon-only buttons with accessible hover labels. Repeated row/column edge buttons are removed in both views. Row/Column actions target the clicked cell/current range; opening menus preserves selection. Explicit Select row/Select column actions remain available, with affected indices shown in menu headings. Row/column menus provide structural operations, headers and sizing; More contains merge/split, copy/export, undo/redo, help and confirmed whole-table deletion. Filter and copy/export have separate popovers with local feedback. Local destructive/structural restrictions while filtered remain unchanged. ## Ordinary file imports — Sprint 1

The sidebar/palette Import files action offers multi-file review, per-file note/original-file selection and Apply to similar files. Markdown defaults to a formatted note, TXT to a plain note; source/code/JSON/YAML/logs and CSV/TSV default to original files with code-note/table-note alternatives. Other text MIME types offer code-note conversion. PDF/image/Office files remain original resources. Import workspace is the separate ZIP workflow.

`lib/fileImports.ts` performs conversion; `components/modals/FileImportModal.tsx` owns ready/pending/imported/failed states. Text-to-note imports cap at 5 MiB and accept strict UTF-8 or BOM-marked UTF-16. Invalid encoding/binary text fails before creation; original-file import remains available. Inert Markdown parsing preserves images and local/unsupported links as text references with review warnings, without automatic asset fetching. CSV rejects unclosed quotes, preserves internal empty rows and caps conversion at 10,000 rows, 500 columns and 50,000 cells. Sidebar CSV-to-note creates no extra binary; slash CSV retains its source resource.

Retry skips successful rows and reuses each row's UUID. `PUT /api/resources/imports/{id}` accepts multipart title plus either file or content (serialized structured doc). `FileImportService` hashes the original payload, stores an internal `Resource.importFingerprint` and commits metadata/backlinks transactionally. Identical retries return the same resource; changed-payload reuse returns 409. Duplicate titles create separate IDs. Fingerprints are excluded from DTOs/workspace archives; occupied IDs after restore are never overwritten. If an uploaded CSV asset is followed by an invalid insertion target, the original file remains available in the sidebar and retry does not duplicate it.

## Settings and keyboard behavior

Settings are persisted in `settings.app_settings_v2` as one JSON document:

```json
{
  "workspace": {"maxOpenNotes":2,"openBehavior":"split","autosaveDelay":0,"focusMode":false},
  "local": {"<device-id>": {"theme":"os","accentColor":"blue","density":"comfortable","animationMode":"snappy","previewMode":"side","sidebarMode":"fixed","uiTransparency":0.85,"sidebarCollapsed":false}},
  "keybindings": {"commandPalette":{"mac":"Mod+K","windows":"Mod+K"}}
}
```

Workspace values are shared. `maxOpenNotes` is clamped 1-3; autosave delay is nonnegative milliseconds. Local appearance is **stored on the backend under a device ID**, not solely in browser storage. `vaultor_device_id` is retained in localStorage; clearing it selects a different settings entry. Keybinding overrides are scoped by platform (`mac` / `windows`, with non-Mac using Windows bindings), with defaults resolved for absent overrides.

Ctrl+Arrow word movement and Ctrl+Shift+Arrow word selection remain available. Mod means Ctrl on Windows and Cmd on macOS; Alt means Option on macOS. Alt+Arrow switches open notes (Option+Arrow on Mac). The original Mod+Arrow, Sprint 2 Mod+Alt+PageUp/PageDown and conflicting persisted Mod+Alt+Arrow bindings migrate in frontend/backend normalization; other custom shortcuts survive.

Sidebar defaults to Ctrl+Alt+B / Cmd+Option+B, leaving Bold and Quote intact inside the editor. Frontend/backend normalization migrate only the former sidebar Mod+B value; an identical custom value cannot be distinguished and also migrates. Other custom values survive. New Bold/Quote conflicts are rejected with guidance. Mac Option-letter matching uses physical letter codes; composition events do not trigger workspace actions. Help/settings derive labels from the shared definitions.

Backend settings migrate legacy `workspace_settings`; frontend migrates `vaultor_local_settings` and `vaultor_sidebar_collapsed`. Keep normalization/defaults aligned between TypeScript and Java. Frontend writes optimistic leaf patches through a serialized queue and rejects stale read/write responses. Failed leaves remain pending with Retry; incoming refresh waits for outstanding writes. Workspace operations flush settings first. `PATCH /settings` merges transactionally into the latest document; different fields are preserved, same-field writes are last committed wins. Full-document PUT is local legacy only. See [MULTI-DEVICE.md](MULTI-DEVICE.md) for patch bounds and revision requirements on HTTPS note saves.

## Workspace transfer and export foundation

Individual note export format buttons immediately save the target note, prepare an immutable export and automatically request its download. Dashboard keeps NoteExportModal and its NoteExportController mounted independently of picker visibility; the picker closes automatically after download handoff, with Download again retained in a compact status card. One active/unresolved export at a time prevents duplicate clicks. Bounded status retries and download retries retain the operation; confirmed preparation failure or a definite pre-operation graph conflict offers a fresh save/snapshot attempt. Ambiguous creation failures require inspection rather than automatic resubmission. Download again is available, conversion warnings and IDs are disclosures, and no browser-save success is claimed. Reload stops frontend tracking; it does not replay old downloads. Workspace identity/generation changes dispose the export controller; import closes stale export/title UI. See NOTE-EXPORTS.md for lifecycle and limitations.

TransferService orchestrates one persisted-operation worker. WorkspaceExporter separates archive rendering; ExporterRegistry enables workspace/zip and notes/md, md-assets, pdf, docx. Scope definitions also reserve notes and table. DocumentService validates node/mark shapes separately from attribute objects (ordered lists legitimately have attrs.type=null) and traverses blocks, marks, links, tables and asset reference attributes; renderers consume structured documents, not editor HTML. NoteExporter registrations and NoteRenderer implement standalone and outgoing-graph export; see [NOTE-EXPORTS.md](NOTE-EXPORTS.md) for API, fidelity and limits.

Note export defaults to This note; Include linked resources previews counts, saves only participants, and validates the final graph fingerprint under the mutation gate. NoteExportGraph follows recognized structured outgoing references breadth-first, deduplicates cycles, excludes backlinks and bounds nodes/depth/document-and-binary bytes. Changed membership after saving requires review. Graph Markdown is a ZIP of relative-linked note files; PDF/Word use combined sections and internal destinations/bookmarks, packaged with original files when present. Reading content uses labels rather than resource UUIDs; optional references identify omissions, while export.json carries package traceability. Reading packages are distinct from workspace archives. No document/database/session schema changed. See NOTE-EXPORTS for precise limits, contracts and known fidelity restrictions.

ZIP version 2 contains manifest.json (version, creation time, counts, SHA-256 checksums), workspace.json (logical resources/tags/workspace settings plus organization: collections, memberships and resource/collection favorites), and files/{resource-id}. No live SQLite file, credentials, diagnostics or device appearance/keybindings are exported. JSON entries cap at 20 MiB, archive defaults to 512 MiB, expanded data 2 GiB and 20,000 entries. Configure limits through environment variables; malformed paths, duplicate entries, checksums, counts and document/reference shapes are validated before mutation. Missing document targets appear as preview warnings.

Preview stages the upload. Merge generates a new resource graph and rewrites both inline links and table source IDs; same-name tags reuse existing colors and workspace settings stay unchanged. Replace requires explicit confirmation and replaces resources/tags/files/workspace settings while retaining local appearance and keybindings. Both derive backlinks from documents. Merge remaps collection members to newly allocated resource IDs, unifies collections by normalized name and preserves existing collection favorites. Replace restores archived collection IDs and all favorites. Organization validates before mutation and restores within the metadata transaction. Plain version 1 archives remain readable without organization. Repeating a commit returns the original operation, never applies twice; to retry a failed commit upload/preview again.

Before the DB transaction, imported binaries are copied under unique names and their names journaled. Metadata changes and the obsolete-file cleanup journal commit in one transaction. Old binaries are deleted only after commit. Restart marks interrupted queued/running operations failed and removes unreferenced staging; CLEANUP resumes idempotently. Rollback preserves existing metadata and binaries. Cancellation is allowed at preview/queue and during import preparation, but never after the commit phase begins. Progress is phase-based, not byte-level. UI refreshes after completion without timed reload or backend exit.

Future work: table XLSX/PDF and separately connected Google Docs publishing. Individual note Markdown/PDF/DOCX export is implemented. Do not expose unfinished formats as selectable. Artifact/staging directories currently remain until manually cleaned with the backend stopped; automatic transfer-artifact expiry is a follow-up.

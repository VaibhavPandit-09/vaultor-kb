## Product and architecture

Vaultor is a personal, locally hosted knowledge workspace. Notes and uploaded files are resources, organized by flat collections and tags and connected through inline links. The desktop opens its owned workspace directly; browser access uses a local owner handoff or host-approved LAN device session. There are no accounts, master passwords, note lock controls, note/archive encryption, or encrypted archive compatibility. D5 adds owner/device access credentials separately from workspace data. Obsolete credentials stored in an existing database are ignored; startup does not delete resources.

React 19 + TypeScript 5.9 + Vite 8 + Tailwind 3 + Redux + Tiptap 3 call Spring Boot 4 / Java 25 through a shared Axios client at /api. Spring Data JPA stores metadata and serialized Tiptap documents in SQLite; file bytes live separately on disk. Hikari uses one connection to serialize application transactions and avoid concurrent SQLite read-to-write lock upgrades; reads also queue, so keep transactions short. Backend JSON uses Jackson 3 tools.jackson. Exact versions are in the package lock and pom.xml. Vite proxies /api and /access to 127.0.0.1:8080 on fixed port 5173; only exact loopback development Origins are rewritten. Docker embeds the frontend in the Spring JAR and serves one origin.

The backend is authoritative. This is not an offline browser database or a synchronization system. Docker publishes to loopback by default. Host-approved LAN access is explicit and off by default; never expose this personal deployment publicly or bypass device approval for debugging.

## Agent-owned release delivery

Installed-app changes are not complete at a development build: agents own version/package-lock bumps, fresh UI plus embedded browser/server builds, focused/native target checks, original-key-signed artifact pairs, source commits/tags, GitHub draft assets and publication under [RELEASE-PROCESS.md](desktop/RELEASE-PROCESS.md). The user-facing exact Windows/Mac/browser/Docker/Ubuntu status and update steps are in [INSTALLATION-AND-UPDATES.md](desktop/INSTALLATION-AND-UPDATES.md). Documentation/test-only changes with no shipped behavior do not require installers. `desktop/scripts/release-artifacts.mjs` verifies installer identity/size/checksum; `publish-release.mjs` defaults to dry-run and requires a clean source tree and matching pushed tag for draft upload, preserving existing assets. Explicit --add-platform permits a missing verified platform pair on an existing published release and byte-identical retries; differing assets are rejected, and the original source tag remains immutable. It does not certify native validation or publish a draft automatically. GitHub Releases are the default public update source. Updates checks on opening and once after normal installed startup, selecting the highest stable complete per-platform pair from at most 100 records. Bounded credential-free GitHub asset redirects are supported; custom feeds still reject redirects. Installed Windows uses one Update and restart action, verified download/save/backup, a hidden parent-waiting silent installer helper and relaunch. Manual import is Advanced; development/portable/Mac replacement remains explicitly manual. No CI key storage or paid feed is configured. Missing native Mac access/original key/verification must be reported, not presented as a successful release.

## Data model and persistence

| Entity | Contract |
| --- | --- |
| Resource / resources | UUID string id, type note/file, title, serialized content, filePath, MIME, size, createdAt/updatedAt/lastOpenedAt, favorite, internal optimistic revision_number/revision_seed, nullable trashed_at/purge_pending/trash_organization, many-to-many tags and collections |
| ResourceCollection / collections | UUID id, display name, unique normalized_name, favorite, internal creationFingerprint for retry-safe creation; resource_collections joins resources to multiple collections |
| Tag / tags | UUID id, normalized unique name, persistent color |
| Relationship / relationships | fromId/toId/type=link, derived from resourceLink and image nodes; IDs are plain strings |
| Setting / settings | key_name/value; app_settings_v2 holds workspace/local/keybindings |
| resource_fts | Derived SQLite FTS5 resource titles/visible saved-note and extracted supported file text; resource triggers maintain transactional consistency; startup/Diagnostics rebuild in gated batches |
| file_search | Derived bounded saved-file text/status/hash keyed by resource version and workspace generation; subprocess decoding, no archive inclusion |
| LifecycleRequest | Durable per-item operation ID/resource/action/expected revision/result, including irreversible purge cleanup and completed purge tombstones; nonportable |
| TransferOperation | persisted kind, status, phase, progress, mode, detail, requestId, timestamps, cleanup journal |

SQLite uses Hibernate ddl-auto=update with hibernate.hbm2ddl.jdbc_metadata_extraction_strategy=individually; there is no versioned migration framework. Individual inspection is required because existing SQLite FTS5/shadow tables expose untyped columns that crash Hibernate grouped metadata extraction on restart. Keep schema updates enabled and leave the derived search tables/data intact. Resource DTOs omit internal file paths and expose note content as a JSON object (never a JSON-encoded string). Entity persistence still stores content as text. Dates use LocalDateTime without a timezone suffix. Opening a resource updates only lastOpenedAt through a metadata SQL write; it does not change updatedAt or hydrate/save its document. Some tag mutations can still change updatedAt, so it is not strictly a content timestamp. Import preserves archived IDs on replacement and allocates new IDs on merge.

ResourceService saves the note and rebuilds outgoing link relationships transactionally. LinkExtractionService extracts resourceLink/image attrs.resourceId; table sourceResourceId is checked/remapped by DocumentService but is not a backlink edge. The former replace-links-and-delete and hard-delete routes are retired (405). Trash retains incoming labels and placements without rewriting referring notes; permanent deletion runs only through revision-checked durable cleanup in Trash. The read-only integrity API reports missing targets. Tag names trim/lowercase and unify case-insensitively; default colors are deterministic. FileStorageService confines paths to its configured directory.

## Backend and API contracts

Use [API.md](development/API.md) for flows and /api/openapi.json for the machine contract. The same APIs serve agents and UI, without a privileged execution interface. Explicit DTOs cover resources, tags, settings and operations. List responses include items/page/size/totalItems/totalPages (size 1–200). Browsing returns metadata-only summaries with title/collection/type/all-selected-tags/favorites filters and recent/updated/title sorting. GET /resources/query supplies relevance-ranked saved note/title/supported PDF and UTF-8 file search with scoped coverage with metadata and safe snippets (size 1–100); legacy /resources/search still caps title matches at 50. See SEARCH.md for search/index contracts. GET resource detail supplies document content. Resource details and list summaries include collections [{id,name}]; list enrichment batches tags and collections without reading documents. PUT /resources/{id}/favorite persists a boolean without changing modification time. GET /organization/pins pages mixed shortcuts with optional kind filtering and appliedKind acknowledgment, batching optional resource summaries; POST /organization/selection reads membership counts for selected IDs. PUT /collections/creations/{id} creates once with initial members, and optional collectionId on note creation/file imports assigns membership transactionally. See [Library workflows](workspace/LIBRARY.md).

Resource details expose an opaque revision; the UI sends quoted If-Match on note updates, returning 412 NOTE_REVISION_CONFLICT for stale writes. JPA optimistic locking guards concurrent updates. GET /workspace/identity returns persistent identity/replacement generation; generation changes inside the replacement transaction. Internal identifiers are excluded from portable archives.

All API responses carry X-Request-ID. Errors use problem details with status, code, detail, fieldErrors and requestId. Default logs contain request method/path/status/duration and mutation outcomes, not complete request payloads, note bodies or binary contents. Unexpected failures include stack traces. Frontend boundaries and network errors retain diagnostic references and correlate server request IDs.

D1 capabilities explicitly expose serverBuild, apiProtocolVersion and minimumClientProtocolVersion; current protocol and minimum client protocol are 3 for managed-image editing and safe resource lifecycle operations. Old clients are refused before editor mounting; update both client and host. BuildInformation uses BUILD_VERSION (default desktop-d1) consistently for capabilities/health and request/transfer logs. The client uses VITE_BUILD_VERSION separately. Deploy frontend/backend together; the UI intentionally rejects old servers lacking compatibility metadata before mounting settings/workspace. Details and examples: [API.md](development/API.md).

RequestLoggingFilter supplies correlation/logging around HostAccessFilter. Only approved requests reach WorkspaceRequestFilter's shared gate for resource/tag/settings/collection/organization calls. Transfers take the exclusive gate during snapshot/commit and search rebuild takes it per batch of 100, and concurrent approved calls receive 409 WORKSPACE_BUSY. The gate is process-local: run a single backend against a data directory. Health requires approval and reports readiness/busy state; integrity checks never repair data. Compose rotates JSON logs at three 10 MiB files; desktop logs retain their existing bounded ring/disk rotation.

Design rule: **Simplicity is sophisticated**. Expose primary actions, group secondary actions, and preserve discoverability and basic keyboard access. Page headings share a flexible title and right-aligned action group aligned with the search/list edge; long titles and action groups wrap within their actual available width. Reserve native chrome only where it overlaps content: desktop Library/Collections/Pinned pages use a 40px top inset and a separate top-edge drag region, not a whole-heading right spacer. Journey controls retain their overlapping chrome reservation. Check long titles, narrow layouts, empty versus filtered states, and both themes when changing page layouts. Collection/create/rename forms use native submission with shared composition guards (`lib/useFormKeyboard.ts`); Enter and clicking submit run the same handler. Synchronous in-flight guards prevent repeat submission; pending name inputs remain read-only/focused and failed values are retained. Collection creation sends the current trimmed name directly to the existing retry-safe server contract, independently of debounced suggestion results; the server resolves uniqueness and uncertain-response retries. Non-submit buttons inside forms explicitly use type=button.

AppModal optionally reads settings so native update/recovery dialogs also work before workspace SettingsProvider mounts; ordinary dialogs retain shared transparency/Escape/focus behavior. PaneNavigation owns stable pane IDs, active pane, per-visit histories, bounded reading-position records and navigation requests/errors. Dashboard owns resource caches, previews and modals. Short paths show every step when space allows; longer paths scroll horizontally, revealing the current step on navigation and resize. Narrow layouts retain scroll access and the keyboard-accessible full-path overflow instead of forcibly hiding neighboring visits. Escape dismisses it and restores trigger focus; leaving for Library unmounts the bar and its portal. Each visit has an independent ID, so A → B → A preserves distinct scroll/caret positions. A linked new pane copies the path and positions with fresh IDs; subsequent history is independent. Returning preserves forward visits until a new linked navigation branches. Histories and their position records are bounded to 200 visits per pane. Scroll recording does not rerender the workspace. Revisiting restores scroll and clamped document selection without remounting a same-note editor. Local renames and loaded resource titles update trail labels without rewriting stored link labels. Deleted/404 destinations remain unavailable steps; transient errors retain Retry and leave the cursor unchanged. Adjacent unavailable visits disable Back/Forward; other valid visits remain reachable from overflow. Forward/back use directional 200 ms smooth or 100 ms snappy transitions, pane changes crossfade, and reduced motion disables animation. Typing, saves and title updates do not replay transitions.

SaveCoordinator holds latest title/content per note, debounces and serializes writes, coalesces newer edits, and exposes Saving / Saved / Save failed with Retry. The title bar has a compact status icon at the top right (spinner/check/cloud alert), hover/focus tooltip, accessible status announcement and clickable retry on failure. Editor editability changes do not emit content updates or queue saves. Title actions wrap below the title in narrow panes. Editor changes reach the coordinator immediately so unmount cannot silently discard a debounce. Pane closing/replacement and history navigation flush only the departing note, including title edits; unrelated save failures cannot block them. Deletion and workspace transfers retain their existing save barriers. Navigation loads and source saves commit before changing a pane; stale requests cannot navigate and failures provide Retry. The configured close-note shortcut is registered in the window capture phase by lib/closeNoteShortcut.ts so ProseMirror cannot swallow it at empty document boundaries. Only this action is reserved; ordinary editor keys remain untouched. Composition, dialogs/modal overlays and fullscreen suppress closing; held/repeated keys and an in-flight close cannot close additional panes. The action still calls the existing save barrier, leaving failed drafts visible for retry. Import clears all stale draft caches after refresh. beforeunload warns while notes/staged titles are dirty or journal writes remain outstanding. NoteRecovery writes versioned local recovery records; conditional server saves acknowledge only their matching version. Conflicts preserve drafts with recovered-copy/saved-version choices. IndexedDB storage failures remain visible and do not block server saving; abrupt termination cannot be guaranteed safe. See [SESSIONS.md](workspace/SESSIONS.md).

Application and independent editor/settings/preview/transfer/diagnostics boundaries show recovery UI and copyable diagnostic details. Regional recovery preserves sibling editor state. Action/network failures normally show a banner. Background browsing and recency failures retain diagnostics/request IDs but use local retry feedback, avoiding a global banner during navigation. Settings writes are serialized with visible failure/retry. Preview requests abort/ignore stale results and clean up object URLs. Diagnostic delivery failures never trigger further diagnostic requests or break UI: queue 100, batch 20, three delivery attempts, local history 100; backend history 200 events/24 hours/process lifetime.

Shared motion is installed once by main.tsx, using finite Web Animations/CSS helpers, device motion tokens and semantic surface markers. Smooth spans dialogs/popovers, previews, settings categories, selection markers, sidebar disclosure, browsing entrances, image/editor menus and action feedback; Snappy remains brief. Exit visuals are inert clones without IDs/roles/focus or React ownership; actual surfaces and Escape/focus registration close immediately. Initial row reveals cap at six and do not replay on query/refresh/save. Reduced motion cancels running work and removes translation/scale/stagger. Mounted editors, selection and network/save ownership are unchanged. [MOTION.md](workspace/MOTION.md) owns the extension and lifecycle rules.

## Ordinary file imports — Sprint 1

The sidebar/palette Import files action offers multi-file review, per-file note/original-file selection and Apply to similar files. Markdown defaults to a formatted note, TXT to a plain note; source/code/JSON/YAML/logs and CSV/TSV default to original files with code-note/table-note alternatives. Other text MIME types offer code-note conversion. PDF/image/Office files remain original resources. Import workspace is the separate ZIP workflow.

`lib/fileImports.ts` performs conversion; `components/modals/FileImportModal.tsx` owns ready/pending/imported/failed states. Text-to-note imports cap at 5 MiB and accept strict UTF-8 or BOM-marked UTF-16. Invalid encoding/binary text fails before creation; original-file import remains available. Inert Markdown parsing preserves images and local/unsupported links as text references with review warnings, without automatic asset fetching. CSV rejects unclosed quotes, preserves internal empty rows and caps conversion at 10,000 rows, 500 columns and 50,000 cells. Sidebar CSV-to-note creates no extra binary; slash CSV retains its source resource.

Retry skips successful rows and reuses each row's UUID. `PUT /api/resources/imports/{id}` accepts multipart title plus either file or content (serialized structured doc). `FileImportService` classifies recognized file signatures with bounded inspection, hashes the original payload, stores an internal `Resource.importFingerprint` and commits metadata/backlinks transactionally. Identical retries return the same resource; changed-payload reuse returns 409. Duplicate titles create separate IDs. Fingerprints are excluded from DTOs/workspace archives; occupied IDs after restore are never overwritten. If an uploaded CSV asset is followed by an invalid insertion target, the original file remains available in the sidebar and retry does not duplicate it.

## Settings and keyboard behavior

Settings are persisted in `settings.app_settings_v2` as one JSON document:

```json
{
  "workspace": {"maxOpenNotes":2,"openBehavior":"split","autosaveDelay":0,"focusMode":false},
  "local": {"<device-id>": {"theme":"os","accentColor":"blue","density":"comfortable","animationMode":"snappy","previewMode":"side","sidebarMode":"fixed","uiTransparency":0.85,"sidebarCollapsed":false,"sidebarSections":{"pinned":{"visible":true,"collapsed":false},"recent":{"visible":true,"collapsed":false},"tags":{"visible":true,"collapsed":false}}}},
  "keybindings": {"commandPalette":{"mac":"Mod+K","windows":"Mod+K"}}
}
```

Workspace values are shared. `maxOpenNotes` is clamped 1-3; autosave delay is nonnegative milliseconds. Local appearance is **stored on the backend under a device ID**, not solely in browser storage. `vaultor_device_id` is retained in localStorage; clearing it selects a different settings entry. Keybinding overrides are scoped by platform (`mac` / `windows`, with non-Mac using Windows bindings), with defaults resolved for absent overrides.

Ctrl+Arrow word movement and Ctrl+Shift+Arrow word selection remain available. Mod means Ctrl on Windows and Cmd on macOS; Alt means Option on macOS. Alt+Arrow switches open notes (Option+Arrow on Mac). The original Mod+Arrow, Sprint 2 Mod+Alt+PageUp/PageDown and conflicting persisted Mod+Alt+Arrow bindings migrate in frontend/backend normalization; other custom shortcuts survive.

Sidebar defaults to Ctrl+Alt+B / Cmd+Option+B, leaving Bold and Quote intact inside the editor. Frontend/backend normalization migrate only the former sidebar Mod+B value; an identical custom value cannot be distinguished and also migrates. Other custom values survive. New Bold/Quote conflicts are rejected with guidance. Mac Option-letter matching uses physical letter codes; composition events do not trigger workspace actions. Help/settings derive labels from the shared definitions.

Backend settings migrate legacy `workspace_settings`; frontend migrates `vaultor_local_settings` and `vaultor_sidebar_collapsed`. Keep normalization/defaults aligned between TypeScript and Java. sidebarSections normalizes the three known sections to visible/expanded on older installations; partial leaf patches preserve siblings. Preferences are device-specific and excluded from portable archives. A host must run 0.3.0 or later to persist these new fields; older hosts normalize them away. Frontend writes optimistic leaf patches through a serialized queue and rejects stale read/write responses. Failed leaves remain pending with Retry; incoming refresh waits for outstanding writes. Workspace operations flush settings first. `PATCH /settings` merges transactionally into the latest document; different fields are preserved, same-field writes are last committed wins. ## Workspace transfer and export foundation

Individual note export format buttons immediately save the target note, prepare an immutable export and automatically request its download. Dashboard keeps NoteExportModal and its NoteExportController mounted independently of picker visibility; the picker closes automatically after download handoff, with Download again retained in a compact status card. One active/unresolved export at a time prevents duplicate clicks. Bounded status retries and download retries retain the operation; confirmed preparation failure or a definite pre-operation graph conflict offers a fresh save/snapshot attempt. Ambiguous creation failures require inspection rather than automatic resubmission. Download again is available, conversion warnings and IDs are disclosures, and no browser-save success is claimed. Reload stops frontend tracking; it does not replay old downloads. Workspace identity/generation changes dispose the export controller; import closes stale export/title UI. See NOTE-EXPORTS.md for lifecycle and limitations.

TransferService orchestrates one persisted-operation worker. WorkspaceExporter separates archive rendering; ExporterRegistry enables workspace/zip and notes/md, md-assets, pdf, docx. Scope definitions also reserve notes and table. DocumentService validates node/mark shapes separately from attribute objects (ordered lists legitimately have attrs.type=null) and traverses blocks, marks, links, tables and asset reference attributes; renderers consume structured documents, not editor HTML. NoteExporter registrations and NoteRenderer implement standalone and outgoing-graph export; see [NOTE-EXPORTS.md](workspace/NOTE-EXPORTS.md) for API, fidelity and limits.

Note export defaults to This note; Include linked resources previews counts, saves only participants, and validates the final graph fingerprint under the mutation gate. NoteExportGraph follows recognized structured outgoing references breadth-first, deduplicates cycles, excludes backlinks and bounds nodes/depth/document-and-binary bytes. Changed membership after saving requires review. Graph Markdown is a ZIP of relative-linked note files; PDF/Word use combined sections and internal destinations/bookmarks, packaged with original files when present. Reading content uses labels rather than resource UUIDs; optional references identify omissions, while export.json carries package traceability. Reading packages are distinct from workspace archives. No document/database/session schema changed. See NOTE-EXPORTS for precise limits, contracts and known fidelity restrictions.

ZIP version 3 contains manifest.json (version, creation time, counts, SHA-256 checksums), workspace.json (logical resources including Trash/timestamps/restoration labels, tags/workspace settings plus organization: collections, memberships and resource/collection favorites), and files/{resource-id}. No live SQLite file, credentials, diagnostics or device appearance/keybindings are exported. JSON entries cap at 20 MiB, archive defaults to 512 MiB, expanded data 2 GiB and 20,000 entries. Configure limits through environment variables; malformed paths, duplicate entries, checksums, counts and document/reference shapes are validated before mutation. Missing document targets appear as preview warnings.

Preview stages the upload. Merge generates a new resource graph and rewrites both inline links and table source IDs; same-name tags reuse existing colors and workspace settings stay unchanged. Replace requires explicit confirmation and replaces resources/tags/files/workspace settings while retaining local appearance and keybindings. Both derive backlinks from documents. Merge remaps collection members to newly allocated resource IDs, unifies collections by normalized name and preserves existing collection favorites. Replace restores archived collection IDs and all favorites. Organization validates before mutation and restores within the metadata transaction. Plain version 1 archives remain readable without organization. Repeating a commit returns the original operation, never applies twice; to retry a failed commit upload/preview again.

Before the DB transaction, imported binaries are copied under unique names and their names journaled. Metadata changes and the obsolete-file cleanup journal commit in one transaction. Old binaries are deleted only after commit. Restart marks interrupted queued/running operations failed and removes unreferenced staging; CLEANUP resumes idempotently. Rollback preserves existing metadata and binaries. Cancellation is allowed at preview/queue and during import preparation, but never after the commit phase begins. Progress is phase-based, not byte-level. UI refreshes after completion without timed reload or backend exit.

Future work: table XLSX/PDF and separately connected Google Docs publishing. Individual note Markdown/PDF/DOCX export is implemented. Do not expose unfinished formats as selectable. Artifact/staging directories currently remain until manually cleaned with the backend stopped; automatic transfer-artifact expiry is a follow-up.

## Known limitations

- Browser storage is origin-specific and best-effort; session snapshots can lag by 500 ms, shared undo is not persisted, and old session records have no automatic expiry. Native multi-tab/refresh lifecycle verification remains N6; see SESSIONS.md.
- Scoped settings preserve concurrent changes to different fields; same-field edits remain last committed wins. There is no collaborative typing or multi-instance SQLite/gate coordination. Saved-state streams reconcile clean notes, preserve drafts and use existing revision conflicts; prolonged/multi-machine fault testing remains D9.
- Library uses bounded metadata pages and virtual rows; saved-note/title search uses a derived FTS5 index; file-content search and broad performance checks remain deferred. Collections, paginated organization management, page-scoped bulk membership/tag updates and archive portability of favorites are implemented. Sidebar tag chips and note tag pickers still load the complete tag list. Broad scale verification is Sprint 6. Transfer snapshot memory remains unbounded by streaming.
- PDF/text preview cap is 1 MiB; supported image preview is 20 MiB/40 MP. Table XLSX/PDF and Google Docs exports remain future work. Note export fidelity and DOCX visual-validation limits are documented in NOTE-EXPORTS.md.
- Settings contains keyboard focus and restores it on dismissal. Complete focus trapping across other modal surfaces and a comprehensive mobile editor redesign remain unimplemented; test responsive surfaces when editing them.
- Diagnostic history is bounded/in-memory; Docker logs are the durable operational source subject to Docker log retention configuration.
- Cleanup errors leave the operation in CLEANUP with an actionable detail; restart retries. Transfer artifacts currently require manual expiry.
- Build reports a large JS chunk and an outdated Browserslist dataset; these do not prevent packaging. Chunk splitting remains performance work.

# Desktop shell and connections

Reviewed 2026-10-04, D6. Electron 44.5.1 runs the bundled React UI against **This computer**, its owned Java server, or a remembered paired private-network host. Local browser access now uses a one-use owner handoff; LAN browser access uses paired HTTPS. Native file/tray/login integration is implemented; D5 host services implemented; D6 client pairing/discovery/trust and integrated window chrome implemented; installers/updates D8. Android remains deferred. Windows development-package startup/relaunch is verified; Mac packaging/verification awaits the Mac mini.

## Development launch

From the repository root:

```powershell
npm --prefix frontend ci
npm --prefix desktop ci
npm --prefix desktop run build
npm --prefix desktop run prepare-server
npm --prefix desktop start
```

Build compiles the frontend and copies it to ignored desktop/ui. prepare-server downloads the pinned, SHA-256-verified free Temurin 25 JRE, retains its legal notices and builds the Spring JAR with the desktop Maven profile, embedding frontend/dist for browser access. Build tooling still needs Node/Java 25; the resulting app does not need installed Java or Docker. Run build before prepare-server after UI changes. Start serves bundled UI, never remote UI. Fresh profiles select This computer automatically; existing selected profiles remain selected. Existing Docker/standalone storage is never adopted. D1-compatible capabilities and workspace identity are required.

`npm --prefix desktop run package:dev` copies Electron/UI/JRE/JAR into a timestamped ignored desktop/packages directory. On Windows launch electron.exe in that folder; on Apple Silicon run the build commands on the Mac, then open Electron.app. macOS packaging preserves framework symlinks and applies free local ad-hoc signing, not publisher signing/notarization. This is an unsigned personal development distribution, not an installer/update release. Do not publish it as a verified Mac build. runtime-lock.json pins Windows x64 and Mac arm64 downloads; update pins deliberately, never at app startup. Temurin source/release references and legal notices travel in bundle/THIRD-PARTY.md and runtime/legal. [Temurin licensing](https://adoptium.net/docs/faq) and [checksum verification](https://adoptium.net/installation/archives/) describe the upstream distribution.

The sidebar connection button opens Connections & hosting on demand. The window ellipsis menu and tray provide the same entry when the sidebar is hidden. No native title row, Windows menu row or connection strip occupies the workspace. Frameless, theme-colored Minimize/Maximize/Restore/Close buttons share the existing top edge; Close still hides to tray. The journey/Library heading reserves their width. Empty journey/Library heading space and the small grip beside the controls drag the window. The standard Edit/View/Window actions remain in the ellipsis menu (macOS also retains its application menu). Browser access has no desktop chrome. Mac native behavior still needs verification.

Connections has This computer, up to 20 remembered servers, name search, Nearby and a semantic manual-address form. Nearby selection fills the form; it never authorizes a host. Pairing shows the host identity under Details, then a six-digit code to compare with Hosting → Devices on the host before approval. Errors retain the entered name/address and approval checks retry the same request. Completed approval is remembered without routine expiry. Forget is available only for inactive non-managed profiles and removes the client credential, never workspace data or recovery records. Re-pairing the same host/CA restores its retained profile ID and therefore its session/recovery namespace. Up to 100 forgotten identities are retained; the limit fails visibly rather than discarding recovery identity.

Private connections require HTTPS with a private IPv4 address (or a .local/localhost name resolving only to private IPv4); no credentials, path, query or fragment belong in the server address. Prefer the host's IP: generated SANs cover IPs and localhost, not arbitrary .local names. There is no public Internet connection feature. The secondary Existing local server form preserves loopback HTTP profiles; it cannot acquire owner credentials for a protected independent server. For an upgraded standalone/Docker host, use its explicitly enabled HTTPS listener and approve through its owner access page. Existing data onboarding remains D8.

Capability/identity checks precede switching. Changed workspace identity requires deliberate confirmation. Last active profile reconnects on relaunch; unavailable/incompatible servers retain a retryable screen and current input. Failed destination checks keep the current workspace. Request failures mark the sidebar dot amber while editors/drafts stay mounted; click the connection button to Retry. Hosting controls are separate from the displayed remote workspace: manage this computer's sharing, requests, devices, browser handoff, certificate export/address refresh, startup preference and logs. See HOST-ACCESS.md for trust setup and firewall help.

## Profiles, sessions and switching

Main owns versioned connections.json in Electron user data: Windows %APPDATA%/Vaultor; macOS ~/Library/Application Support/Vaultor; Linux Electron's application-data directory. It stores installation client UUID, profile UUIDs/name/address, selected profile and last verified workspace ID. Serialized writes replace an intermediate file; malformed storage is reported and preserved. Remote profiles store host UUID and public CA/fingerprint. Secrets are encrypted separately by Electron safeStorage in device-credentials.json (Windows DPAPI/macOS Keychain); unavailable protection fails pairing/connection visibly. No plaintext fallback is accepted. Public bootstrap/probe state excludes CA PEM and every credential. Malformed stores are preserved. Profile records are capped at 1 MiB; credential storage at 128 KiB. Credentials use flushed temporary-file replacement; a failed pairing write can retry its existing completion while that request remains valid. Profiles never enter backend settings/archives.

Stable UI origin is vaultor://app/. Desktop IndexedDB uses vaultor-desktop-sessions-<profile UUID>, preserving workspace identity/generation within each database. A stable desktop-<installation client UUID> session owner survives renderer/process restart. Browser database/tab ownership remains unchanged; there is no automatic browser-session migration. Profile isolation separates copied workspace IDs. Profile UUIDs isolate sessions even when two hosts carry copied workspace identities; verified host UUID plus CA pin establishes remote identity.

Switching saves settings, titles and notes, then verifies recovery writes and a strict layout write before activation. Failed note saves offer Keep drafts and switch; failed settings/storage prevent switching. Retained drafts keep original revisions and existing conflict handling. Upload/import dialogs, tracked mutations and export preparation/download block switching. Old requests abort, stale responses are ignored, save timers clear on unmount, transient views close and Redux filters reset. The destination restores its own context. Completed/error export status is not replayed after a switch; active preparation must finish first.

## Native files and lifecycle

File picking uses the OS dialog for sidebar imports, slash uploads and workspace archives. Main returns opaque selection tickets, names, sizes and modification times, never arbitrary local paths. Native-selected original binaries stream in multipart requests without loading the file into renderer memory. Text conversion reads bounded 1 MiB chunks, up to 32 MiB, while existing import-review conversion limits still apply. Selections are revalidated against size/mtime before reading/uploading; choose again if the file changed. Up to 50 files per pick, 200 retained tickets; tickets are scoped to the active connection and expire from the retained pool after an hour on the next pick.

Note/workspace/file exports stream from the selected API to a sibling temporary file chosen by a native save dialog. Table/diagnostic generated blobs use bounded IPC chunks. Cancel returns Cancelled, preserves the prepared operation and does not render another export. Saved means the stream completed, the file was flushed/closed and its temporary file renamed successfully; failures leave the original destination intact and allow retry. Browser access still reports Download requested. The note picker closes after successful handoff/write, with Download again retained. File previews expose actionable Open/Download pending and retry feedback.

Desktop streaming has a fixed 512 MiB file/upload aggregate limit (backend limits also apply); generated text/JSON/ordinary IPC responses remain capped at 32 MiB. PDF/image previews stream to the private file-cache and use a connection-bound vaultor-file protocol with range requests, not renderer-sized blobs. Preview cache is bounded at 512 MiB aggregate and 20 live previews; up to four preview requests run concurrently, abandoned requests abort and stale results release. OS Open allows a conservative list of document/media/text extensions, never programs, HTML/SVG or scripts. Opened files are retained temporarily for the OS application; cache entries older 24 hours are cleaned on startup. There is no arbitrary renderer path/open API. Save dialogs and save operations are serialized; close a dialog before switching/quitting. Native transfer errors carry request IDs when available.

Closing hides the same window to the tray/menu bar, preserving editors and host. First close explains this. Show Vaultor restores/focuses it; Open in browser uses the owned loopback address. The connection picker includes local Start/Stop host and **Start Vaultor at login in the background**, off by default. Registration is explicit and checked against OS settings; failures stay visible, and persistence failure restores the previous registration. Login launches the remembered connection with a hidden window; first launch selects This computer. Sharing defaults off until explicitly enabled in Hosting. If tray creation fails, the window stays visible rather than becoming inaccessible.

Explicit Quit first verifies the same save/settings/recovery/session barrier used for connection changes, bounded to 30 seconds. Failed note saves permit Keep drafts and quit only after recovery and layout writes succeed; storage/settings failure keeps Vaultor open. Active file dialogs/transfers/mutations block quit. GET /api/operations/activity checks persisted QUEUED/RUNNING/CLEANUP work. The owned server also quiesces mutations and waits up to 15 seconds for requests and operation journals to drain; main waits up to 20 seconds. If it cannot stop safely, Keep hosting is the default; explicit Force quit warns about interrupted operations and only stops the owned child. Browser clients are warned that Quit disconnects them. Independent servers are never stopped.

Reload retains existing exit warnings; it does not automatically replay exports. Resume probes readiness/compatibility without replaying mutations or replacing drafts. Sleep makes hosting unavailable. EOF/parent death allows bounded draining then exits the owned JVM even if its operation cannot finish, leaving persisted recovery journals for next startup. Durable storage and unload callbacks cannot guarantee every abrupt interruption survives.

## Owned local server and data

The managed workspace is userData/local-workspace (Windows normally %APPDATA%/Vaultor/local-workspace): app.db, files/, operations/, host.json and bounded logs/. It is outside the app/package directory; app replacement does not remove it. host.json is a stable local host UUID, separate from database workspace identity/generation and excluded from portable archives. Corrupt host/profile identity is reported and preserved, not regenerated. Use an explicit workspace archive transfer to migrate existing data. No live database copying or automatic Docker-volume migration occurs.

OwnedServer verifies all bundled file checksums/platform/architecture, checks write access and at least 128 MiB free, then spawns the bundled absolute Java executable with a separate working directory. Injected JAVA_TOOL_OPTIONS/JDK_JAVA_OPTIONS/_JAVA_OPTIONS/CLASSPATH are removed. The server binds only 127.0.0.1 with port 0: the OS assigns an unused port, avoiding port-8080 conflicts without probing/adopting another server. Hosting Details shows the changing loopback browser address. Open in browser mints a one-use owner handoff. An opt-in separate HTTPS listener serves paired private-network clients; HTTP stays loopback.

Before Spring opens SQLite, DesktopOwner takes an OS file lock on workspace.lock. A second app/JVM using this directory fails startup instead of sharing writes. It verifies its direct parent, remembers its process start time, and watches parent liveness from startup onward. An ephemeral owner proof travels through the child's inherited environment and private stdout/stdin channel, never command arguments, renderer state, archives or captured logs. Readiness proof comes only from the child; main then checks capabilities/identity before activating transport. STOP on that pipe quiesces mutations and closes Spring after active transfers drain; a blocked stop keeps hosting available. EOF/parent death shuts down the child; startup timeout stops only the directly owned process. This is lifecycle ownership, not user authentication.

Unexpected exits permit at most three automatic restarts per hosting run with 1/3/7-second backoff. Reconnect is an explicit fresh retry; no mutation is replayed. Restarted ports are applied to main transport only after compatibility/workspace verification; a changed workspace requires review and retains separate drafts. Switching to another server leaves the local host running until explicit Stop/Quit; persisted shared hosting resumes on launch even when the selected workspace is remote. Read-only Hosting polling never restarts a stopped host. Starting a local candidate may keep it running until switching away/quit if destination review fails.

Startup failures retain data and expose Retry, other remembered connections and local Details/logs. Missing/damaged runtime, locked directory, disk space/write failure and crash errors are actionable. Diagnostics reports main-owned local status/logs even when server API requests fail. Disk logs rotate at 1 MiB across three files; in-memory logs/backlog are bounded at 200 entries of 2,000 characters, IPC reports at most 80. Owner proofs are intercepted/redacted. Normal structured backend logs retain request IDs; no full request bodies are added. The free-space preflight does not guarantee later saves or transfers cannot fill the disk.

## Main/preload contract

desktop/src/main.mjs owns one frameless window, single-instance locking, narrow native window actions and an on-demand standard menu. The renderer is sandboxed/context-isolated with no Node integration. The secure custom protocol serves only bundled files within desktop/ui under a CSP. Remote renderer networking, webviews and extra windows are denied; only the built-in Chromium PDF extension and its chrome://resources dependencies are additionally allowed for PDF display. Its iframe cannot invoke the trusted main-frame preload handlers. Non-PDF cached content retains a sandboxed deny-by-default policy; PDF display uses Chromium’s viewer policy with PDF JavaScript blocked. HTTP(S) external links go through the OS browser, while file/custom/javascript targets are rejected. Permissions default to denied. Sources: [Electron security](https://www.electronjs.org/docs/latest/tutorial/security), [protocol API](https://www.electronjs.org/docs/latest/api/protocol).

preload.cjs exposes bootstrap, profile creation, probe/activate, request/cancel, clipboard, opaque native file operations, hosting/login state/actions and quit/resume notifications. Every handler validates the originating main frame/window; no IPC object, filesystem, shell or arbitrary URL API is exposed. Probes read capabilities/identity from the managed owner or a pinned, approved remote profile. Expiring tickets bind reviewed workspace identity/generation; activation rechecks them, refuses pending mutations and rotates an ephemeral request token. That token coordinates connection ownership, not server authentication.

Transport validates relative paths, methods, permitted headers, timeout, token and body size/shape. Redirects fail; ambiguous mutations are never automatically retried. Main/caller cancellation combine. The frontend adapter serializes text/FormData, reconstructs response bytes/status/headers and preserves Axios JSON/blob/problem errors and correlation IDs. Clipboard is limited to 1 MiB. Owner keys, device credentials and certificate trust remain main-owned; renderer-supplied authentication headers are rejected. DesktopTransport and NativeFiles share connectionFetch, so uploads, exports and previews use the same HTTPS pin/credential as JSON requests.
